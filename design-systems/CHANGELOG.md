# 디자인 시스템 변경 이력

날짜는 작업일 기준. 화면 작업 중 컴포넌트가 필요해지면 화면에 로컬 스타일을 두지 않고
이 시스템을 고친 뒤 화면에서 가져다 쓴다 (CLAUDE.md 디자인 시스템 사용 원칙).

---

## 2026-08-18 — `Pagination` 신설 · 무한 스크롤을 걷어낸다

점포 335곳을 스크롤로만 내려가면 **끝이 없다.** 어디쯤 왔는지도 얼마나 남았는지도 알 수
없고, 처음으로 돌아가려면 내려온 만큼을 손가락으로 되감아야 했다. U-ST-04 가 요구한 것은
"한 번에 다 그리지 않는다"이고 무한 스크롤도 그것을 지켰지만, 지키는 방법이 문제였다.

```
‹   1  …  9  …  17   ›
```

### 숫자를 셋만 보여주는 이유는 손가락 자리다

첫 쪽 · 지금 쪽 · 마지막 쪽. 사이는 …로 접고 이웃 쪽은 화살표가 맡는다. 흔한 다섯 개 꼴
(`[1][…][8][9][10][…][17]`)을 쓰지 않은 것은 **44px(`--tap-min`)를 지키기 위해서다** —
360px 화면에서 쓸 수 있는 폭이 320px 이라 44px 짜리 일곱 개가 들어가지 않는다.
폭을 34px 로 줄여 다섯을 넣느니 셋을 제대로 만든다.

```
화살표 2×44 + 숫자 3×44 + …2×24 + 여백 = 280px   ≤ 320px
쪽이 다섯 이하면 접지 않고 전부           = 274px   ≤ 320px
```

지금 쪽은 색으로만 알리지 않는다 — `aria-current="page"` 로 읽히고 굵기도 달라진다.
쪽이 하나뿐이면 아무것도 그리지 않는다: 넘길 곳이 없는데 회색 화살표만 서 있으면
"여기서 뭔가 더 볼 수 있나" 하고 한 번 눌러보게 된다.

### 스크롤 되돌리기는 이 컴포넌트가 하지 않는다

쪽 단추는 목록 **끝**에 있다. [다음]을 누르면 새 쪽의 첫 줄이 아니라 끝줄 근처가 열린다.
되돌리는 일은 스크롤 컨테이너를 가진 쪽이 맡는다 — `Sheet` 는 이미 `scrollKey` 가 있었고,
`DetailPage` 에 같은 것을 새로 달았다. 여기서 하려면 어느 조상이 스크롤되는지 DOM 을
뒤져야 하고 화면마다 그 답이 다르다.

`DetailPage` 도 이제 목록을 담는다(S13 상점가 전체보기). 칩을 바꿔도 같은 일이 필요하다.

## 2026-08-18 — 시트 머리 부분에서 37px 를 덜어낸다

절반 스냅에서 **머리 부분이 목록보다 컸다.** 시트 높이 237px(지도 영역의 37%) 중 184px 를
손잡이·제목·소재지·제어 줄이 쓰고, 목록에 남는 것이 53px — 점포 한 줄(약 76px)도 못 채웠다.
시트를 열었는데 가게가 하나 걸쳐 보이는 상태다.

### `Sheet` 에 `titleAside` — 제목 줄 오른쪽

| | |
| --- | --- |
| `titleAside` | 제목과 **한 줄을 나눠 쓴다.** 짧고 부수적인 것. 세로가 공짜다 |
| `headerExtra` | 제목 줄 아래 전체 폭. 가로가 필요한 것 (시설 유형별 개수 줄) |

상점가 소재지가 여기로 옮겨왔다 (`DistrictSummary`). 상점가명은 짧고 제목 줄 오른쪽은
비어 있었다 — 그 빈 자리에 넣으면 한 줄이 통째로 없어진다. 폭은 52% 로 묶는다: 넘게 두면
긴 소재지가 제목을 밀어 상점가명이 줄바꿈된다. 여기서 접혀야 할 것은 제목이 아니다.

**소재지는 반드시 한 줄이다** (`whiteSpace: nowrap`). 두 줄로 감기면 제목 줄이 그만큼
두꺼워져 **아래로 한 줄 내려놓은 것과 높이가 같아진다** — 이 자리를 만든 이유가 사라진다.
그래서 `titleAside` 는 `flex: 0 0 auto` 로 줄지 않게 두고, 폭이 모자라면 제목이 접힌다.

한 줄에 넣으려고 두 가지를 뺐다. 360px 화면의 셈이 그대로 근거다:

```
제목 152px + 소재지 153px + 여백 8px = 313px   (쓸 수 있는 폭 320px)
  + 핀 아이콘 13 + 그 여백 4          = 330px   → 넘침
  + "처인구"                          = 375px   → 넘침
```

핀 아이콘이 하던 일("이건 위치다")은 자리와 생김새가 대신하고(제목 오른쪽의 옅은 회색 한 줄),
보조기기에는 `aria-label` 로 적는다. "처인구"는 데이터 쪽에서 뺐다 — 이 탭은 지금 서 있는
상점가 하나만 다루고 컨텍스트 바가 QR 지점을 이미 적는다. 구가 필요한 자리(S13 목록)에서는
`DISTRICTS` 의 `gu` 를 따로 쓰므로 잃는 것이 없다.

정렬은 `baseline` 이다. 위 정렬로 두면 19px 제목의 윗선에 12px 글자가 붙어 공중에 뜬다.
전체 스냅에서만 나오는 닫기 단추는 `alignSelf: flex-start` 로 되돌린다 — 44px 짜리 상자를
글자 밑선에 맞추면 제목보다 한참 아래로 내려간다.

### 여백: 손가락 자리에 보태지 않는 것만 걷어냈다

```
Sheet 헤더 아래     space-2 → space-1
ListControls 안팎   space-1 → 0        (위아래 모두)
OnnuriToggle 안팎   space-1 → 0
```

**제어 줄의 두 행은 각각 44px(`--tap-min`)을 이미 갖고 있다.** 그 바깥 여백은 누를 자리를
넓히지 않으면서 세로만 먹는다. 44px 자체는 건드리지 않았다 — U-CM-13 이 정한 손가락 자리다.

머리 부분 184px → 147px, 목록 53px → 90px (0.7줄 → 1.2줄). 남은 제약은 절반 스냅 비율
(37%) 자체이고, 그건 5-3 #1 확정값이라 여기서 건드리지 않았다.

## 2026-08-18 — 알약 정리: `FestivalBanner` 상태 배지 sm · `DistrictRow` 축제 배지 기본 자리 축소

**`FestivalBanner` 의 상태 배지(진행중·예정)가 md 로 남아 있었다.** 목록의 `tag` 자리를
전부 sm 으로 내릴 때 이것만 빠졌는데, 같은 시트 안에서 바로 아래 목록의 온누리 배지와
높이가 갈렸다. 12px 글자에 알약만 부푼 모양이라 글자에 비해 커 보이는 것도 같은 이유다.
축제명 옆에 붙는 알약이니 성격도 `tag` 자리와 같다 — `size="sm"`.

**`DistrictRow` 의 `festivalTag` 를 켜두는 곳이 S03-E 하나로 줄었다.** 둘러보기 탭에 이어
S13 전체보기에서도 껐다. 두 화면 다 축제를 맡는 자리가 따로 있고([전체보기] → S12), 여기
배지는 서른몇 줄 중 여섯에만 붙어 **그 여섯 줄이 다른 종류처럼** 보이게 할 뿐이다.
눌리는 것도 아닌데 알약 모양이라 같은 화면의 칩(필터)과 같은 것으로 읽히기까지 했다.
S03-E("가볼 만한 상점가")만 남긴 이유: 거기는 축제 정보가 따로 없어 그 배지가 "왜 저기로
가나"에 대한 유일한 답이다. 기본값은 `true` 로 둔다 — 새로 붙는 화면은 대개 그런 자리다.

## 2026-08-18 — 목록 행의 꺾쇠 제거 · 토스트 축소 · 선택 배경 한 단계 더 옅게

### `FacilityRow` · `StoreRow` 에서 꺾쇠(`>`)를 뗀다

꺾쇠는 "이 줄을 누르면 다른 화면으로 간다"는 뜻이다. 그런데 이 두 줄은 이제 누르면
**보고 있던 지도**에서 핀이 켜지고 카드가 뜬다 — 화면이 바뀌지 않는다. 다른 곳으로 갈
것처럼 말해놓고 제자리에 두면 그 다음에 무엇을 눌러야 할지 알 수 없다.
상세로 가는 길은 그 카드의 [상세 보기]가 맡고, 꺾쇠도 거기 붙어 있다.

**`DistrictRow` 와 `NearbyFacilities` 는 그대로 단다.** 앞은 용인시 누리집으로 정말
나가고, 뒤는 상세 오버레이를 걷고 탭까지 옮긴다 — 둘 다 화면이 바뀐다.

### `Toast` — 글자 16px → 14px, 여백 8px → 6px

높이가 38px → 31px 이 됐다. 전에 "세로를 줄이자고 글자를 건드리면 가장 급하게 읽어야 할
문장이 가장 작아진다"고 적으며 16px 를 지켰는데, **실제로 일어난 일은 그 반대였다** —
16px 로는 두 줄짜리 토스트가 흔했고, 두 줄이 되는 순간 아래 탭바까지 덮었다. 2.2초 뒤
사라지는 알림이 화면 아래 3분의 1을 가리면 읽히기 전에 방해가 먼저 된다.

14px(`--fs-label`)은 배지(12px)보다 크고 본문(16px)보다 한 단계 작은 값이라 흘려보내는
알림이 앉기에 맞다. 줄바꿈은 막지 않았다 — 긴 오류 문장과 2차 글자 확대에서는 두 줄이
되며 늘어나야 한다 (U-CM-14). 대신 **문구를 짧게 쓰는 것이 화면 쪽 책임**이 됐다.

### `--surface-selected` — green-100 → green-50

green-100(#ddf5e8)은 흰 바탕과 1.15:1 로 갈렸는데, 그것이 한 줄만 다른 종류의 항목처럼
보이게 했다. 훑어 내려가는 눈이 매번 거기서 걸리는데, 정작 그 줄은 사용자가 방금 자기
손으로 누른 줄이라 찾아줄 필요가 없다. green-50(#f1fbf5)은 1.06:1 로 **거의 안 보인다.**

이 색이 답하는 질문은 "어디 있지"가 아니라 "방금 누른 게 이거였나"이고, 그건 눈이 이미 그
줄에 가 있을 때만 물어보는 질문이다. 찾아내는 일은 지도의 핀(green-500 + 물결)이 한다.
한때 green-50 을 물린 이유("`--brand-primary-soft` 와 같은 값이라 액션의 색과 섞인다")는
실제 화면에서 성립하지 않았다 — 그 토큰을 쓰는 것은 둘러보기 탭의 매장 카드뿐이고 목록
줄과 같은 화면에 서지 않는다. `--text-muted` 대비는 4.97:1 → 5.39:1 로 오히려 올라갔다.

## 2026-08-18 — `Notice` 에 `neutral` 톤과 `sm` 크기

`info` 의 바탕(`--state-info-soft` = teal-100)이 **온누리 배지와 같은 색이다.** 둘이 한
화면에 있는 S13 에서 안내 띠가 온누리와 관련된 것처럼 읽혔다 — teal 은 이 앱에서 온누리가
가져간 색이다.

그런데 문제는 색만이 아니었다. "새 창으로 열립니다"는 알림도 경고도 아니고 **사실 한 줄**이라,
애초에 의미색을 쓸 자리가 아니었다. 회색으로 조용히 깐다.

```
neutral   바탕 --surface-sunken(ink-50) · 글자 --text-muted(ink-500) = 5.05:1, AA 통과
sm        여백 space-2/3 · 아이콘 15 · 글자 --fs-micro
```

`sm` 은 글자만 줄이지 않고 여백과 아이콘까지 함께 줄인다 — 12px 글자에 space-4 여백이
붙으면 글자보다 여백이 크다. 높이는 박지 않았다: 글자를 확대하면 두 줄이 되며 늘어난다
(U-CM-14). `TONES` 표에 본문 색 칸을 하나 더 뒀다. 지금까지는 본문이 늘 `--text-body`
였는데, neutral 에서만 제목과 본문이 같은 회색이어야 조용해진다.

## 2026-08-18 — `ListControls`, 결과 수·정렬이 없으면 그 줄을 안 그린다

S12 축제 전체보기에서 결과 수와 정렬을 걷어내자 44px(`--tap-min`)짜리 빈 띠가 칩 위에
남았다. 안에 든 `<h3>` 이 비어 있어도 줄 자체는 서 있었기 때문이다.

```jsx
{title || sortOptions.length ? ( …결과 수 + SortSelect 줄… ) : null}
```

칩만 쓰는 화면도 이 컴포넌트를 쓸 수 있게 하려는 것이지, **결과 수를 없애도 된다는 뜻은
아니다** — 목록이 길고 필터가 여럿이면 "결과가 왜 12곳뿐인가"에 답하는 것이 그 수다.
S03(335곳)과 S13(32곳)은 그대로 둔다.

## 2026-08-18 — `DistrictRow` 의 거리 0 을 "지금 계신 곳"으로

S13 상점가 전체보기가 32곳을 **전부** 깔면서 현재 상점가(둔전, 거리 0)가 처음으로 이 행에
들어왔다. 그대로 두면 "처인구 포곡읍 · 0m"라고 적힌다 — 0m 는 거리가 아니라 계산 결과다.

```jsx
const km = d.dist === 0 ? "지금 계신 곳" : d.dist >= 1000 ? … : `${d.dist}m`;
```

문구는 `FestivalRow` 의 같은 자리에서 가져왔다. 두 목록이 같은 사실을 다르게 말할 이유가
없고, 새 낱말을 지어내면 어느 쪽이 맞는지 화면만 보고는 알 수 없다.

## 2026-08-18 — `Badge` 에 `size` 추가, 목록의 배지 높이를 하나로

S02 시트의 `쉼터` · `AED` 배지가 S03 의 `온누리` 배지보다 커 보였다. 실제로 컸다 —
온누리는 `OnnuriBadge` 안에서 `padding: 2px 7px` 로 여백을 **덮어쓰고** 있었고,
나머지 배지는 Badge 기본값 `4px 9px` 을 그대로 썼다. 글자는 둘 다 `--fs-micro` 라
글자에 비해 알약만 부푼 모양이 된다.

작은 배지가 한 컴포넌트 안에 숨어 있던 것이 원인이므로, 여백을 `Badge` 로 끌어올렸다.

```jsx
const SIZES = { md: "4px 9px", sm: "2px 7px" };
<Badge size="sm" tone="info">쉼터</Badge>
```

**`sm` 은 `ListRow` 의 `tag` 자리를 위한 값이다.** 그 자리는 행마다 같은 x 좌표에 알약이
줄지어 서는 곳이라, 높이가 갈리면 목록을 훑을 때 세로줄이 흔들린다. 공공시설 목록과
점포 목록이 같은 시트 안에서 탭으로 갈리는 S02/S03 에서 특히 그렇다.
`md` 는 상세 화면 머리말처럼 배지가 홀로 서는 자리에 남긴다.

`tag` 자리를 쓰던 곳을 전부 `sm` 으로 옮겼다 — `FacilityRow`(유형), `StoreRow`(온누리,
이미 sm), `DistrictRow`(축제), `FestivalRow`(상태). `OnnuriBadge` 의 padding 덮어쓰기는
지웠다. 같은 "작은 배지"가 두 곳에 따로 적혀 있으면 한쪽만 고쳐진다.

글자 크기는 건드리지 않았다. 배지는 이미 `--fs-micro` 로 이 시스템에서 가장 작은 글자이고,
여기서 더 줄이면 WCAG AA 대비를 만족해도 읽히지 않는다 (U-CM-13).

## 2026-08-18 — `FestivalCard` 톤을 파스텔로, 크기를 한 단계 줄임

원색 여섯 장(짙은 청록·검정·팥·파랑·주황·노랑 + 흰 글자)으로 시작했는데,
**카드끼리는 갈렸지만 앱과 갈렸다.** 나머지 화면은 흰 바탕에 초록 한 점이 전부라,
그 사이에 원색 카드가 끼면 광고 배너를 붙여놓은 것처럼 보였다.

**여섯 색을 전부 램프의 가장 옅은 칸으로 내리고 글자를 잉크색 하나로 통일했다.**

| tone | 바탕 | 짙은 짝(`-deep`) |
| --- | --- | --- |
| `sky` | teal-100 | teal-700 |
| `lilac` | blue-100 | blue-500 |
| `sand` | cream-300 | cream-900 |
| `peach` | amber-100 | amber-500 |
| `rose` | red-100 | red-700 |
| `stone` | ink-100 | ink-500 |

카드끼리 갈리는 일은 여전히 여섯 색이 하고, 앱 전체와의 결은 "밝은 바탕 + 어두운 글자"라는

바탕이 전부 밝으니 글자색이 갈릴 이유가 없다.

**짙은 색을 쓰는 자리는 아이콘 스티커 한 점뿐이다.** 파스텔만으로는 카드에 초점이 없는데,
색을 진하게 쓰는 자리를 카드당 하나로 묶으면 여섯 장이 나란히 놓여도 소란스럽지 않다.

**크기도 한 단계씩 줄였다** — 제목 19→17, 홍보 문구 16→14, 날짜·상점가 13→12,
조아용 92→72, 스티커 36→28, 최소 높이 148→112. 한 화면에 카드가 한 장 반밖에 안 들어가면
목록을 훑는다는 느낌이 사라진다.

## 2026-08-18 — 고른 핀을 크기·색·물결 셋으로 알린다 (`KakaoMap`)

목록 행을 눌러도 마커를 누른 것과 같아진 뒤에 나온 지적이다 — "핀이 여러 개 몰려 있으면

맞다. 전에는 **색만** 바꿨다(`--pin-selected`, 초록 → 짙은 초록). 점포 335곳이 골목 하나에
몰려 있어 화면에 핀 열 개가 겹치는데, 그중 하나가 한 단계 어두워진 것은 옆에 두고
비교해야 보인다. 게다가 목록에서 고른 사람은 애초에 어느 핀인지 모르니 비교할 대상이 없다.

셋을 함께 준다:

| | 토큰 | 왜 |
| --- | --- | --- |
| 색 | `--pin-selected` = **green-500 (밝은 민트)** | 아래 참조 |
| 물결 | `--pin-selected-halo`(green-600) + `yong-pin-pulse` | 핀 아래에서 번진다. 몰린 곳에서 눈이 먼저 가는 것은 움직임이다 |
| 크기 | `--pin-selected-scale` (1.12배) | 처음엔 1.34배였는데 같은 무리의 핀이 아니라 다른 종류의 표시로 보였다. 고른 것은 **여전히 그 목록의 하나**여야 한다 |

색은 짙은 초록(green-800) → 노랑(cream-700) → 민트(green-500) 순으로 두 번 갈아엎었다.
오답 둘이 각각 알려준 것이 있다:

| 시도 | 왜 틀렸나 |
| --- | --- |
| 짙은 초록 | 같은 초록 안에서 **명도만** 옮기면 "고른 것"이 아니라 "조금 다른 점포"로 읽힌다 |
| 노랑 | 지도에서는 확실히 갈렸지만 **길찾기와 끊겼다**. 도착지 핀도 경로선도 [길찾기]도 초록이라 "고른 곳 → 저기로 간다"의 한 줄기 밖으로 나갔다 |

민트는 둘을 다 푼다 — 계열은 초록이라 길찾기와 이어지고, **채도가 확 높아** 같은 화면의
어느 핀과도 겹치지 않는다. 점포(ink-500 회색)·온누리(teal-500 청록)·상점가(green-700
진초록)·시설(적색/청록)이 모두 어둡거나 탁한 쪽이라, 밝고 맑은 하나만 튀어 오른다.
조아용 몸통에서 뽑은 `--character-green` 이라 새 색을 들이지도 않는다.

물결만 한 단계 짙은 green-600 이다 — 핀과 같은 green-500 으로 두면 옅게 깔릴 때
(움직임 최소화 상태의 opacity .18) 흰 지도 바탕에서 사라진다.

⚠️ **테두리는 건드리지 않는다.** 바탕색이 밝아 윤곽이 약하다는 이유로 회색과 잉크를 차례로
넣어봤는데, 테두리 색이 다른 순간 같은 무리의 핀이 아니라 다른 종류의 표시로 읽혔다.
고른 것을 알리는 일은 위 셋이 맡고, 흰 테두리는 "이것도 핀이다"를 맡는다.

**목록 행은 같은 초록의 옅은 쪽이다** — 신규 `--surface-selected`(green-100 #ddf5e8).
핀이 green-500 이고 줄이 green-100 이라, 계열이 같은 짙고 옅은 짝으로 한 동작의 앞뒤가 된다.
지도는 핀 무리 속에서 갈려야 해 채도를 높이고, 목록은 자기가 누른 줄을 확인만 하면 된다.

옅게 두는 것은 목록의 강조가 지도의 강조와 하는 일이 달라서다. 지도에서는 핀 열 개 중
하나를 **찾아내야** 해서 물결까지 동원하지만, 목록에서는 이미 자기가 누른 줄이라 어디인지
안다 — 필요한 것은 "방금 누른 게 이거다"라는 확인이지 시선을 끄는 일이 아니다. 진하게 깔면
그 줄만 다른 종류의 항목처럼 보여 훑어 내려가는 눈이 매번 걸린다. 같은 이유로 한때 넣었던
왼쪽 강조 띠도 뺐다.

green-50(=`--brand-primary-soft`)이 아닌 이유 둘: 흰 카드와 거의 갈리지 않아 눌린 티가
안 났고, 그 토큰은 버튼·배지가 쓰는 **액션의 색**이라 "고른 것"과 "누를 수 있는 것"이 같은
색으로 읽힌다. 한 단계 더 진한 green-200 은 `--text-muted` 대비가 4.35:1 로 AA 아래다
(green-100 은 4.97:1) — 옅게 가는 데는 읽기 쪽 이유도 있다.

물결은 한 번에 그치지 않고 2.4초로 느리게 계속 돈다 — 카드를 읽다가 지도로 눈을 옮기는
사이에 끝나버리면 못 본다. 움직임 최소화를 요청한 기기에서는 반복이 1회로 줄고, 요소의
**바탕 모습**(은은한 원)이 그 자리에 남아 강조가 사라지지 않는다.

⚠️ **고른 핀은 클러스터에서 꺼낸다.** 점포 마커는 클러스터러 안에 있어서, 고른 핀이 뭉침
숫자 뒤에 그대로 숨는 경우가 있었다 — 카드는 떴는데 지도에는 아무 변화가 없다.
고른 동안만 빼서 지도에 직접 얹고, 놓으면 되돌린다. 되돌리는 일은 효과의 **정리(cleanup)**

알고, 셋이 되는 순간 원하는 값까지 두 번 눌러야 한다. 고른 것은 색과 **체크 표시**로
함께 알린다 (색만으로 알리면 색을 못 보는 사람에게는 어느 쪽인지 보이지 않는다).

허용하지 않고, 브라우저마다 안쪽 클릭이 바깥으로 새거나 삼켜진다.

⚠️ **닫힘 상태는 배너가 들지 않는다.** 배너를 그리는 시트 헤더는 탭을 옮기면 언마운트되므로,

넘어가면 다시 보여야 하므로, 기억할 값은 "한 번 닫았다"가 아니라 "이 축제를 닫았다"다.

## 2026-08-18 — 신규 `FestivalCard` (store) · 축제 카드 6색 토큰

축제 전체보기(S12)가 `FestivalRow` 여섯 줄을 깔고 있었는데, "상점가 축제를 알리는 자리인데
홍보가 전혀 안 된다"는 지적이 나왔다. 맞는 지적이고, 원인은 **행이 고르는 자리의 생김새**라서다.
이름·날짜·거리를 나란히 세우면 여섯을 빠르게 견줄 수 있지만, 어느 축제가 있는지 모르는
사람에게는 여섯이 다 같아 보여서 하나도 읽지 않고 나간다.

**`FestivalCard`** — 한 건이 화면 한 뼘을 차지한다. 왼쪽은 읽는 자리(상태 배지 · 날짜 ·
축제명 · **홍보 문구** · 상점가명 · 거리), 오른쪽은 보는 자리(조아용 + 성격 아이콘 스티커).
카드 전체가 눌린다 — 안에 [자세히 보기]를 두면 여섯 번 같은 말을 한다.

**`--fest-*` 6색** (`tokens/colors.css`) — 카드끼리 구별되라고 있는 색이다.
상태(진행중·예정·종료)는 카드 안 배지가 **글자로** 말한다. 색만으로 상태를 읽게 하면
색을 못 보는 사람에게 목록이 통째로 무너진다. 종료만 색을 거두는데(`--fest-done-*`),
그때도 배지의 "종료"가 먼저다.

⚠️ **초록 계열이 없다.** 카드 위에 조아용(초록 용)이 서는데 초록 바탕에서는 검은 외곽선이
있어도 몸통이 배경에 잠긴다. teal-900 · ink-900 · red-700 · blue-500 · amber-500 · cream-700 여섯이다.

포즈는 `MASCOT_FULL`(1:1 전신)에서만 고른다. 상반신 아트워크를 섞으면 정사각 상자에서
높이가 3분의 2로 줄어 카드마다 캐릭터 크기가 달라 보인다.

## 2026-08-18 — `FacilitySummary` 말풍선이 오른쪽으로 잘리던 문제

원거리 안내 말풍선(U-FC-09)을 **경고가 걸린 항목의 왼쪽 끝**에 붙이고 오른쪽으로
`min(280px, 78vw)` 만큼 펼치고 있었다. `SAFETY` 순서가 AED · 대피소 · 쉼터라 대피소는
줄의 가운데쯤에서 시작하는데, 거기서 280px 을 펼치면 화면 오른쪽으로 잘려 나갔다.

항목마다 시작점이 다르므로 **시작점을 항목에 맞추는 한 어느 유형에서든 잘릴 수 있다.**
쉼터(세 번째)면 더 심하고, 2차의 글자 확대에서는 AED 에서도 잘린다.

그래서 말풍선을 **줄 컨테이너에 좌우로 붙였다**(`left:0; right:0`). 폭이 컨테이너와
같아지므로 잘릴 자유도 자체가 없어진다. 대신 **꼬리만** 경고가 걸린 항목의 아이콘 아래로
옮긴다 — 어느 유형에 붙은 경고인지는 꼬리가 가리키고, 폭은 컨테이너가 책임진다.

꼬리 위치는 상수로 둘 수 없어 `getBoundingClientRect` 로 잰다. 앞 항목의 폭이 개수
자릿수와 글자 크기에 따라 달라지기 때문이다. 말풍선 모서리를 넘지 않도록 양끝을 묶고,
창 크기가 바뀌면 다시 잰다.

함께 고친 것: 말풍선의 첫 값을 `useEffect` 가 아니라 `useState` 초기화에서 정한다.
effect 로만 열면 첫 프레임이 닫힌 상태로 그려졌다가 곧바로 열려, 급히 보는 사람 눈에
한 번 깜빡이는 것으로 남는다.

선택지는 세로로만 쌓는다. 가로로 늘어놓으면 글자를 키웠을 때 줄이 깨지는데, 라디오는
줄이 깨지면 어느 글자가 어느 동그라미의 것인지 알 수 없게 된다.

### 신규 — `LoadingBar` (feedback)

S01 QR 진입 로딩이 첫 사용처다. `value` 를 주면 확정(그만큼 참), 안 주면 불확정(흐름)이다.
S01 은 단계가 셋으로 정해져 있어 확정을 쓴다 — 불확정 막대는 "언제 끝날지 모른다"는 뜻이라
끝을 아는 화면에 쓰면 실제보다 오래 걸리는 것처럼 느껴진다.

`Input` 은 이미 갖고 있는데 `Select` 만 없었다. S10 이 둘을 나란히 쓰면서, 같은 폼 안에서

[조아용]  지금 계신 곳

### `FacilitySummary` — `warnings` (U-FC-09 를 배너에서 말풍선으로)

전에는 목록 맨 위에 경고 배너 한 장이 통째로 들어갔다. 그 배너가 말하는 것은 "대피소가 멀다"
한 가지인데 자리는 목록 두 줄만큼을 먹었다.

이제 **개수 옆 아이콘에 작은 주의 배지**가 붙고 문장은 말풍선이 갖는다. 경고와 그 대상(대피소)이

**말풍선은 경고가 새로 생겼을 때 저절로 열린다.** 배지만 두고 눌러야 열리게 하면 가장 알아야 할
사람(급히 대피소를 찾는 사람)이 그것을 못 보고 지나간다. 한 번 닫으면 다시 열리지 않는다.

경고가 걸린 유형은 개수가 0 이어도 줄에 남긴다 — 경고를 걸어놓고 대상을 빼면 어디에 붙은
경고인지 알 수 없다.

### 신규 — `RouteSteps` (navigation)

구간별 도보 안내(U-NV-03)가 처음 쓴다. 한 줄에 **거리와 동작이 함께** 온다 —

걷는 사람이 알아야 하는 것은 "여기서 얼마나 더 가면 되는가"뿐이다.

(S08 코스의 순번과 같은 성격). 마지막 항목 아래로는 잇지 않는다 — 거기서 끝이라는 표시다.

회전 종류는 7종(`start` `straight` `left` `right` `slight-left` `slight-right` `arrive`)만
들인다. **제공자의 숫자 코드를 컴포넌트에 들이지 않는다** — 카카오·TMAP 이 서로 다른 체계를
쓰고 개정도 되므로, 코드→종류 변환은 데이터 어댑터(`screens/main/data/walkRoute.js`)가 맡는다.
그래야 제공자를 바꿀 때 디자인 시스템을 고치지 않는다.

문구 조립은 `routeStepText` 한 곳에서만 한다. 화면과 스크린리더가 다른 문장을 읽으면 안 된다.

### `KakaoMap` — `route` 레이어 추가

코스(`course`)와 가장 비슷해 보이지만 성질이 정반대다.

| | 코스 점선 | 경로 실선 |
| --- | --- | --- |
| 무엇 | 들르는 순서를 이은 직선 | 경로 API 가 돌려준 실제 도보 길 |
| 뜻 | "이 순서로 돌아라" | **"이 길로 가라"** |
| 색 | 초록 (점포 계열) | **파랑** (QR 지점 계열) |

파랑으로 정한 이유: 초록은 이 지도에서 이미 점포·클러스터·상점가의 색이라, 그 위에 초록 선을
그으면 "점포들을 이은 선"으로 읽힌다. 파랑은 QR 앵커(`--pin-anchor`)와 같은 계열이고,
그 점에서 출발하는 선이라는 것이 색으로 이어진다.

선을 **두 겹**으로 긋는다(흰 밑선 + 파란 본선). 카카오 기본 지도의 도로가 회색·노랑·흰색이라
한 겹만 그으면 교차로에서 도로 위에 묻힌다.

경로 실패(U-NV-04)도 이 레이어가 그린다 — `straight: true` 면 회색 점선이 된다.
방향과 거리만 맞는 직선을 실선으로 그으면 안내가 거짓말이 되기 때문이다.

출발 마커는 따로 만들지 않았다. 지도 생성 때의 QR 앵커(파란 점 + 말풍선)가 그대로 출발점이다 —
화면의 "내 위치"는 언제나 QR 지점이라는 전제(제안서 3-1)가 여기서도 유지된다.

`turns` 배열에는 출발·도착도 `dot:false` 로 **남겨 둔다.** 걸러서 넘기면 목록과 인덱스가
어긋나 세 번째 항목을 눌렀는데 네 번째 지점이 커진다.

### `tokens/icons.css` — 경로선 토큰

`--route-line` `--route-line-casing` `--route-line-w` `--route-casing-w`
`--route-line-straight` `--route-turn-bg` `--route-turn-active` `--pin-dest`.
색과 굵기를 화면 코드에 적지 않기 위한 것이다 — 경로선은 S07 하나만 쓰지만,

## 2026-08-18 — 첫 로딩 10.8MB → 1.07MB

배포 직후 보고했던 "첫 로딩 4.7MB"는 **폰트를 빼고 센 값이라 틀렸다.**
실제로는 JS 4.7MB + 폰트 6.1MB ≈ **10.8MB** 였다. 길에서 QR 을 찍는 사용자가
모바일 데이터로 받을 양이 아니다.

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 폰트 | 6,146 KB (.otf 4종) | **428 KB** (dynamic subset 16조각) |
| Babel + .jsx 원본 60여 개 | 3,379 KB · 요청 61건 | **0** (빌드 시점으로 이동) |
| 번들 | — | 464 KB · 요청 1건 |
| lucide | 624 KB (아이콘 2,021개) | **번들에 포함** (쓰는 48개만) |
| react / react-dom | 1,161 KB (development) | 143 KB (production) |
| **합계** | **약 10.8 MB** | **약 1.07 MB** |

### 폰트 — `.otf` 를 버리고 dynamic subset 으로

`.otf` 는 애초에 웹폰트 포맷이 아니다. 네 방식을 실측해 골랐다:
정적 woff2 4종 3,046KB / Variable woff2 1개 2,009KB / **dynamic subset 474KB**.

92조각을 unicode-range 로 나눠 두면 브라우저가 **실제로 쓰인 글자가 든 조각만** 받는다.
이 화면들이 쓰는 서로 다른 글자는 355자(한글 음절 327자)이고 92조각 중 **16조각**에 걸린다.
조각은 92개 전부 넣는다 — 16개만 넣으면 새 점포명이나 새 화면에서 다른 글자가 나올 때
조용히 시스템 폰트로 떨어지고, 화면은 멀쩡해 보여서 알아채기 어렵다.

가변 폰트(굵기 45~920)라 400/500/600/700 을 한 벌로 커버한다.
`--fw-light` 나 `--fw-black` 을 앞으로 써도 파일을 더 넣을 필요가 없다.
`--font-sans` 맨 앞에 `"Pretendard Variable"` 을 넣었다.

CDN 을 런타임 의존으로 두지 않았다 — 공공 서비스라 외부 CDN 이 막히면 글꼴이 통째로 사라진다.
SIL OFL 재배포 조건인 라이선스 원문을 `assets/fonts/pretendard/OFL.txt` 에 함께 뒀다.

### JSX 프리컴파일 — `tools/build.mjs`

브라우저가 Babel(3MB)로 `.jsx` 60여 개를 실시간 변환하던 것을 빌드 시점으로 옮겼다.

**로더와 해석 규칙이 한 글자도 달라선 안 된다.** 다르면 로컬에서는 되고 배포에서만 깨지는,
가장 찾기 어려운 버그가 된다. `_ds_loader.js` 의 네 가지를 그대로 옮겼다 —
변환 프리셋, `require()` 정규식, 외부 모듈 처리, 순환 참조 대비 등록 순서.
다른 점은 하나뿐이다: 경로를 빌드 시점에 풀어 모듈마다 `{적힌 경로 → 모듈 id}` 표를 함께 넣는다.
브라우저에서 경로를 다시 풀 일이 없어 해석이 갈라질 여지가 사라진다.

**개발 방식은 바뀌지 않는다.** `screens/main/index.html` 이 번들 유무를 보고 갈라진다 —
번들이 있으면(배포) 그것만 받고, 없으면(로컬) 지금처럼 원본을 읽는다.
로컬에서 원본을 고치면 리빌드 없이 새로고침만으로 반영된다. `?dev=1` 로 강제도 가능하다.

**번들은 커밋하지 않는다** (`.gitignore`). 두 세션이 화면을 고칠 때마다 낡는데,
낡은 번들이 커밋되면 그게 그대로 배포된다. Vercel 이 매번 새로 만든다.

### lucide — 쓰는 48개만

전체본이 624KB(아이콘 2,021개)로 번들(400KB)보다 컸다. 빌드가 소스의 모든 문자열 리터럴 중

버튼 참조가 필요한데, `AppBar` 시그니처에 ref 전달을 더하는 대신 `DetailPage` 가
`header button[aria-label="뒤로"]` 를 DOM 에서 찾는다. 이미 여러 화면이 쓰는 컴포넌트라
파급을 만들 값어치가 없었다.

### 신규 — core

| 컴포넌트 | 역할 |
| --- | --- |
| `InfoList` | 라벨–값 정보 행. 값이 빈 항목은 스스로 걸러낸다 ("부가정보: —" 는 정보가 아니라 잡음) |
| `CopyField` | 주소 + [복사]. `navigator.clipboard` 가 없으면 `execCommand` 로 폴백 |

`InfoList` 를 `<table>` 로 짜지 않은 이유: 라벨 폭을 고정하면 2차 글자 확대에서 값이
좁은 열에 갇혀 다섯 줄로 접힌다. 라벨을 값 위에 얹고 행이 내용만큼 늘어나게 뒀다 (U-CM-14).

`CopyField` 의 폴백이 필요한 이유: `navigator.clipboard` 는 보안 컨텍스트(https 또는
localhost)에서만 존재한다. 검수 중 사내 IP(`http://192.168.x.x:8000`)로 열면 그냥 undefined 라
아무 일도 일어나지 않고, 그것은 "복사가 안 된다"가 아니라 "버튼이 죽었다"로 읽힌다.
결과는 토스트를 직접 띄우지 않고 `onCopied(성공여부)` 로 올린다 — 토스트는 화면 최상단에
하나만 있어야 하고 그 자리는 화면이 갖는다.

### 신규 — facility

`NearbyFacilities` — 인근 편의시설 (U-ST-07). **`DistrictSheet` 에 인라인으로 있던 블록을
그대로 옮기고 원래 자리도 교체했다.** 명세가 이것을 상점가 상세와 점포 상세 **양쪽**에
요구하는데, 두 벌로 두면 한쪽만 고쳐져 두 화면이 같은 시설을 다르게 말하게 된다.

행을 `FacilityRow` 가 아니라 `ListRow` 로 짠 것은 의도다. 여기는 "가는 곳"이 아니라
"곁에 뭐가 있는지"를 알리는 자리라, 거리·유형 배지·개방시간까지 붙이면 네 줄짜리
보조 정보가 본문보다 무거워진다.

## 2026-08-14 — 시트를 올리면 검색창과 칩이 잘리던 문제

두 개의 별개 원인이 겹쳐 있었다. 두 탭 모두 해당된다.

### 원인 1 — 올라오는 시트가 필터 바를 덮는다

시트는 z 500, 상단 필터 바는 z 300 이다. 시트를 끌어올리면 그냥 덮어버리므로
검색창과 칩이 **위에서부터 잘려 나간다.**

전체 스냅에서 필터를 시트 헤더 안으로 옮겨 붙이는 `mode="inline"` 이 있었지만 답이 아니었다 —
스냅이 `full` 로 확정된 뒤에야 재배치가 일어나므로 **끌어올리는 도중에는 그대로 잘렸고**,
필터가 화면 맨 위에서 시트 헤더 안으로 순간이동해 눌러야 할 자리가 계속 바뀌었다.

**`Sheet` 에 `topInset` prop 추가.** 부모(지도 영역) 위쪽에 시트가 덮으면 안 되는 높이(px)다.
세 곳이 함께 이 값을 본다 — 전체 스냅 높이, 드래그 상한, 놓았을 때의 스냅 판정 비율.
셋 중 하나만 놓쳐도 시트가 필터를 덮거나 엉뚱한 단계로 붙는다.
화면은 필터 바의 **실측 높이**를 그대로 넘긴다 (검색창 유무로 달라지므로 상수를 쓸 수 없다).

즉 필터 바가 있는 화면에서 "전체"는 지도 영역 전부가 아니라 **필터 바 아래 전부**다.
z 순서는 5-3 표 그대로 두고, 필터의 물리적 위치도 늘 같다.

`MapFilterOverlay` 의 `mode` prop 은 제거했다 (`inline` 을 쓸 이유가 사라졌다).
`topInset` 이 0 이면 전체 스냅은 종전대로 100% 이므로 다른 화면의 동작은 그대로다.

### 원인 2 — `headerExtra` 가 닫기 버튼과 폭을 나누고 있었다

`Sheet` 의 헤더는 [제목 | 닫기 버튼] 2열이었고 `headerExtra` 가 **제목 열 안**에 있었다.
전체 스냅에서 [지도] 버튼이 나타나면 그 폭(약 60px)만큼 열이 좁아지는데, 그 안의 필터는
`calc(var(--gutter-screen) * -1)` 로 좌우를 넘쳐 흐르게 되어 있어 **검색창 오른쪽이 [지도] 버튼 밑으로 깔렸다.**

`headerExtra` 를 제목 줄 **아래 전체 폭**으로 옮겼다. 시설 요약과 상점가 요약도 같은 문제를
겪고 있었으므로(닫기 버튼 폭만큼 좁아져 줄이 접힘) 함께 해결된다.

### 검증

`Sheet` 를 직접 렌더해 확인했다 — `topInset:120` 에서 전체 스냅 높이가
`calc(var(--sheet-full) - 120px)`, 접힘·절반은 영향 없음, `topInset:0` 이면 종전과 동일.
헤더는 `flex:1` 열이 제목 줄 하나뿐이고 `headerExtra` 가 닫기 버튼 뒤에 온다.

## 2026-08-14 — 쉼터를 안전시설로 재분류

이 서비스의 쉼터는 **무더위쉼터·한파쉼터**다. 폭염과 한파는 실제 인명 피해가 나는 재난이고
지정 쉼터는 그 대응 시설이므로 편의시설이 아니라 안전시설이다. 편의시설로 남는 것은 화장실 하나.

### 분류를 둘로 나눴다 — 하나로 두면 지도의 붉은색이 뜻을 잃는다

`FacilityIcon` 이 `EMERGENCY` 하나로 **섹션 분류**와 **핀 색**을 동시에 정하고 있었다. 분리했다.

| 상수 | 대상 | 쓰는 곳 |
| --- | --- | --- |
| `SAFETY` | aed, shelter, **rest** | 목록 섹션, 시트 헤더 개수, 원거리 배너 감시 대상 |
| `EMERGENCY` | aed, shelter | 지도 핀 적색, 목록 유형 배지 적색, 아이콘 적색 강조 |
| `CONVENIENCE` | toilet | 편의시설 섹션 |

쉼터를 `EMERGENCY` 에 넣지 않은 이유: 붉은색은 "지금 당장"을 뜻해야 하는데 4종 중 3종이
붉으면 색이 아무것도 구분하지 못한다. 심정지와 재난 대피는 분 단위로 다투는 일이고
무더위쉼터는 그 층위가 아니다. 쉼터의 안전 성격은 색이 아니라 **섹션 배치**로 드러낸다.
기능명세서 5-2 의 "화장실과 쉼터는 중립 계열"도 그대로 지켜진다.

`FACILITY_TYPES` 순서도 `aed → shelter → rest → toilet` 로 바꿨다 (칩 순서가 분류를 따른다).

### 섹션 안에서는 여전히 거리순이다

U-FC-04 의 "AED와 대피소를 목록 상단에"는 **섹션 배치**로 이미 지켜진다 (안전시설 섹션이 통째로 위).
섹션 안에서까지 유형 순으로 묶으면 90m 쉼터가 2km 대피소 아래로 내려가,
거리순이라는 목록의 약속이 깨진다.

### 헤더와 섹션은 같은 것을 센다

`FacilitySummary` 도 `SAFETY` 를 센다. 둘이 다른 기준을 쓰면 "안전시설 8곳"이라 적혀 있는데
그 아래 섹션에는 11줄이 있는 상태가 된다.

기능명세서 U-FC-01 / U-FC-04 / U-FC-09 와 5-2 스타일 규칙에 이 분류와 근거를 반영했다.
더미 데이터의 쉼터 4건도 성격이 이름에서 읽히도록 고쳤다 (`둔전마을회관 경로당` →
`둔전마을회관 무더위쉼터` 등).

## 2026-08-14 — 진입 직후 마커가 안 뜨던 버그 + 아이콘 2건 확정

### `KakaoMap` — 첫 진입에 핀이 하나도 안 그려졌다

증상: 화면에 들어가면 지도에 핀이 없고, 필터 칩을 다른 것으로 눌렀다 되돌려야 나타난다.

원인은 **비동기 초기화와 이펙트 의존성의 경합**이다. 지도 생성은 SDK 를 네트워크로 받는 비동기인데
마커 이펙트는 첫 렌더에서 동기로 돈다. 그때 `kakaoRef.current` 가 아직 `null` 이라 아무 것도
그리지 않고 끝나고, 그 뒤 지도가 생겨도 `stores` / `facilities` 배열의 **참조가 그대로**라
이펙트가 다시 돌지 않는다. 칩을 누르면 배열이 새로 만들어지면서 그제야 그려진 것이다.

수정: 지도 생성 완료를 `ready` **state** 로 올리고 세 마커 이펙트(점포·시설·선택 강조)의
의존성에 넣었다. ref 로 두면 값이 바뀌어도 리렌더가 일어나지 않아 같은 문제가 남는다.

이 버그는 상점가 탭에도 있었다. 진입 탭이 공공시설로 바뀌면서 드러났을 뿐이다.

### 아이콘 2건 확정 (기능명세서 5-2 갱신)

| 대상 | 변경 | 사유 |

## 2026-08-14 — 시트 스냅 재조정 (지도 노출 확대)

`--sheet-collapsed` **25% → 18%**, `--sheet-half` **62% → 37%** (`--map-pad-*` 도 30/67 → 22/41 로 동반 조정).
`Sheet` 의 `SNAP_RATIO` 도 같이 맞췄다.

기본 상태에서 지도가 더 보여야 한다는 요청. 이 서비스는 "여기가 어디인가"를 먼저 답하고
목록은 그 다음이라는 판단이므로, 절반 스냅에서 지도가 화면의 3분의 2를 갖는다.

**단위 주의를 토큰 주석과 규칙 문서에 명시했다.** 시트 % 는 뷰포트가 아니라 **지도 영역**
(뷰포트 - 앱바 56 - 컨텍스트바 48 - 탭바 64 = 뷰포트의 80%) 기준이라, 눈으로 보는
"화면의 몇 %" 와 숫자가 다르다. 시트 **37% ≈ 화면 30%** 다. 이 구분이 없으면
"30% 로 해달라"는 요청에 시트를 30% 로 잡아 실제로는 화면의 24% 가 된다.

포기한 것: 62% 의 근거였던 **"목록 3행이 보여야 목록으로 읽힌다"**. 절반에서 보이는 것은
첫 1~2행뿐이다. 대신 그 첫 행이 잘리지 않는 선(250px)을 하한으로 잡았다 —
반쯤 잘린 행은 "더 있다"는 신호가 아니라 레이아웃 오류로 읽힌다.

기능명세서 5-3 에 **5-3-1 확정 결과** 절을 추가했다. 5-3 이 "확정해야 할 6가지"로만 남겨둔
항목의 답을 명세서 본문에서도 바로 볼 수 있게 했다 (전문은 `docs/S03_map_overlay_rules.md`).

`SectionHeader` 의 `note` prop 은 되돌렸다 — 유일한 사용처였던 "응급 상황에 먼저 찾는 곳입니다"
문구를 뺐으므로 쓰는 곳이 없다. `chevron_right` → `chevron-right` 오타 수정은 유지한다.

  최종 마커 색 체계: **파랑 = QR 지점 / 초록 = 점포 클러스터 / 청록 = 온누리 / 회색 = 일반 점포 / 빨강 = AED·대피소**
- **`map/KakaoMap`, `map/MapCanvas` — 앵커 라벨을 검은 알약에서 꼬리 달린 흰 말풍선으로.**
  검은 알약은 지도 위에서 너무 무겁게 읽혔다. 흰 바탕 + 꼬리로 어느 지점을 가리키는지 형태로 드러내고,
  글자는 semibold → medium 으로 낮췄다.
  `KakaoMap` 은 점과 말풍선을 **두 개의 CustomOverlay 로 분리**했다 — 하나로 묶으면 `yAnchor` 하나로는
  점을 좌표에 정확히 앉히면서 말풍선을 그 위에 띄울 수 없다.
  목업(`MapCanvas`)도 같은 형태로 맞췄다. 목업과 실지도가 다르게 생기면 목업으로 검증하는 의미가 없다.

### 2026-08-14 (추가) — S07 1차 리뷰 반영

화면 검토 결과 6건. 전부 화면이 아니라 시스템 쪽을 고쳤다.

- **`tokens/typography.css` — 굵기를 전반적으로 한 단계 낮췄다.**
  화면 텍스트 대부분이 600~700 에 몰려 있어 두껍고 답답하게 읽혔다.
  `--fw-semibold` 600→500, `--fw-bold` 700→600, `--fw-extrabold` 800→700, `--fw-black` 900→800.
  컴포넌트가 전부 `var(--fw-*)` 를 참조하므로 토큰 한 곳만 고치면 전 화면에 적용된다.
  semibold 와 medium 이 같은 500 이 되었다 — 두 단계를 구분하지 않기로 한 결정이고,
  이미 참조 중인 토큰 이름은 그대로 둔다.
- **`navigation/AppBar`** — 제목을 3열 그리드(`1fr auto 1fr`)로 정중앙에 놓는다.
  기존 `flex + paddingRight` 보정은 좌우 폭이 다르면 제목이 한쪽으로 밀렸다
  (뒤로가기 44px 만 있고 오른쪽이 비면 22px 왼쪽으로 치우침). 긴 제목은 자르지 않고 줄바꿈한다.
- **`navigation/ContextBar`** — 문구 구조 변경. `현재 위치 OO` → `QR 스캔 지점 : OO` 로 바꾸고
  아래 줄에 `*QR 스캔 지점을 기준으로 위치가 안내됩니다.` 를 작게 덧붙인다.
  GPS 를 쓰지 않으므로 사용자가 걸어서 이동하면 "현재 위치"는 사실과 달라진다. 기준점의 정체를 그대로 밝힌다.
- **`feedback/Sheet` — 전체 스냅 90% → 100%.**
  90% 일 때 남는 10% 는 스크림에 덮여 회색 띠로만 보였고 지도로도 목록으로도 쓸모가 없었다.
  이제 전체 스냅은 지도를 완전히 덮는 "목록 화면"이다.
  - 스크림은 `scrim` prop 을 켠 화면에서만 깔린다 (전체 스냅 자동 적용 제거)
  - 전체 스냅에서는 위쪽 모서리를 각지게 — 둥글면 그 틈으로 지도가 조각처럼 비친다
  - `closeIcon` / `closeLabel` prop 추가. 지도를 100% 덮으므로 돌아갈 길이 헤더에 보여야 한다
    (S07 은 `map` 아이콘 + "지도"). 핸들 드래그만 남기면 못 돌아가는 사용자가 생긴다
- **`tokens/layers.css`** — `--sheet-full` 100%, `--map-visible-full` 0% 로 갱신하고 근거를 주석에 남겼다

화면 쪽 변경 (`screens/S07/`)
- 지도 우측 플로팅 버튼을 **[목록] 하나로** 줄였다. QR 지점 복귀는 컨텍스트 바의 [기준점 보기]가 맡는다.
  지도 위에 버튼이 둘이면 주된 행동이 흐려지고, 기준점이 적힌 줄 옆에 복귀 버튼이 있는 편이 자연스럽다
- **오류 신고를 S07 에서 제거**했다 (앱바 우측 상단 + 시트 하단 링크 둘 다).
  기능명세서 U-CM-10 을 "진입점은 상세 화면에만 둔다"로 개정하고, S04·S08 의 관련 기능 ID 에 추가했다.
  신고는 대상이 특정되어야 접수 가치가 있는데 목록 화면에서 누르면 무엇을 신고하는지 알 수 없다.
  아이콘도 `flag` → **`siren`** 으로 교체했다 (`flag` 는 북마크인지 신고인지 읽히지 않는다).
  기능명세서 5-2 에 공통 동작 아이콘 표를 새로 넣어 글리프를 고정했다

### 2026-08-14 (추가) — 로컬 실행·카카오 연동 실패가 원인을 말하도록

지도가 안 뜰 때 회색 빈 박스만 나와서 사용자가 원인을 알 수 없던 문제.

- **`map/kakaoLoader.js`**
  - **10초 타임아웃 추가.** 카카오는 미등록 도메인에도 스크립트를 200 으로 내려주는 경우가 있어
    `script.onerror` 가 걸리지 않고, `kakao.maps.load` 콜백이 오지 않으면 Promise 가 영원히 대기한다.
    이제 실패로 떨어져 `KakaoMap` 의 `MapCanvas` 폴백 + 사유 표시 경로를 탄다
  - **에러 문구에 현재 origin 을 넣는다** — 콘솔에 등록할 주소를 그대로 복사할 수 있게
  - **기존 스크립트 태그 재사용 분기 수정** — 로드가 끝난 태그에 `onload` 를 다시 걸어
    영원히 대기하던 버그. `window.kakao.maps` 존재 여부로 먼저 가른다
  - **실패를 영구 캐싱하지 않는다** — reject 후 `promise = null` 로 되돌려, 앱키나 도메인을 고친 뒤
    재시도할 수 있다
  - 주석의 도메인 등록 경로를 현행으로 정정:
    `[플랫폼 > Web > 사이트 도메인]`(구) → `[앱 설정 > 앱 > 플랫폼 키 > JavaScript 키 > SDK 도메인]`(현)
- **`_ds_loader.js`** — 실행 안내를 `python -m http.server` 에서 `node tools/serve.mjs` 로 교체.
  Windows 에서 `python` 이 Microsoft Store 앱 실행 별칭이면 조용히 아무 것도 하지 않고 끝나
  "서버를 띄웠는데 연결이 안 된다"가 된다. 화면에 뜨는 에러 문구도 같이 고쳤다
