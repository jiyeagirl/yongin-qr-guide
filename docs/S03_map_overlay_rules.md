## 0. 기준 컨테이너 — 먼저 합의할 것

시트 높이와 지도 패딩의 % 는 **뷰포트가 아니라 "지도 영역"** 기준이다.

```
┌─────────────────────────┐
│ ContextBar   한 줄(≈40) │  z 300   ← QR 기준점, 항상 노출 (U-CM-04)
├─────────────────────────┤
│                         │
│   지도 영역             │  position: relative
│   (남는 높이 전부)       │  ← 시트 %, 지도 패딩 %, 플로팅 clamp 의 기준
│                         │
├─────────────────────────┤
│ TabBar            64px  │  z 450   ← 항상 노출 (U-CM-03)
└─────────────────────────┘
```

> **앱바를 없앴다** (2026-08-18). 앱바 56 + 띠 48 로 상단이 100px 을 넘게 먹고 있었는데 그
> 아래가 지도라 화면에서 가장 비싼 자리다. 지점명은 띠 한 줄이 그대로 이어받는다 (U-CM-04).
> 지도 영역은 그만큼 커졌고, **아래 % 는 여전히 지도 영역 기준**이라 값 자체는 그대로다 —
> 다만 px 환산은 아래 수치보다 조금씩 커진다. 코드가 실측(px)으로 계산하므로 어긋나지 않는다.

390×844 기기에서 지도 영역 ≈ **740px** (앱바를 없애기 전 676px). 아래 px 환산은 개정 전 값이며,
비율과 규칙을 읽기 위한 것이지 코드가 쓰는 수가 아니다.

> 기존 토큰은 지도 패딩을 `vh` 로 적어 두었는데, 뷰포트에는 앱바·컨텍스트바 98px 이 포함되므로
> 그만큼 과대 계산된다. 이번에 % 로 바로잡았다. (`CHANGELOG.md` 참조)

## 1. 바텀시트 3단 스냅 — 지도 노출 비율

> **% 를 읽을 때 주의.** 이 표의 % 는 **지도 영역** 기준이다. 지도 영역은 뷰포트의 80%(676/844)이므로
> 눈으로 보는 "화면의 몇 %" 와 숫자가 다르다. 예: 시트 37% ≈ **화면의 30%**.
> 두 값을 헷갈리면 "30% 로 해달라"는 요청에 시트를 30% 로 잡아 실제로는 화면의 24% 가 된다.

| 스냅 | 시트(지도영역) | **지도 노출** | 676px 환산 | 화면 대비 | 근거 |
| --- | --- | --- | --- | --- | --- |
| 접힘 collapsed | 18% | **82%** | 시트 122px | 14% | 시트 헤더(핸들 21 + 제목 26 + 요약 두 줄 51 + 여백 16 ≈ **114px**) 딱 그만큼. 접으면 "여기가 어디이고 몇 곳인지"만 남고 목록은 지도에 자리를 내준다 |
| 절반 half | 37% | **63%** | 시트 250px | **30%** | 기본 상태. 헤더를 빼면 목록 128px — 시설 1.5행 / 점포 2행. 목록을 *읽는* 높이가 아니라 목록이 아래 있다는 것을 알리는 높이다 |
| 전체 full | 100% − 필터 바 | **0%** | 시트 676 − 필터 바 | 100% | **목록 화면**. 목록을 볼 때는 목록만 본다. 단 상단 필터 바는 덮지 않는다 (아래) |

> **시트는 상단 필터 바를 덮지 않는다 (2026-08-14).** 시트가 z 500, 필터 바가 z 300 이라
> 막아두지 않으면 시트를 끌어올릴 때 검색창과 칩이 **위에서부터 잘려 나간다.**
> `Sheet` 의 `topInset` 에 필터 바의 실측 높이를 넘겨 전체 스냅 높이와 드래그 상한을 함께 줄인다.
> 필터 바가 있는 화면에서 "전체"는 지도 영역 전부가 아니라 **필터 바 아래 전부**다.
>
> 대안이었던 "전체 스냅에서 필터를 시트 헤더 안으로 옮겨 붙이기"는 버렸다. 드래그 **도중에는**
> 여전히 잘렸고(스냅이 아직 `full` 이 아니므로), 필터가 화면 위아래로 순간이동해 자리를 잃었다.
> 시트를 막는 쪽이 z 순서를 그대로 두고 필터의 물리적 위치도 늘 같다.

토큰: `--sheet-collapsed / -half / -full`, 여집합은 `--map-visible-*`

> **접힘 25% → 18%, 절반 62% → 37% (2026-08-14).** 지도를 더 보고 싶다는 요청에 따른 조정이다.
> 이 서비스는 "여기가 어디인가"를 답하는 것이 먼저이고 목록은 그 다음이라는 판단이므로,
> 기본 상태에서 지도가 화면의 3분의 2를 갖는다. 목록을 읽을 때는 시트를 끌어올린다.
>
> 이 조정으로 **"목록 3행이 보여야 목록으로 읽힌다"는 기존 근거는 포기했다.** 절반에서 보이는 것은
> 첫 1~2행뿐이다. 대신 그 첫 행이 잘리지 않고 온전히 보이는 선(250px)을 하한으로 잡았다 —
> 반쯤 잘린 행은 "더 있다"는 신호가 아니라 레이아웃 오류로 읽힌다.

> **전체 스냅은 90% → 100% 로 바뀌었다 (2026-08-14).** 90% 일 때 남는 10% 는 스크림에 덮여
> 회색 띠로만 보였고, 지도로도 목록으로도 쓸모가 없었다. 대신 지도로 돌아갈 길이 반드시 필요하므로
> 시트 헤더 오른쪽에 **[지도]** 버튼을 둔다 — 핸들을 아래로 끄는 방법만 남기면 발견하지 못하는 사용자가 생긴다.

> **`Sheet` 의 `SNAP_RATIO` 와 토큰은 반드시 같은 값이어야 한다.** CSS 는 시트 높이를, 그 표는
> 드래그를 놓았을 때 어느 단계로 붙일지를 맡는다. 둘이 어긋나면 절반에 둔 시트를 조금만 끌어도
> 다른 단계로 튄다 (실제로 한 번 어긋났었다 — CHANGELOG 참조).

### 미리보기 카드가 뜨면 시트는 **접힘**이다 (2026-08-26 개정, 사용자 요청)

목록 행이나 지도 마커를 눌러 카드가 뜰 때, 시트가 절반·전체에 있으면 **접힘으로 내린다.**
종전에는 전체일 때만 절반으로 내렸는데, 그러면 카드가 뜬 화면이 시트 37% + 카드 + 탭바라
**지도가 3분의 1도 남지 않는다** — 정작 카드가 가리키는 마커를 보라고 띄운 카드다.
지금 무엇을 보고 있는지는 카드가 말하고 있고, 그 아래 목록은 방금 그중 하나를 고른
목록이라 지금 읽을 것이 아니다. 접힘(18%)은 시트 헤더 딱 그만큼이라 「목록이 아래
있다」는 것만 남는다.

**카드의 [x] 를 누르면 내리기 전 자리로 돌아간다.** 목록에서 한 곳을 눌러 본 사람이
카드를 닫는 것은 「보던 목록으로 돌아간다」는 뜻이다. 그 사이에 시트를 직접 끌었으면
기억을 버린다 — 그때는 시트의 자리를 사람이 새로 정한 것이라, 되돌리면 방금 한 일을
취소하는 셈이 된다. 탭을 옮길 때도 함께 버린다.

**전체에서 올 때만 카드를 시트가 멈춘 뒤에 띄운다** (`--dur-slow` 뒤). 카드는
`bottom = 시트 높이`로 시트 윗변에 얹혀 있고 그 값은 트랜지션이 도는 동안 프레임마다
갱신되므로, 전체에서 바로 띄우면 **필터 바 바로 아래에서 나타나 지도를 가로질러
흘러내린다.** 절반 → 접힘은 그 거리가 카드 한 장 남짓이라 시트와 함께 자리를 잡는
것으로 보인다 — 거기에 320ms 를 걸면 마커를 눌러도 한참 아무 일이 없는 화면이 된다.

동작
- 핸들을 끌면 손가락을 따라오고, 놓으면 가장 가까운 스냅으로 붙는다
- 짧게 탭하면 접힘 → 절반 → 전체 순환
- **스크림을 쓰지 않는다.** 전체 스냅이 지도를 100% 덮으므로 뒤에 비칠 것이 없다
  (`Sheet` 의 `scrim` prop 은 남아 있고, 명시적으로 요청한 화면에서만 켜진다)
- 키보드: Enter/Space 순환, ↑↓ 한 단계 이동
- 전환은 `--dur-slow 320ms` / `--ease-out`

고정 px 가 아니라 % 인 이유: 2차 글자 확대에서 행 높이가 늘어도 비율은 유지된다.

## 2. 마커 탭 시 지도 패딩

문제: 마커를 탭하면 지도가 그 마커를 화면 중앙으로 옮기는데, 중앙은 이미 시트에 덮여 있다.
탭한 마커가 시트 뒤로 숨어 아무 반응이 없는 것처럼 보인다.

### 계산

지도는 **위아래 양쪽**에서 가려진다. 위는 상단 필터 바, 아래는 시트다.

```
topPad    = 상단 필터 바 실측 높이 + --map-pad-gap
bottomPad = 시트 실측 높이
          + (미리보기 카드가 떠 있으면 카드 높이 + --map-pad-gap)
          + --map-pad-gap                       // 24px

실제로 보이는 띠의 중앙 y = topPad + (지도 높이 - topPad - bottomPad) / 2
```

지도에 넘기는 방법 (카카오맵에는 `setPadding` 이 없다):

```js
// 지도 중심을 화면 좌표 P 의 좌표로 옮기면 P 가 지도 정중앙으로 간다. 따라서
//   마커의 새 y = 지도높이/2 - (P.y - 마커y)
// 이걸 목표 y 와 같게 두고 풀면  P.y = 마커y + (bottomPad - topPad) / 2
const proj = map.getProjection();
const pt = proj.containerPointFromCoords(markerLatLng);
map.panTo(proj.coordsFromContainerPoint(
  new kakao.maps.Point(pt.x, pt.y + (bottomPad - topPad) / 2)
));
```

### 설계 기본값 (토큰)

| 스냅 | `--map-pad-*` | 676px 환산 |
| --- | --- | --- |
| 접힘 | 22% | 149px |
| 절반 | 41% | 277px |
| 전체 | 41% | — 전체에서는 지도를 조작하지 않는다. 절반 값을 그대로 두어 시트가 다시 내려올 때 카메라가 튀지 않게 한다 |

### 실행 시에는 measure 한 px 를 쓴다

토큰의 % 는 설계 기본값이다. 실제로는 `Sheet` 의 `onHeightChange` 가 올려보낸 **실측 px** 를 쓴다.
스냅이 바뀌면 자동으로 따라오고, 2차 글자 확대로 시트 헤더가 커져도 어긋나지 않는다.

또 하나: 지도를 올려 잡는 것만으로는 "탭이 먹혔다"는 느낌이 안 난다.
탭한 대상이 무엇이었는지가 그 자리에서 읽혀야 하므로 **`MapPreviewCard`** 를 시트 위에 띄운다.
카드가 떠 있는 동안에는 카드 높이도 가림 높이에 포함된다.

### 목록 행을 눌러도 마커를 누른 것과 같다 (2026-08-18 개정)

전에는 시트의 행을 누르면 곧장 상세(S05/S06)로 갔다. 그런데 목록과 지도는 **같은 배열**을
보고 있는데(`storeMarkers === storeRows`), 목록에서 고른 것이 지도의 어디인지가 목록만
봐서는 끝내 드러나지 않았다. 이 서비스가 답하는 질문이 "저기 어디 있나"인데 행을 누르면
지도를 지나쳐 상세로 건너뛴 셈이다.

지금은 행을 누르면 **마커를 누른 것과 똑같이** 동작한다 — 그 마커가 켜지고, 지도가 그리로
움직이고, 카드가 뜨고, 거기서 [길찾기]와 [상세 보기]로 갈라진다. 전체 스냅이었다면 절반으로
내려온다 (`pickOnMap`). 상세로 가는 길이 한 번 더 눌러야 하는 길이 됐지만, 그 한 번이
**어디인지 보여주는** 한 번이다.

**시트가 내려와야 하면 카드는 내려온 다음에 뜬다** (2026-08-25 개정). 종전에는 선택과
스냅 변경을 같은 프레임에 했는데, 카드가 `bottom = 시트 실측 높이` 로 시트 윗변에 얹혀
있어 **뜨는 순간의 앵커가 아직 전체인 시트의 윗변**이었다 — 카드가 필터 바 바로 아래에서
나타나 지도를 가로질러 흘러내렸다. 지금은 스냅만 먼저 바꾸고 시트가 멈춘 뒤
(`SHEET_SETTLE` = `--dur-slow` + 한 프레임) 선택을 넣는다. 그 320ms 동안 감춰지는 것은
없다 — 전체 스냅은 시트가 지도를 통째로 덮은 상태다. 시트가 이미 절반·접힘이면 기다릴
것이 없어 종전대로 즉시 뜬다(지도 마커를 직접 누르는 경우가 전부 이쪽이다).

목록과 지도는 같은 어댑터(`pickFacility` · `pickDistrict`)를 부른다. 한쪽에만 두면 같은
것을 눌렀는데 카드에 적히는 말이 눌린 자리에 따라 달라진다.

**그래서 그 줄에는 꺾쇠(`>`)가 없다** (2026-08-18). 꺾쇠는 "누르면 다른 화면으로 간다"는
뜻인데 이제 화면이 바뀌지 않는다 — 보고 있던 지도에서 핀이 켜질 뿐이다. 다른 곳으로 갈
것처럼 말해놓고 제자리에 두면 그 다음에 무엇을 눌러야 할지 알 수 없다. 상세로 가는 길은
미리보기 카드의 [상세 보기]가 맡고, 꺾쇠도 거기 붙어 있다. 반대로 **정말 나가는 줄에는
그대로 단다** — 용인시 누리집으로 나가는 `DistrictRow`, 오버레이를 걷고 탭을 옮기는
주변 공공시설 목록.

**상점가 탭의 "주변 공공시설"은 탭을 옮겨서 켠다** (2026-08-18). 그 탭은 점포 레이어를
갖고 있어 시설 마커가 지도에 없다 (U-CM-17: 한 번에 한 레이어) — 여기서 카드를 띄워도
가리킬 핀이 없다. 그래서 상세로 보내는 대신 **그 시설이 실제로 그려지는 공공시설 탭으로
데려가** 거기서 켠다. 목록에서 고른 것을 지도에서 보여준다는 규칙을 지키면서 레이어 규칙도
깨지 않는 유일한 길이다. 유형 필터가 그 시설을 걸러내고 있으면 그 유형으로 좁힌다 —
"전체"로 풀면 사용자가 걸어둔 조건을 말없이 지우는 셈이고, 그대로 두면 켤 마커가 없다.

**점포 상세(S06) 하단의 같은 목록도 마찬가지다.** 한때 여기만 시설 상세로 보냈다 —
오버레이를 닫고 탭까지 옮기는 것이 과하다고 봤다. 그런데 **같은 목록을 어디서 눌렀느냐에
따라 다른 곳으로 가는 것**이 더 나빴다. 예외를 없앴다: 오버레이를 전부 걷고(`closeAll`)
공공시설 탭으로 내려와 그 시설을 켠다. 셸은 언마운트되지 않으므로 그 사이의 상태 갱신이
그대로 살아남아, 지도가 드러날 때 이미 켜져 있다 (U-CM-16).

**둘러보기(S04)의 신규·인기 매장 카드도 마찬가지다** (2026-08-18). 그 탭에는 지도가
아예 없으므로 여기서도 탭을 옮긴다 — 상점가 탭으로 내려와 그 점포를 켠다.

다만 여기는 걸러낼 축이 셋이다(업종 칩 · 온누리 · 검색어). 이 카드는 335곳 목록을 우회하는
지름길이라(U-ST-09), 지름길로 고른 가게가 필터에 걸려 지도에 없으면 지름길이 아니라 막다른
길이 된다. 그래서 **걸린 축만 골라 푼다.** 업종 칩은 그 가게의 업종을 **더하고**(2026-08-20.
여럿 고르기가 되면서 바꾸지 않고 더할 수 있게 됐다 — 걸어둔 조건을 아무것도 잃지 않는다.
위와 같은 이유로 전부 해제하지 않는다), 온누리와 검색어는 좁힐 자리가 없어 끄는 수밖에 없다.
아무것도 걸리지 않았으면 아무것도 건드리지 않는다 — 대개 이 경우다.

카드가 들고 있는 것은 `note`("이번 주 조회 1위")가 붙은 사본이므로 `id` 로 원본을 되찾아
고른다. 사본을 그대로 넘기면 목록용 문구가 `selected` 에 딸려 들어간다.

상세가 필요하면 지도에 뜨는 카드의 [상세 보기]가 한 번에 데려간다. 그 카드에는 [길찾기]도
함께 있어, 상세로 곧장 갔을 때보다 갈 곳이 오히려 많다.

**남은 예외는 없다.** 점포·시설·상점가를 어디서 눌러도 지도의 미리보기 카드를 거친다.
축제(S09)와 코스(S10)만 곧장 상세로 가는데, 그 둘은 지도 위의 점이 아니라 읽을거리다.

## 3. 플로팅 컨트롤 앵커링

문제: 목록 토글과 QR 지점 복귀 버튼을 화면 하단에 고정하면 시트가 올라올 때 시트 뒤로 사라진다.

```
bottom = clamp( --float-gap,                                  // 12px, 최소
                시트 실측 높이 (+ 카드 높이 + gap) + --float-gap,
                100% - 상단 필터 바 실측 - 기둥 실측 높이 - --float-gap )
right  = --float-inset                                        // 16px
```

> **위쪽 상한이 `44px` 상수에서 실측 둘로 바뀌었다** (2026-08-26). 그때는 이 기둥에
> 단추 하나뿐이라 44 가 곧 기둥의 높이였고, 상한이 지도 영역의 위끝만 막으면 됐다.
> 반경 고르개(아래)가 서면서 기둥이 200px 을 넘게 되어 둘 다 다시 잡았다 —
> **기둥의 높이**는 안에 무엇이 서는지 부품이 모르므로 잰다(2차 글자 확대도 함께 따라온다),
> **상단 필터 바**는 시트에게 넘기는 `topInset` 과 **같은 실측값**이다. 시트가 필터 바
> 아래까지만 올라오는 것과 같은 이야기이고, 막지 않으면 작은 화면 + 절반 스냅에서
> 기둥 윗머리가 검색창과 칩 위로 올라선다 (기둥이 z 400, 필터가 z 300 이다).

- 시트 상단(미리보기 카드가 있으면 카드 상단)에 붙어 **함께 움직인다**
- **이동에는 트랜지션을 걸지 않는다** (2026-08-25 개정). 종전 규칙은 "시트와 같은
  `--dur-slow` / `--ease-out`"이었는데, 앵커로 넘어오는 시트 높이가 이미 프레임마다
  갱신되는 실측값이라 거기에 320ms 를 한 번 더 걸면 버튼이 시트보다 **늦게 출발해
  시트가 멈춘 뒤에도 혼자 미끄러진다.** 트랜지션을 빼야 시트에 붙어 움직인다.
  `opacity` 는 그대로 둔다 — 그쪽은 전체 스냅에서 한 번 바뀌는 값이다
- **전체 스냅에서는 `opacity 0` + `pointer-events none`.** 시트가 화면 전체를 소유한다

### 플로팅 **버튼**은 [스캔 위치로] 하나뿐이다 (2026-08-18 개정)

| 버튼 | 상태 | 이유 |
| --- | --- | --- |
| 목록 | **없음** | 시트를 위로 끌면 되는 일을 버튼이 한 번 더 제공하고 있었다. 시트 자체가 목록/지도 토글이다 |
| QR 지점 복귀 | **지도 우측 하단** | 지도를 끌어 움직인 뒤에 되돌리고 싶어지는 자리는 지도 위이지 화면 맨 위가 아니다 |

> **2026-08-14 에는 두 버튼 모두 없앴었다.** 그때 QR 지점 복귀는 컨텍스트 바의
> **[지점으로 이동]** 이 맡고 있었기 때문이다. 그 바가 얇은 한 줄로 줄면서(아래 4장 개정)
> 버튼이 갈 곳이 없어졌고, 원래 규칙대로 지도 위로 내려왔다.
> 결과적으로 위 앵커링 규칙이 처음으로 실제 화면에 쓰인다 — 규칙만 있고 대상이 없던 상태가 끝났다.

버튼은 이것 하나다. 지도 위에 버튼을 늘리지 않는다는 원칙은 그대로다.

### 자리는 **지도 우측 하단**이고, 통일감은 **폭이 낸다** (2026-08-26 개정, 사용자 요청)

> **같은 날 이 단추를 반경 고르개 바로 아래로 올렸다가 되돌렸다.** 올린 근거는
> 「닮게 만들었으면 붙여야 한다」였다 — 둘이 같은 알약이 되고 나니 화면 위아래 끝에
> 하나씩 떨어져 선 것이 「같은 것이 왜 두 군데 있나」로 읽혔다. **붙여 놓고 보니 화면
> 오른쪽 위가 검색창 · 칩 줄 · 고르개 · 단추로 넉 줄이 됐다** — 지도를 보라고 만든
> 화면에서 위쪽이 통째로 막히는 것이 v1.11 이 내내 고쳐 온 바로 그 문제다.
> `FloatingControls` 의 `place="top"` 은 손님이 없어져 함께 지웠다.

**통일감은 자리가 아니라 모양이 낸다.** 둘은 높이도 폭도 같고, 그거면 멀리 있어도
한 벌로 읽힌다.

- **폭이 같다** — `--float-pill-min`(108px). 높이·바탕·테두리·그림자·글자색은 이미
  같았고 **폭만 글자 수를 따라 달랐다**(「반경 4km」 ≈ 92px, 「스캔 위치로」 ≈ 104px).
  나란히 놓였다면 오른쪽 끝만 맞춰도 같아 보이지만 **둘은 화면의 반대쪽 끝에 떨어져
  선다** — 그때 한 벌인지를 말하는 단서는 **각자의 덩어리 크기**뿐이다
- 고르개에서 남는 폭은 `space-between` 이 가른다: 글자는 왼쪽에, 삼각형은 오른쪽 끝에
  붙는다 (가운데로 모으면 삼각형이 알약 안쪽으로 떠서 무엇에 딸린 표시인지 흐려진다)
- `min-width` 이지 `width` 가 아니다 — 2차 글자 확대에서 내용이 넘치면 알약은 그대로
  늘어난다. 그 크기에서는 둘의 폭이 다시 갈릴 수 있는데, **글자가 잘리는 것보다 폭이
  어긋나는 편이 낫다**
- 자리와 앵커링은 위 표·규칙 그대로다 — 시트 윗변에 붙어 함께 움직이고, 전체 스냅에서는
  감춘다

### 단추는 **아래 반경 고르개와 같은 알약이다** (2026-08-26 개정, 사용자 요청)

이 단추와 안내 반경 고르개(아래)는 **같은 지도 위에 함께 떠 있는 둘**인데 서로 다른
부품처럼 보였다 — 한쪽은 34px 알약에 13px 글자, 이쪽은 48×44 둥근 네모에 아이콘을 이고
선 12px 글자였다. **지도 위에 뜨는 것이 둘뿐이면 둘은 같은 것이어야 한다.**

`FloatingControls` 의 `subtle` 이 이제 `InlineSelect.floating` 과 **같은 값을 쓴다.**

- **높이 34px · 알약 · `--surface-float-translucent`(.82) + `--blur-glass` ·
  `--border-float-translucent` · `--shadow-card` · `--text-body`** — 한 줄도 다르지 않다.
  손가락 자리는 위아래 5px 투명 여백으로 44px (Chip · `InlineSelect` 와 같은 두 겹)
- **글자는 아이콘 옆에, `--fs-micro`(12px)**. 아이콘은 14px 다. 아침에 옆에 붙였다가
  알약이 120px 을 넘어 지도 오른쪽 아래를 덮은 적이 있어 한때 세로로 쌓았는데,
  이 글자 크기에서는 **옆에 붙여도 100px 남짓**이다 — 높이가 48 에서 34 로 내려간 만큼을
  폭으로 돌려준 셈이고, 그 값에서는 둘이 같은 것으로 읽히는 편이 낫다
- 글자를 다시 떼지는 않는다 — 그림 하나로는 어디로 가는 단추인지 배워야 알기 때문에
  붙인 글자다 (v1.9)

> **쌓기는 없어졌다.** 「아이콘 위 · 글자 아래」는 폭을 아이콘만큼(≈48px)으로 줄이려던
> 것이었고 그 목적은 이뤘지만, **같은 지도 위의 다른 하나와 닮지 않는 값**이었다:
> 세로 두 줄이라 알약으로 말 수 없어 모서리 둥근 네모였고, 그래서 높이도 44 를 넘었다.
> 폭 50px 을 아끼는 것보다 **둘이 한 벌로 보이는 것**이 낫다는 것이 이번 판의 판단이다.

### 안내 반경 고르개는 **필터 바의 칩 줄 아래**에 있다 (2026-08-26, 사용자 요청)

공공시설 탭(S02)에만 있다. 상점가 목록은 반경이 아니라 **소속 상점가**가 정하므로,
저기서 같은 것을 그리면 아무것도 뜻하지 않는 동그라미가 된다.

> **아침에는 지도 오른쪽에 세로로 서 있었다** (`RadiusSlider` — 알약 안에 `4km / 3km /
> 2km`, 밀거나 눌러 고르기). 같은 날 통째로 걷어냈다: 세 칸이 각각 손가락 자리를
> 가지려니 200px 짜리 기둥이 됐고, 그것이 서 있는 내내 **지도 오른쪽 3분의 1이
> 가려졌다.** 고를 것이 셋뿐이면 펼쳐 두는 것이 아니라 **접어 두는 것**이 맞다.

- **자리는 칩 줄 **아래**, 오른쪽 끝**이다 (`MapFilterOverlay` 의 `trailing`).
  칩과 같은 줄에 두지 않는 이유는 4장에 있다 — 칩 줄은 화면 끝까지 흘러 마지막 칩이
  잘린 채 걸치는 것으로 「더 있다」를 말하는데, 오른쪽 끝에 무언가를 고정하면 그 신호가
  사라진다. 제 줄을 갖되 왼쪽은 비워 두어 그 줄로도 지도가 보인다. 오른쪽 끝은 위
  검색창·칩 줄과 **같은 세로선**이다
- **모양은 필터 칩과 같은 알약**이다 (`InlineSelect` 의 `floating`). 같은 바 안에 서는
  것이라 다르면 안 된다 — 34px · `--fs-caption`, 손가락 자리는 위아래 투명 여백으로
  44px (Chip 과 같은 수법)
- **바탕은 위 [스캔 위치로]와 같은 값이다** — `--surface-float-translucent`(.82) +
  `--blur-glass`, 테두리 `--border-float-translucent`. 하루에 네 번 고친 자리다:
  흰 판 + `--border-strong` → `.70` + 흐림 → **완전 투명** → 지금 (2026-08-26, 네 번 다
  사용자 요청)

  > **투명은 안 됐다.** 알약을 걷고 글자에 흰 테(`--halo-on-map`, 지도 라벨의 수법)를
  > 둘렀는데 화면에서 읽히지 않았다 — 테는 획 둘레 1~2px 를 밝히는 것이라 글자와 배경의
  > 밝기가 비슷하면 **획만 도드라지고 덩어리가 배경에서 떨어지지 않는다.** 지도 라벨이
  > 그걸로 버티는 것은 획이 굵고 자간이 넓어서다. **막을 얇게 하는 것과 없애는 것은
  > 다른 일**이고, 없앤 자리에는 글자를 앉힐 바닥이 없다.
  >
  > `.82` 로 돌아온 것은 그것이 [스캔 위치로]가 이미 쓰는 값이어서다 — 요청은 「80%
  > 정도」였고 2 포인트 차이로 토큰을 하나 더 두는 것보다 **지도 위에 떠 있는 둘이 같은
  > 바탕인 편이 낫다.** `--surface-float-translucent-soft`(.70) 는 지웠다.
- 단추에 적히는 것은 **「반경 3km」**, 펼친 목록은 「2km / 3km / 4km」다. 소수점을
  적지 않는다(「3.0km」가 아니다) — 이 셋은 재서 알려주는 거리가 아니라 **고르는
  눈금**이다. **왼쪽 아이콘은 없다** (2026-08-26 오후, 사용자 요청): `circle-dot` 이
  서 있었는데 그 그림이 가리키던 지도의 원이 없어졌고(아래), 단추 글자가 이미
  「**반경** 3km」라고 축을 적는다
- **오른쪽은 꺾쇠가 아니라 채워진 삼각형**(자체 제작 `caret-down`, 13px)이다
  (2026-08-26, 사용자 요청). 표시 자체는 남아야 한다 — 누를 수 있다는 말은 글자가 하지
  못한다. 다만 **지도 위에서 2px 짜리 윤곽선 획은 길·구획선과 굵기가 같아 섞인다.**
  채워진 덩어리는 같은 크기에서도 배경과 갈린다. 모서리는 둥글렸다 — 각진 삼각형은
  13px 에서 꼭짓점 셋이 바늘처럼 서서 옆 글자보다 눈에 먼저 든다. **줄 안에 서는
  고르개(정렬·출발지)는 꺾쇠 그대로다** — 그쪽은 흰 카드 위라 섞일 것이 없다
- **고른다고 지도가 움직이지 않는다** (2026-08-26 오후, 사용자 요청). 고르는 즉시
  그 반경에 축척을 맞췄었다(`KakaoMap` 의 `fitRadius`, 지금은 없다). 화면에서 일어난
  일은 **넓히려고 누른 사람 앞에서 지도가 작아지는 것**이었고, 곧바로 다시 확대하게 되니
  한 번 고를 때마다 손동작이 둘 딸려온다. 넓어졌다는 것은 **목록이 말한다** — 곳수가
  늘고 새 마커가 화면 가장자리에 나타난다. 축척은 사람이 정한다
- **지도에 반경 원은 없다** (같은 날 함께 걷어냈다. 점선 · 앵커와 같은 파랑 · 채움 5%
  였다). 축척을 사람 손에 돌려주고 나면 3·4km 원은 대개 화면 밖이라, 남겨 두면
  **가장자리에 걸친 호 한 조각**이 된다 — 무엇의 일부인지 알 수 없는 선이다

### 버튼은 **`qr-code` + 「스캔 위치로」** 다 (2026-08-26 개정, 사용자 요청)

처음에는 과녁(`crosshair`)이었다. **바꾼 이유는 그 그림이 다른 뜻을 이미 갖고 있어서다** —
어느 지도 앱에서나 과녁은 「GPS 로 지금 내가 선 자리를 찾는다」이고, 누르는 사람이 이
버튼도 그런 것으로 읽었다. 이 앱은 **GPS 를 쓰지 않는다**: 화면의 「내 위치」는 언제나
QR 을 찍은 그 지점이고 모든 거리가 거기서 잰 값이다 (제안서 3-1).

2026-08-25 에는 그 답으로 **자체 제작 아이콘**을 만들었다 — 지도 핀 윤곽 안에 QR 모듈
넷을 넣은 `qr-pin` 이다. **하루 만에 걷어냈다.** 그림은 맞는 뜻을 담고 있었지만 20px
짜리 버튼 안에서 모듈이 점으로 뭉개졌고, 뭉개지지 않았더라도 「핀 안의 QR = QR 을 찍은
자리」는 **처음 보는 사람이 한 번 배워야 아는 뜻**이다. 이 서비스의 사용자는 안내판 앞에
서서 처음 이 화면을 여는 사람이다.

지금은 **lucide `qr-code` 하나에 글자를 붙인다.** 그 그림은 이 앱에서 이미 컨텍스트 바가
「QR 스캔 지점 기준 안내」 앞에 세워 쓰는 것이라 같은 화면 안에서 뜻이 이어지고, 어디로
가는 버튼인지는 **글자가 적는다** — 지도 위에 버튼이 이것 하나뿐이라 폭이 늘어도 부딪힐
것이 없다. `FloatingControls` 는 `text` 가 있으면 알약이 넓어지며 오른쪽에 붙어 왼쪽으로
자란다 (`padding` 이 `0 12px` → `10px 14px`).

**`aria-label` 과 보이는 글자는 같은 「스캔 위치로」다.** 다르게 두면 음성으로 조작하는
사람이 화면에 보이는 이름을 불렀을 때 그 버튼이 반응하지 않는다.

> 자체 제작 아이콘 표(`Icon.jsx` 의 `LOCAL`)는 이것으로 **비었다.** 표는 남는다 —
> lucide 에 정말 없는 그림이 다시 필요해질 자리이고, 쓰는 법이 그 자리에 적혀 있다.

- 목록/지도 전환은 화면을 나누지 않는다: 시트를 전체 스냅으로 끌면 목록, 시트 헤더의 `지도` → 절반 스냅.
  별도 목록 라우트를 만들지 않는다

## 4. 상단 필터 바의 고정 범위

> **2026-08-14 개정.** 처음에는 필터를 전부 시트 안에 넣고 업종 칩만 sticky 로 두었다.
> 국내 지도 앱(네이버 지도)과 비교한 결과 **필터는 시트가 아니라 지도 위에 있어야 한다**로 바꿨다.
> 이건 취향 문제가 아니라 5-3 레이어 표를 제대로 따르는 쪽이다 —
> 표에는 처음부터 `z 300 | 상단 필터 바 | 스크롤해도 고정` 이 지도 위 독립 레이어로 정의되어 있었는데,
> 필터를 시트(z 500) 안에 넣는 바람에 그 레이어가 비어 있었다.

S03 에는 필터가 **넷**이다 — 업체명 검색, 업종 칩, 온누리 칩, 정렬 고르기(U-ST-15).
전부 한 곳에 고정하면 시트 상단의 절반 가까이가 필터로 찬다. 그래서 **성격에 따라 둘로 나눈다.**

### 목록은 쪽으로 끊는다 (2026-08-18 개정)

전에는 무한 스크롤이었다 (20곳씩 이어붙임). U-ST-04 가 요구한 "한 번에 다 그리지 않는다"는
지켜졌지만 **끝이 없는 목록**이 됐다 — 335곳을 내려가는 동안 어디쯤 왔는지도 얼마나 남았는지도
알 수 없고, 처음으로 돌아가려면 내려온 만큼을 되감아야 했다. 쪽으로 끊으면 목록에 끝이 생기고
[1]이 늘 손 닿는 곳에 있다. 한 쪽 20곳, 335곳이면 17쪽이다.

**지도 마커는 쪽을 따르지 않는다.** 필터에 걸린 335곳이 전부 그대로 찍힌다 — 쪽은 읽는
단위이지 범위가 아니고, 2쪽으로 넘겼다고 지도의 핀이 사라지면 지도가 목록의 부속이 된다.
목록과 마커가 같은 배열을 본다는 규칙(U-ST-13)은 **필터 결과** 기준이지 쪽 기준이 아니다.

쪽을 넘기면 시트 스크롤이 맨 위로 돌아간다. 쪽 단추가 목록 끝에 있어서, 그러지 않으면
새 쪽의 끝줄 근처가 열려 방금 넘긴 쪽의 위쪽을 못 본 채 다시 올려야 한다. 조건이 바뀔 때와
같은 장치(`scrollKey`)를 쓰며, 그래서 쪽 번호도 셸이 들고 있다.

### 지도 위는 두 줄을 넘기지 않는다

지도 위 고정은 곧 지도를 그만큼 영구히 가린다는 뜻이다.

- **배경 패널을 깔지 않는다.** 흰 알약만 그림자와 함께 떠 있어 사이사이로 지도가 보인다.
  패널을 깔면 두 줄이 아니라 두 줄 크기의 불투명 판이 된다.
- 합계 약 **96px** (검색 44 + 칩 44 + 간격). 676px 지도 영역의 14%.
  온누리 칩을 목록 쪽으로 내리면서 세 줄이 될 뻔한 것을 두 줄로 막았다.

### 정렬은 필터를 대체하지 않는다

정렬은 업종 칩·온누리·검색과 **독립된 축**이다 (U-ST-15 "업종 칩과 조합 가능해야 한다").
`음식 칩 + 인기순`, `온누리 + 인기순` 이 모두 성립한다. 정렬을 칩 줄에 8번째 칩으로 넣지 않는 이유다.

인기 매장을 **카드 섹션이 아니라 정렬 축으로** 처리하는 이유는 기능명세서 4장 각주 그대로다 —
상점가 탭은 이미 상단이 필터로 차 있고 그 아래 수백 개 무한스크롤이 이어지므로,
카드 섹션을 얹으면 실제 목록이 두세 번 스크롤해야 보이기 시작한다.
카드 섹션은 목록과 경쟁할 요소가 없는 **둘러보기 탭(S04)** 이 가져간다 (U-DC-02).

### 온누리 칩이 목록 쪽인 이유

U-ST-11 은 온누리를 업종 칩과 **분리**할 것을 요구한다. 축이 다르기 때문이다 —
업종 칩끼리는 OR 이고 온누리는 그 결과에 AND 로 겹친다. 지도 위 칩 줄에 붙여두면
그 차이가 보이지 않아 일곱 번째 업종처럼 읽힌다. 목록 제어 줄로 내리면 정렬과 나란히
"목록에 적용되는 조건"으로 묶여 성격이 분명해지고, 지도 위도 한 줄 아낀다.

> **모양은 2026-08-20 에 스위치에서 칩으로 바뀌었다** (U-ST-11 개정). 목록 쪽이라는 것은
> 그대로이고, 그 안에서 **제 줄을 버리고 결과 수 옆으로 올라왔다** —
> 「전체 335곳 (🎫 온누리 가맹점) ⇅ 거리순」 한 줄이다. 알약은 작은 크기(28px)를 쓰되
> 눌리는 자리는 44px 을 지키고, **가맹 수는 알약에 적지 않는다** — 켜면 왼쪽 결과 수가
> 곧 그 수다(「전체 139곳」).
>
> 업종 칩과의 분리는 자리와 색이 맡으므로(목록 위 · teal) 모양까지 다를 필요가 없었고,
> 스위치에는 **조건을 걷어낸다는 뜻이 형태에 없었다** — 칩은 켜지면 ×가 붙어 그것을 말한다.
> 이 줄로 목록 제어가 두 줄에서 한 줄이 되어 절반 스냅에서 점포 한 줄을 더 번다.

### 필터 바는 시트가 어디에 있든 자리가 바뀌지 않는다 (2026-08-14 개정)

전에는 전체 스냅에서 필터를 시트 헤더 안으로 옮겨 붙였다. 지금은 **시트가 필터 바 아래에서 멈춘다**
(규칙 1의 `topInset`). 필터는 언제나 지도 영역 맨 위 같은 자리에 떠 있다.

아래 옛 설명은 왜 그 방식을 버렸는지 기록으로 남긴다.

<details><summary>옛 방식 (inline 재배치)</summary>

목록만 보는 상태에서 필터를 못 쓰면 안 되므로, 이때는 `MapFilterOverlay` 가

## 5. 탭바와 바텀시트의 공존

둘 다 화면 하단에 있다. 명세서가 준 선택지는 두 가지였다.

| 방식 | 결과 |
| --- | --- |
| **탭바를 항상 보이게 두고 시트를 그 위에서 시작** ← 채택 | 지도 영역이 64px 줄어 스냅 수치를 다시 잡아야 한다 |
| 전체 스냅에서 탭바를 숨김 | 화면은 넓어지지만 목록을 끝까지 올린 상태에서 탭 전환이 막힌다 |

**탭바는 항상 보인다.** 구현상 탭바는 시트의 **형제 요소**이고, 시트는 탭바 위의 지도 영역
안에서만 움직인다. 그래서 전체 스냅(100%)에서도 탭바를 덮지 않는다.

근거: 탭바는 이 서비스의 **유일한 전역 내비게이션**이다 (별도 홈 화면이 없다).
목록을 끝까지 올린 상태에서 다른 탭으로 갈 길이 사라지면, 사용자는 시트를 다시 내려야 한다는 걸
스스로 알아내야 한다. 64px 을 아끼자고 만들 상황이 아니다.

`--z-tabbar: 450` 은 시트가 뷰포트 오버레이인 화면을 위해 유지한다. 이 화면에서는 둘이
레이아웃상 겹치지 않으므로 z 값이 실제로 쓰이지는 않는다.

## 6. 탭 전환 시 지도 동작

**카메라를 QR 지점으로 되돌리고 줌을 그 탭의 기본 레벨로 맞춘다.**

| 탭 | 카메라 | 이유 |
| --- | --- | --- |
| 공공시설 | QR 지점 + 레벨 4 | QR 지점 주변 (~500m) |
| 상점가 | QR 지점 + 레벨 4 | 상점가 한 구역 |
| 둘러보기 | **32개 지점을 담는 경계로 `fitTo`** | 대상이 QR 지점 주변이 아니라 32개소 전체(약 25km)다. 레벨을 상수로 찍으면 기기 폭과 분포에 따라 잘리거나 너무 멀어진다. 가려지는 위아래(필터 바 / 시트)는 padding 으로 넘긴다 — 규칙 2와 같다 |

근거: 지도를 멀리 끌어둔 채 탭을 바꾸면 새 레이어의 마커가 전부 화면 밖이라
"아무것도 없는 탭"으로 보인다. QR 지점은 이 서비스의 고정 기준점이므로 탭을 바꿀 때
거기로 돌아오는 것이 일관된다.

- **같은 탭 안에서는 유지한다.** 업종 칩이나 온누리를 바꿔도 카메라는 그대로다 —
  필터는 목록을 줄이는 동작이지 이동이 아니다
- 지도 인스턴스는 다시 만들지 않는다. `setCenter` + `setLevel` 만 호출한다 (U-CM-16)
- 탭을 바꾸면 시트는 절반 스냅으로, 선택된 마커는 해제된다

### 마커 레이어는 한 번에 하나 (U-CM-17)

탭이 소유한 레이어만 그린다. 시설 마커와 점포 마커를 동시에 노출하지 않는다.

- 공공시설 탭 → 시설 마커만 (유형 4종 색, 클러스터 없음)
- 상점가 탭 → 점포 마커만 (클러스터, U-ST-13)
- 둘러보기 탭 → 상점가 지점 마커만 (32개소, 축제 있는 곳은 호박색, 클러스터 없음)
- 상점가 탭의 "주변 공공시설"은 **목록으로만** 제공하고 지도에는 찍지 않는다.
  U-ST-07(연계 노출)과 U-CM-17(한 레이어)이 부딪히는 지점인데, 마커를 섞으면
  적색 시설 핀이 점포 클러스터 사이에 흩어져 무엇을 보는 화면인지 흐려진다

## 7. S02 공공시설 탭이 이 규칙을 어떻게 물려받았는가 (2026-08-14)

S02 는 이 문서의 값을 **하나도 바꾸지 않고** 그대로 쓴다. 그것이 이 문서가 존재하는 이유다.
탭마다 시트 높이나 필터 위치가 다르면 탭 전환이 화면이 통째로 바뀌는 것처럼 보인다.

| 규칙 | S03 상점가 | S02 공공시설 | 같은가 |
| --- | --- | --- | --- |
| 1. 시트 스냅 | 18 / 37 / 100% | 18 / 37 / 100% | **동일** |
| 2. 지도 패딩 | measure 한 px | measure 한 px | **동일** (아래 주의) |
| 3. 플로팅 컨트롤 | [QR 지점으로] 1개 | [QR 지점으로] 1개 | **동일** |
| 4. 상단 필터 바 | 검색 + 업종 칩 6종 | 시설 유형 칩 4종 | 위치·z·측정·여럿 고르기 동일, **축만 다름** |
| 5. 탭바 공존 | 시트의 형제 | 시트의 형제 | **동일** |
| 6. 탭 전환 시 지도 | QR 지점 + 레벨 4 | QR 지점 + 레벨 4 | **동일** |

### 지도 패딩은 반드시 measure 여야 한다는 것이 여기서 증명됐다

공공시설 탭에는 검색창이 없어 상단 필터 바가 한 줄 낮다. 만약 `topPad` 를 상수로 박아뒀다면
공공시설 탭에서 마커를 탭할 때마다 필요 이상으로 아래를 잡아 마커가 화면 위쪽으로 치우쳤을 것이다.
`MapFilterOverlay` 가 `ResizeObserver` 로 실측 높이를 올려보내고 `MainApp` 이 그대로
`KakaoMap` 의 `topPad` 로 넘기므로 두 탭이 자동으로 맞는다.

### 필터 축은 탭이 소유하고 상태도 분리한다

`cat`(업종)과 `fcType`(시설 유형)은 별개의 state 다. 하나로 합치면 탭을 오갈 때
"음식"이 "AED"로 둔갑한다. 대신 **탭을 바꿔도 각 탭의 필터는 지우지 않는다** —
상점가에서 "음식 + 온누리"를 걸어두고 공공시설을 잠깐 본 뒤 돌아왔을 때
조건이 풀려 있으면 사용자가 다시 걸어야 한다. 탭 전환이 지우는 것은 선택과 스냅뿐이다.

### U-FC-03 "목록과 지도 토글"은 별도 버튼이 아니다

시트 스냅 자체가 토글이다 (규칙 3에서 S03 이 이미 내린 결론과 같다).
시트를 끌어올리면 목록, 내리면 지도이며, 전체 스냅에서는 헤더의 **[지도]** 버튼으로 돌아온다.
같은 일을 하는 버튼을 하나 더 두면 시트 상태와 버튼 상태가 어긋나는 경우가 생긴다.

### 시설 마커는 클러스터에 넣지 않는다

점포는 335개라 클러스터가 필수지만(U-ST-13), 시설은 수십 단위다. 그리고 응급 시설이
클러스터 숫자 뒤로 숨는 상태를 만들면 U-FC-04(안전시설 우선 노출)의 취지에 어긋난다.
대신 유형 4종이 각자 핀 색을 갖는다 — AED/대피소는 적색 계열 두 단계, 화장실/쉼터는 중립 계열 두 단계
(`--pin-aed / --pin-shelter / --pin-toilet / --pin-rest`).

색만으로 4종을 가르는 것은 색약 사용자에게 불충분하므로(6장 남은 확인사항 #1),
목록에서 **유형 배지**를 글자로 달고 **안전시설 / 편의시설 섹션**으로 나눈다.
핀 색상 외 보조 구분은 이 두 가지로 해결한 것으로 본다.

## 함께 확정된 것

- **목록과 지도는 한 표면이다.** 별도 라우트를 만들지 않고 시트 스냅으로 전환한다
- **조아용은 이 화면에 한 번만 등장한다** (2026.08 개정). QR 스캔 지점 컨텍스트 바의 왼쪽 자리에서
  `qr-code` 아이콘을 대신한다. 목록·지도·마커·상세는 여전히 중립을 유지한다
  (빈 결과 Notice 에도 캐릭터를 쓰지 않았다)
- **언어·음성·글자 크기 버튼은 자리도 두지 않는다** (확정 결정사항 3). AppBar 의 `actions` 는
  코드 레벨에서만 확장 가능한 슬롯으로 남아 있다
- **고정 높이 금지.** 카드·버튼·목록 행은 `min-height` 만 쓴다 (U-CM-14)
