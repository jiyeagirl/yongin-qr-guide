## 1. 공공시설 (M11 · M12) — `#/facilities`

### 1-1. 목록

| 항목 | 내용 |
|---|---|
| 제목 · 개수 | 「공공시설 정보 관리」 · 「{n}곳」 |

| 열 | 명칭(정렬) · 유형(아이콘 + 이름, 정렬) · 도로명주소(정렬, 좌표가 없으면 「좌표 없음」 배지) · 주요 항목 · 노출 여부(토글) |

| 행 클릭 | 수정 창 |
| 삭제 | 없음 |

### 1-2. 수정 다이얼로그

| 항목 | 내용 |
|---|---|
| 제목 | 「공공시설 수정」(크기 lg), 부제 `{유형 이름} · {명칭}` |
| 항목표 선택 | 행의 `type` 으로 정한다(`aed` · `toilet` · `rest` · `shelter`). **유형은 수정 창에서 바꿀 수 없다**(유형 칸이 없다) |
| 주소 선택 | 주소 · 위도 · 경도가 함께 들어온다. AED · 대피소는 현재 명칭이 비었거나 **옛 주소에서 만든 이름과 같을 때만** 새 주소로 명칭을 다시 만든다(손으로 고친 이름은 덮지 않는다) |
| 좌표 | 주소 바로 아래 지도 칸(슬롯) |
| 저장 직전 보정 (`derive`) | AED · 대피소는 이름이 비어 있을 때만 주소에서 만든다(`facilityName`, 예: 「둔전로 42 AED」). 값이 있으면 유지 |

## 2. QR 지점 (M13 · M14) — `#/qr`

### 2-1. 목록

| 항목 | 내용 |
|---|---|
| 제목 · 개수 | 「QR 지점 관리」 · 「{n}곳」 |
| 머리 단추 | [QR 지점 등록] → 폼 |
| 필터 | 소속 구 고르개(「전체 구」 + 3개 구) → 사용 여부 고르개(「사용 여부 전체」 / 「사용」 / 「미사용」) → 검색창(「QR ID, 지점명 검색」) |
| 구 판정 | 주소(`addr`, 없으면 `dong`)에서 읽는다(`guOf`) |
| 열 | QR ID(정렬) · 지점명(정렬) · 도로명주소(없으면 `dong`, 둘 다 없으면 `-`) · 소속 골목형 상점가(없으면 「지정 안 함」) · 설치 상태(배지: 설치예정 경고 / 설치완료 성공 / 훼손 위험 / 철거 중립, 정렬) · 설치일자(없으면 `-`) · 사용 여부(토글, 정렬) |
| 줄 강조 | 설치완료인데 사용 여부가 꺼진 줄은 경고 색, 훼손은 위험 색 |
| 선택 · 일괄 | 체크박스 → [사용] · [미사용] |
| 삭제 | 없음 |
| 빈 목록 | 「조건에 맞는 지점이 없습니다.」 |

### 2-2. 등록 · 수정 다이얼로그

| 항목 | 내용 |
|---|---|
| 제목 | 「QR 지점 등록」 / 「QR 지점 수정」(크기 lg), 수정 창 부제 지점명 |
| 등록 기본값 | 설치 상태 = 설치예정, 사용 여부 = 꺼짐 |
| 항목 | 항목표 열 개 전부. 소속 상점가 선택지는 항목표의 붙박이 목록이 아니라 **지금 살아 있는 상점가**(「— 지정 안 함 —」 + 목록) |
| 주소 선택 | 주소 · 위도 · 경도가 함께 들어온다 |
| 저장 | 행 `id` 는 바꾸지 않는다(QR ID 를 고쳐도 `id` 유지). 새 행은 id 를 지어 넣지 않고 덮개가 `qr-new-NNN` 을 매긴다 |
| 저장 전 추가 검사 | 같은 QR ID 가 **다른 지점**에 이미 있으면 QR ID 칸 「이미 다른 지점에 매칭된 QR ID 입니다.」(고르는 목록이 막으므로 정상 사용에서는 걸리지 않는다) |

**폼 위 안내 상자** (해당할 때만, 위에서 아래로)

| 조건 | 문구 | 톤 |
|---|---|---|
| 등록 창이고 고를 수 있는 QR ID 가 0개 | 「사전 생성된 QR ID 50개가 모두 지점에 매칭되어 고를 수 있는 ID 가 없습니다. 새 QR ID 와 QR 이미지 생성은 개발 담당자에게 요청해 주세요.」 | 위험 |
| 설치 상태가 설치완료이고 사용 여부가 꺼짐 | 「설치는 완료되었으나 지금은 쓰지 않는 상태입니다. 운영을 시작하려면 [사용 여부]를 켜 주세요.」 | 경고 |
| 수정 창이고 소속 상점가가 비어 있음 | 「소속을 비워 두면 이 지점으로 들어온 사용자에게 가까운 골목형 상점가 3곳을 대신 안내합니다. 근처에 골목형 상점가가 없는 자리(공원 · 관공서 앞)에서는 그것이 맞는 화면입니다.」 | 중립 |

### 2-3. QR ID 고르기 (`type: "picker"`)

| 항목 | 내용 |
|---|---|
| 사전 생성 목록 | `qr-001` ~ `qr-050` (`QR_CODE_TOTAL` = 50, 목데이터가 규칙으로 만든다) |

## 3. 오류신고 (M15) — `#/reports`

시민이 만든 접수 건을 관리자가 **처리 상태 · 담당자 · 내부 메모**만 기록한다. 등록 · 삭제 · 회신이 없고, 접수 내용은 읽기 전용이다. 시드 데이터는 16건(`rp-001` ~ `rp-016`).

### 3-1. 목록

| 항목 | 내용 |
|---|---|
| 제목 · 개수 | 「오류신고 관리」 · 「{n}건」 |
| 필터 | 처리 상태(「전체 상태」 + 접수 · 확인중 · 처리완료 · 반려 · 중복) → 신고 유형(「전체 신고 유형」 + 정보 오류 · 없어진 시설 · 위치 부정확 · 추가 제안 · 기타) → 대상 유형(「전체 대상 유형」 + 공공시설 · 점포 · 상점가 · 축제 · 기타) → 검색창(「내용 검색」, 내용만 본다) |
| 기본 차례 | 상태 먼저(접수 → 확인중 → 처리완료 → 반려 → 중복), 같은 상태 안에서 접수일 최신순. 열 머리 정렬로 바꿀 수 있다 |
| 열 | 접수번호(112px, 정렬) · 접수일(124px, 정렬) · 대상 유형(100px, 정렬) · 대상(200px, 없으면 `-`) · 신고 유형(120px, 정렬) · 내용(남는 폭, 한 줄 말줄임) · 담당자(130px, 없으면 `-`, 정렬) · 상태(96px, 배지, 정렬) |
| 배지 색 | 접수 위험 · 확인중 경고 · 처리완료 성공 · 반려 / 중복 중립 |
| 선택 · 일괄 | 없음 |
| 빈 목록 | 「조건에 맞는 접수 건이 없습니다.」 |
| 미처리의 정의 | 접수 · 확인중(`OPEN_STATES`). 좌측 메뉴 배지가 이 건수를 센다 |

### 3-2. 상세(처리) 다이얼로그

| 구역 | 내용 |
|---|---|
| 제목 · 부제 | `{접수번호} · {신고 유형}` / `{접수일} 접수 · {대상 유형}` (크기 lg) |
| 접수 내용(읽기 전용 표) | 대상 · 대상 ID · 접수 지점(`qrCode`) · 신고 내용(줄바꿈 유지). 값이 없으면 `-` |
| 처리 항목 | 처리 상태(select, 기본 「접수」) · 담당자(select) · 내부 메모(textarea 3행, 최대 500자, 안내 문구 「확인 경위, 연락한 곳, 판단 근거.」) |
| 담당자 선택지 | 「— 담당자 없음 —」 + **사용 중인 계정의 이름** (계정 표에서 읽는다) |
| 하단 단추 | 왼쪽 [{가는 화면 이름}로 이동](대상 유형이 공공시설 · 점포 · 상점가 · 축제일 때만), 오른쪽 [닫기] · [저장] |
| 이동 단추 | 「공공시설 정보 관리」 · 「점포 정보 관리」 · 「골목형 상점가 정보 관리」 · 「축제 정보 관리」 화면으로 이동하며 창을 닫는다. **한 건을 곧장 열지는 않는다**(대상 유형 「기타」는 단추 없음) |

**항목표**

| 항목 | 키 / spec | 필수 | 형식 | 범위 · 검증 |
|---|---|---|---|---|
| 처리 상태 | `state` / `status` | 필수 | select | 접수 · 확인중 · 처리완료 · 반려 · 중복 |
| 담당자 | `assignee` / `assignee` | 선택 | select | 위 선택지. 저장 시 비면 `null` |
| 내부 메모 | `memo` / `internal_memo` | 조건부(처리 상태가 **처리완료 · 반려**일 때 필수) | textarea | 최대 500자. 오류 「{처리완료|반려}로 변경하려면 내부 메모를 입력해 주세요.」. 중복으로 옮길 때는 필수가 아니다. 저장 시 앞뒤 공백을 지우고 비면 `null` |

- 접수 항목(대상 유형 · 대상 ID · 신고 유형 · 내용 · 접수 지점)은 시민이 제출한 값이며 관리자 화면에서 고칠 수 없다. 내용 길이(10~500자) 검사는 이 화면에 없다.
- 저장 성공: 토스트 「{접수번호} 처리 내용을 저장했습니다.」. 이력 대상 「오류신고」.
- `fields.js` 의 `REPORT_FIELDS` 는 같은 세 항목을 정의하지만 이 화면은 그것을 쓰지 않고 위 규칙을 직접 구현한다(`REPORT_STATES` · `REPORT_TYPES` · `REPORT_TARGET_TYPES` · `REPORT_CLOSING_STATES` 상수는 사용).

## 4. 대시보드 (M02) — `#/dashboard`

**조회 전용**이다(내보내기 없음). 값의 출처: 스캔 · 길찾기 계열은 `stats.js` 의 **생성값**(결정적 시드 난수, 60일치, 서버 로그 아님), 오류신고 · 점포 · 시설 · 상점가는 덮개를 거친 현재 목록.

| 구획 | 내용 |
|---|---|
| 머리 | 제목 「대시보드」, 설명 `{기간 이름} · {시작일} ~ {종료일} · 스캔 로그 기준`, 기간 고르개(알약 탭: 오늘 · 최근 7일 · 최근 30일, **기본 최근 7일**) |
| 처리 대기 배지 | 「좌표 누락 점포」 하나 — 점포와 공공시설 중 좌표가 없는 건수 합계. **0 이면 줄 전체가 없다.** 누르면 점포 정보 관리로 이동. 「미처리 오류신고」 배지는 없다(좌측 메뉴 배지가 대신한다) |
| 요약 카드 4종 | 누적 QR 스캔(회) · `{기간} QR 스캔`(회, 증감률 「{어제\|지난 7일\|지난 30일} 대비 ±n%」, 직전 같은 기간이 0 이면 증감률 없음) · `{기간} 길찾기 실행`(회) · `{기간} 신규 오류신고`(건, 접수일이 기간 안인 신고 수) |
| 차트 | 일별 스캔 추이(막대, 높이 180, 가로 3분의 2) · 시설 유형별 조회 비중(화장실 52 · 쉼터 24 · AED 15 · 대피소 9 %, 고정값, 설명 「공공시설 탭에서 열어 본 시설의 유형」) |
| 골목형 상점가별 둘러보기 매장 | 상점가 고르개(폭 420, 줄 형식 「{구} - {상점가명} (점포 {n}곳)」, 노출 점포가 없으면 「(점포 자료 없음)」, 구 순서 → 이름 순, 기본 둔전) → 선택한 상점가의 「조회수 상위 점포」 표 |
| 조회수 상위 점포 표 | 설명 `사용자 모바일 웹 '둘러보기' 탭의 '인기 매장' {DISCOVER_PICK}곳`(`DISCOVER_PICK` = **8**). 열: 순위(1위 강조 배지) · 상호명(업종 아이콘 · 지점명 · 온누리 배지) · 상권업종대분류명(200px) · 상권업종중분류명(200px, 없으면 업종 칩 이름) · 도로명주소 · 조회수(우측 정렬). 숨김 점포는 빠지고, 뽑는 규칙은 시민 화면과 같은 함수(`discoverPicks`) |
| 점포 자료 없는 상점가 | 표 대신 정보 상자 「점포 목록이 아직 들어오지 않았습니다」: 시 안내 점포수가 있으면 「이 골목형 상점가는 시 안내 기준 점포 {n}곳이 등록되어 있으나, 점포 목록 데이터가 아직 적재되지 않았습니다.」, 없으면 「이 골목형 상점가는 점포 목록 데이터가 아직 적재되지 않았습니다.」, 이어서 「이로 인해 사용자 화면의 신규 매장 / 인기 매장 리스트가 노출되지 않습니다.」 |

대시보드에 **없는** 것: 지점별 스캔 횟수 · API 사용량 · 신규 점포 표 · 탭별 조회 비중. (`SCANS_BY_POINT` · `API_USED_TODAY` · `TAB_SHARE` · `QUOTA_DEFAULTS` 값은 데이터 파일에 남아 있으나 읽는 화면이 없다.)
