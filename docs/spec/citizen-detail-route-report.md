# 시민용 — 상세 · 길찾기 · 오류신고 · 해시 라우터 (현재 상태)

현재 코드가 기준이다. 코드에서 확인한 동작 · 규칙 · 데이터 출처 · 상태 · 예외만 적는다. 「미정」은 코드나 방향 문서가 미정으로 적은 것이다.

## 1. 해시 라우터와 오버레이

### 1-1. 경로

| 해시 | 화면 | 대상을 찾는 곳 |
|---|---|---|
| `#/` 또는 없음 | 셸 (탭 + 지도) | — |
| `#/facility/:id[/:출발지id]` | S05 시설 상세 | `FACILITIES` |
| `#/store/:id[/:출발지id]` | S06 점포 상세 | 현재 상점가(동백이음길) 점포 227 |
| `#/route/{facility\|store}/:id[/:출발지id]` | S07 길찾기 | 첫 조각(종류)으로 시설 또는 점포 목록 |
| `#/report[/{facility\|store}/:id]` | S10 오류신고 | 종류 + id. 조각이 없으면 대상 없는 폼 |
| `#/course/:id` | S08 코스 상세 | 지금 코스 4개 (`d.courses` — 이음길 함께가게 · 먹자골목 · 온누리 알뜰 · 동네 상점) |
| `#/festival/:id` | S09 축제 상세 | `FESTIVALS` |
| `#/district/:id` | 다른 상점가 안내 (S13-A) | `DISTRICTS` 32곳 |
| `#/festivals` · `#/districts` · `#/stores` | S12 · S13 · S15 목록 | 대상 없음 |

- 읽는 규칙(`parseHash`): `#/` 뒤를 `/` 로 나눈 첫 조각이 화면 이름, 나머지는 `decodeURIComponent` 한 조각 배열. 상세 이름(`facility · store · course · festival · route · district`)은 조각이 하나 이상 있어야 열리고, `report · festivals · districts · stores` 는 조각 없이도 열린다. 그 밖의 이름은 모두 셸이다.
- 대상 id 를 못 찾으면(`#/store/없는id`, `#/report/facility/없는id`) 토스트 「정보를 찾을 수 없습니다」 를 띄우고 `back()` 한다. 대상 없는 `#/report` 는 정상이다.
- 길찾기 · 신고만 조각이 둘이다(종류 + id). 상세 · 길찾기의 마지막 조각은 **코스에서 물고 온 출발지 id** 다 (`#/store/dj-042/dj-041`). 대상은 항상 첫 id 조각만 보고, 신고 해시에는 출발지를 붙이지 않는다.

### 1-2. 기록(history) 규칙

| 함수 | 하는 일 | 쓰는 곳 |
|---|---|---|
| `go(path)` | `pushState({shellDepth: 현재+1})` → 뒤로가기가 이동을 되돌린다 | 상세 · 길찾기 · 신고로 들어갈 때 |
| `replace(path)` | `replaceState`, 깊이 유지 — 기록을 쌓지 않는다 | 길찾기 출발지 바꾸기 |
| `back()` | 쌓은 기록이 있으면(`shellDepth>0`) `history.back()`, 없으면 현재 항목을 `…#/` 로 **교체**해 셸로 나간다 | 앱바 뒤로 · Esc · 대상 못 찾음 |
| `closeAll()` | 쌓은 깊이만큼 `history.go(-깊이)`, 없으면 `#/` 로 교체 | [X](길찾기 · 상점가 안내) · [상점가 둘러보기] · 목록 → 지도 이동 |

- 쌓은 깊이는 history 항목마다 `history.state.shellDepth` 에 적는다. 브라우저 뒤로가기로 돌아와도 그 항목의 값이 복원된다. 딥링크로 상세에 바로 들어오면 되돌아갈 항목이 없고, 그때 뒤로는 서비스를 떠나지 않고 셸로 교체된다.
- 이동은 `pushState` 뒤에 `popstate` 이벤트를 직접 알려 구독자가 해시를 다시 읽는다.

### 1-3. 오버레이

- 상세 · 목록 화면은 셸(`MainApp`)을 언마운트하지 않고 **루트의 마지막 자식**으로 덮는다. 그래서 탭 · 업종 칩 · 온누리 · 검색어 · 정렬 · 쪽 · 시트 스냅 · 지도 상태가 그대로 남고, 뒤로가기는 즉시다.
- `DetailPage`: 전체를 덮는 `z-modal`(600), `role=dialog aria-modal`. 열릴 때 오른쪽 16px 에서 밀려 들어오며 나타난다(200ms). 움직임 최소화 설정이면 애니메이션 없이 나타난다. 나갈 때는 애니메이션이 없다.
- 열리면 앱바의 뒤로 단추에 초점을 둔다. **Esc 로 뒤로(`onBack`)** 간다.
- 토스트(`z-toast` 700)는 오버레이 위에 뜬다.
- 코치마크와 S14 대화상자는 라우트가 셸일 때만 뜬다. 상세가 열려 있는 동안은 미루고 닫힌 뒤에 뜬다.
- 첫 화면으로 들어온 상세(`entry` = `history.state.shellDepth` 가 0 이하)에서 점포 · 축제 상세의 앱바 뒤로 단추는 `store` 아이콘 + 라벨 「홈」이 된다. 누르면 셸(상점가 탭)로 나간다.

### 1-4. 길찾기 · 신고로 가는 길 (한 곳에서만 조립한다)

- `goRoute(item)`: 시설(`item.type` 이 시설 유형)이면 `facility`, 아니면 `store`. 지금 해시가 물고 있는 출발지가 있고 도착지와 다르면 그 id 를 붙인다. 부르는 곳: 지도 미리보기 카드 [길찾기](점포 · 시설) · 시설 상세 [길찾기] · 점포 상세 [길찾기]. 코스 상세 카드의 [길찾기]는 `goRoute` 를 거치지 않고 직접 `#/route/store/{id}[/{직전 가게 id}]` 로 간다.
- 점포 상세의 하단 단추는 **들어온 길이 정한다**(2026-10-19): 상점 QR 로 막 들어온 첫 화면(`entry`)은 [상점가 둘러보기], 앱 안에서 연 상세는 [길찾기](`footprints`). 머리에는 길찾기 버튼이 없다.
- 점포 상세 머리: 상인회 정회원(`store.member`) 가게는 가게 이름 줄 오른쪽에 **「이음길 함께가게」 배지**(64px 그림, `screens/main/assets/badges/ieumgil-member.png`, alt 「이음길 함께가게 (상인회 정회원)」)가 선다(2026-10-30). 비정회원은 없다. 층(`floor`)은 아직 화면에 적지 않는다.
- 점포 상세 머리 아래: 받은 가게만 **해시태그 줄**(`store.tags`, 브랜드 색 캡션 「#문제집, 참고서 #단골 많은집 #다양한도서」)이 선다 — 지금은 동백문고 하나(`dongbaekStores.js` 의 `DONGBAEK_INTROS`). 사진을 받은 가게는 사진 줄(`store.images`)에 그 사진이 선다. 파일이 없거나 깨지면 그 칸만 자리표시로 돌아간다(`PhotoStrip`). 입력 항목 정의서 1-2 밖의 항목이라 관리자 입력 칸은 아직 없다(2026-10-30).
- `goReport(item)`: 대상이 있으면 `#/report/{facility|store}/{id}`, 없으면 `#/report`. 부르는 곳은 시설 상세 · 점포 상세 · 길찾기의 [경로 오류 신고]다. 축제 · 코스 · 상점가 화면에는 신고 단추가 없다. 대상 없는 `#/report` 는 화면 안 어디에도 링크가 없다(직접 주소로만 연다).

## 3. 시설 상세 (S05)

### 3-1. 구성 (위에서 아래)

| 순서 | 내용 |
|---|---|
| 앱바 | 제목 = 시설명, 뒤로 |
| 머리 | 유형 배지(AED · 화장실 · 쉼터 · 대피소, 색은 유형표) · 유형 아이콘 · 시설명 · 「약 {거리}, 도보 {n}분」 (`dist ≥ 1000m` 면 `약 1.4km`, 도보 분 = `max(1, round(dist/67))`) |
| 도로명주소 | `CopyField` — 복사 단추. 복사하면 토스트 「주소를 복사했습니다」, 실패하면 「복사에 실패했습니다. 주소를 길게 눌러 선택해 주세요」 |
| 유형별 항목 | `InfoList` (아래 표) |
| [정보 오류 신고] | 표 아래 작은 글자 단추 → `#/report/facility/:id` |
| 고지 | 「공공시설 정보 {YYYY.MM.} 기준」 + 119 안내 한 줄 |
| AED · 대피소만 | 붉은 한 줄 「심정지나 재난 상황이라면 119 신고가 먼저입니다.」 (쉼터 · 화장실에는 없다) |
| 하단 고정 | [길찾기] (`footprints`) → `goRoute` |

### 3-2. 유형별 항목 (순서 그대로)

| 유형 | 제목 · 주소 외 항목 | 값 형식 |
|---|---|---|
| AED | 설치 위치 | 글자 |
| 화장실 | 개방시간 · 남성용 대변기수 · 남성용 소변기수 · 여성용 대변기수 · 여성용 소변기수 · 비상벨 설치 여부 · 기저귀 교환대 · 입구 CCTV | 칸수는 「N칸」(0 도 값), 나머지 셋은 ○/×(읽어줄 때 「있음/없음」) |
| 쉼터 | 운영시간 · 이용가능 인원 · 부가정보 | 인원은 「N명」 |
| 대피소 | 실제 위치 · 최대 수용 인원 | 「약 N명」(천 단위 쉼표) |

- 선택 항목이 비어 있어도 줄을 지우지 않고 「-」(읽어줄 때 「정보 없음」)으로 남긴다. ○/× 항목이 null 이면 「-」, false 면 ×.
- 시설 데이터 필드: AED `addr · place`, 화장실 `name · addr · hours · menToilet · menUrinal · womenToilet · womenUrinal · emergencyBell · diaperTable · entranceCctv`, 쉼터 `name · addr · hours · capacity · extra`, 대피소 `addr · place · capacity`. AED · 대피소는 명칭 필드가 없어 도로명주소에서 만든다(`facilityName`: 도로명 + 건물번호 + 유형, 예 「둔전로 42 AED」).
- 시설은 22곳(AED 7 · 대피소 3 · 화장실 7 · 쉼터 5), 기준점에서 거리 · 방위로 좌표를 계산한 더미다.
- 시설 유형별 기준일(`FACILITY_AS_OF`): AED 2026.05. · 화장실 2026.04. · 쉼터 2026.06. · 대피소 2026.03.

## 4. 점포 상세 (S06)

### 4-1. 구성 (위에서 아래)

| 순서 | 내용 | 조건 |
|---|---|---|
| 앱바 | 제목 = 상호, 뒤로(첫 화면이면 「홈」) | |
| 머리 | 업종 배지(`CATEGORY_LABELS`, 없으면 「기타」) · 온누리 배지 · 업종 아이콘 · 상호 | 온누리 배지는 가맹일 때, 주소는 값이 있을 때 |
| 사진 | `PhotoStrip` 「가게 이미지」 — 점포 `images` 자료가 없어 자리표시 3장 | 항상 |
| 소속 상점가 · 주소 | 사진 밑 줄은 **없다**(2026-10-19). 가게 이름 밑에 도로명주소(`caption` · muted), 그 밑에 지도핀 아이콘 + 소속 골목형 상점가 이름(`caption` · muted)을 줄을 갈라 적는다(슬래시로 잇지 않는다) — 링크가 아니다. 상점가로 가는 길은 하단 [상점가 둘러보기] | 상점가나 주소가 있을 때 |
| 진행 중 축제 배너 | 현재 상점가의 축제 한 건(`FestivalBanner`, 조아용 excited) → `#/festival/:id` | 축제 상태가 「진행중」일 때만, **QR 로 처음 진입한 상세에서만**(셸 안쪽에서 연 상세에는 없다 — 2026-10-19) |
| 현재 가게에서 시작하는 골목 한바퀴 코스 | 점선 발자국 길(`FootprintTrail`) + 제목 + 「주변 가게들을 따라 골목의 다양한 매력을 발견해 보세요.」 + 코스 카드 가로 스크롤 → `#/course/:id`. 이 가게가 코스에 들어 있으면 카드가 그 줄을 표시한다(`currentId` — 「코스에 포함된 가게」 · 속 찬 순번 · 「현재 보고 있는 가게」) | 그 가게 둘레 코스(`coursesFrom(id)`)가 있을 때. `coursesFrom` 은 그 가게 자신을 코스에 넣지 않아 지금은 표시가 나오지 않는다 |
| [정보 오류 신고] | → `#/report/store/:id` | 항상 |
| 고지 | 「2026.03. 기준 정보로, 실제 영업 여부와 다를 수 있습니다.」 (119 없음) | |
| 하단 고정 | `entry`(상점 QR 첫 화면)이면 [상점가 둘러보기](`store` 아이콘) → 열린 오버레이를 모두 닫고 상점가 탭. 아니면 [길찾기](`footprints`) → `goRoute` 로 S07 | 항상 |
| 머리 오른쪽 | [길찾기] 작은 채움 버튼(xs primary) (`footprints` 아이콘, 상호 줄 오른쪽) → `goRoute` 로 S07 | 항상 |

- 화면에 없는 것: 정보 표(지점명 · 업종 대/소분류 · 온누리 줄) · 주소 복사 · 주변 공공시설 · 조회수.
- 어떤 길로 열어도(상점 QR · 지도 카드 · 코스 카드 · 검색) 같은 모양이다. 코스는 항상 그 가게 둘레로 만든다.
- 점포 데이터 필드: `id · name · branch · cat · bizL · biz · bizS · ksic · onnuri · dist · views · agoMonths · addr · lat · lng`. 상세는 `name · cat · onnuri · addr · images` 만 읽는다. 나머지는 목록 한 줄(`biz`) · 검색(`name`, `biz`) · 정렬(`views`, `dist`) · 데이터 보존용이다.

## 5. 길찾기 (S07)

### 5-1. 출발지 · 도착지

| 항목 | 규칙 |
|---|---|
| 도착지 | 해시의 종류 + id 로 찾은 시설 또는 점포 |
| 출발지 기본값 | 기준점(`ANCHOR`: 화면의 「내 위치」는 언제나 QR 지점이며 GPS 를 쓰지 않는다) |
| 코스에서 들어온 경우 | 해시 마지막 조각의 가게 id 가 출발지다 (코스 순서상 직전 가게). 없는 id 면 조용히 기준점으로 돌아간다 |
| 바꿀 수 있는 후보 | 기준점 + **도착지가 든 코스**(없으면 지금 출발지가 든 코스)의 다른 지점들. 후보가 기준점 하나뿐이면 드롭다운을 그리지 않는다 |
| 바꾸기 | 출발 줄 글자 옆 「바꾸기」(`InlineSelect`). 고르면 해시 마지막 조각을 `replace` 로 갈아 끼운다(기록이 쌓이지 않는다). 기준점을 고르면 조각을 뺀다 |
| 임의 주소 검색 | 없다 |

### 5-2. 구성 (위에서 아래)

| 순서 | 내용 |
|---|---|
| 앱바 | 제목 「길찾기」, 뒤로(한 칸), 오른쪽 [X] 「지도로 나가기」(`closeAll`) |
| 경로 지도 | 비율 4:3, 높이 최대 46vh, 레벨 3. 셸 지도와 별개 인스턴스. 경로 전체에 맞춰(`fitTo`, 위아래 24px) 열린다. 지도의 도착 핀을 누르면 도착지 상세(`#/{종류}/{id}`)로 간다(출발지를 물려준다) |
| 출발 → 도착 | 왼쪽 기둥(출발 점 · 선 · 도착 핀). 「출발 · QR 스캔 지점」(코스에서 왔으면 「출발 · 코스 안의 가게」) + 이름. 「도착」 + 유형 아이콘 · 이름 · 온누리 배지 + 「{유형 또는 업종} · {주소}」 |
| 총계 배지 | 성공: 「도보 {분}분」 · 「약 {거리}」. 폴백: 「경로 안내 없음」 · 「직선 약 {거리}」 · 「{방위}쪽 방향」 |
| 상세 경로 안내 | 성공일 때만. 단계 목록(아래), 누르면 지도가 그 지점으로 가고 지도의 꺾임 점을 눌러도 같은 단계가 켜진다 |
| [경로 오류 신고] | 작은 글자 단추 → `#/report/{종류}/{id}` (도착지가 대상) |
| 고지 | 기준일: 시설 「공공시설 정보 {YYYY.MM.} 기준」 / 점포 「점포 정보 2026.03. 기준」. 본문: 성공일 때 「거리는 실제 보행 경로 기준이며, 도보 시간은 상황에 따라 달라질 수 있습니다. 」 + 점포면 「안내 정보는 참고용입니다.」. 119 문장은 도착지가 시설일 때만 |
| 하단 고정 | 폴백일 때만 [다시 시도] |

### 5-3. 상태

| 상태 | 화면 |
|---|---|
| 로딩 | `EmptyState`(조아용 curious) 「도보 경로를 찾고 있어요」 / 「{출발지}부터 {도착지}까지」. 경로 응답을 기다리는 동안. 화면을 떠난 뒤 온 응답은 버린다 |
| 성공 | 위 구성. 지도: 흰 밑선(10px) + 파란 본선(6px), 꺾임 점(14px), 도착 핀 |
| 폴백 | `Notice(warning)` 「도보 경로를 불러오지 못했습니다」 / 「지금은 상세 경로를 안내드릴 수 없어 방향과 직선거리만 알려드립니다. {출발지}에서 {방위}쪽으로 약 {거리} 거리입니다. 지도의 회색 점선은 실제 걷는 길이 아니라 두 지점을 곧게 이은 선입니다.」 + 사유(`reason`)가 있으면 「사유: …」. 단계 목록은 만들지 않고 지도에는 회색 점선만 긋는다. 하단 [다시 시도] → 경로를 다시 요청 |

- 경로가 예시(`sample`)인지 실 응답(`api`)인지는 화면에 구분해 적지 않는다.
- 단계 한 줄(`routeStepText`): 출발 「출발」 · 직진 「100m 직진」 · 회전 「50m 앞에서 좌회전」 · 도착 「30m 앞 도착」(거리가 0 이면 동작만). 종류 7개: 출발 · 직진 · 좌회전 · 우회전 · 왼쪽 방향 · 오른쪽 방향 · 도착. 둘째 줄은 길 이름(도착은 도착지 이름).
- 거리 표기: 1000m 이상이면 `x.x km`, 그 미만 `m`. 도보 분은 `max(1, round(초/60))`.

## 6. 경로 제공자 (`walkRoute.js` · `config.js`)

### 6-1. 규칙

- 화면은 `requestWalkRoute(origin, dest)` 하나만 부른다. 항상 결과를 돌려주며 실패하지 않는다(실패는 폴백으로 돌려준다).
- 돌려주는 값: `{ source, distance(m), duration(초), path[], steps[], straight, reason?, compass? }`. `source` = `api`(실 응답) · `sample`(예시) · `fallback`(직선 안내).
- 카카오가 공개한 길찾기 REST API 는 자동차 경로이고 도보 공개 API 는 없다. 어느 제공자를 쓰든(카카오 협의 · TMAP 보행자 경로) REST 키를 보관할 **서버 프록시**를 거쳐야 한다. 제공자 선택은 「미정」이다.
- 전환: `config.js` 의 `WALK_ROUTE_ENDPOINT` 에 프록시 주소를 넣으면 실 응답을 쓴다. 현재 값은 빈 문자열이라 **예시 경로**가 쓰인다. 화면 코드는 바뀌지 않는다.

### 6-2. 흐름

1. 출발 · 도착 좌표가 없으면 즉시 폴백(`reason` 「좌표 없음」).
2. 검수 스위치(`?route=fallback|sample|api`): `fallback` 이면 항상 폴백.
3. 캐시 조회: 키 = 출발 · 도착 좌표를 소수점 5자리로 끊은 문자열. 메모리 + `sessionStorage`(`yongin.walkroute.v1`). 맞으면 그대로 돌려준다.
4. 실 API 를 쓰는 조건: `?route=api` 이거나(`?route=sample` 이 아니고 엔드포인트가 있을 때). 그때:
   - 오늘 사용량이 한도(`WALK_ROUTE_QUOTA` = 1000) 이상이면 폴백(「오늘 경로 안내 한도를 넘었습니다」).
   - 호출 전에 사용량을 1 올린다(`localStorage` `yongin.walkroute.quota` `{date, used}`, 날짜는 UTC `YYYY-MM-DD` 기준, 날짜가 바뀌면 0). 응답이 실패해도 한 건으로 센다.
   - 요청: `{ENDPOINT}?origin={lng},{lat}&destination={lng},{lat}&priority=RECOMMEND`, 응답 대기 한계 6초(`WALK_ROUTE_TIMEOUT`).
   - 성공하면 캐시에 쓰고 돌려준다. 실패(시간 초과 · 429 · 그 밖 오류 코드 · 응답 형식 오류)는 모두 폴백이며 `reason` 에 「경로 서버 응답이 늦습니다」 · 「경로 호출 한도를 넘었습니다」 · 「경로 서버 응답 {코드}」 · 오류 문구를 담는다. **엔드포인트가 있는데 예시 경로로 대신하지 않는다.**
5. 예시 경로: 엔드포인트가 없거나 `?route=sample` 일 때. 검수용으로 일부러 `SAMPLE_ROUTE_DELAY`(320ms) 늦춘 뒤 만들고 캐시에 쓴다. 연동 시 0 으로 두는 값이다.

### 6-3. 실 응답 변환 (`normalize`)

- 형식은 카카오모빌리티 길찾기 응답을 가정한다: `routes[0].summary.{distance, duration}` · `sections[].roads[].vertexes`(`[경도, 위도, …]`, 경도가 먼저) · `sections[].guides[]`(`x, y, distance, type, name`). `result_code` 가 0 이 아니면 오류로 본다. 경로 점이 2개 미만이어도 오류다.
- 안내 코드 → 7종 변환표: 1 직진 · 2 좌 · 3 우 · 5 왼쪽 방향 · 6 오른쪽 방향 · 100 도착 · 101 출발. 표에 없는 코드는 직진이다. 제공자 문서로 반드시 검증해야 한다는 주석이 코드에 있다 — 검증은 「미정」이다.
- 단계의 거리는 직전 안내 지점에서 그 지점까지의 거리다.

### 6-4. 예시 경로 생성

- 결정적이다: 씨앗이 도착지 좌표에서 나오므로 같은 도착지는 새로고침해도 같은 경로가 나온다.
- 도로 축을 북북동 24° 로 기울인 격자로 보고, 두 축을 번갈아 타는 계단식 경로를 만든다. 꺾는 횟수는 직선거리 260m 미만 1회 · 700m 미만 2회 · 그 이상 3회. 마지막 점은 도착 좌표에 정확히 맞춘다. 구간이 240m 를 넘으면 중간 직진 단계를 하나 넣는다. 길 이름은 두 축에 서로 다른 이름 묶음에서 구간마다 정한다. 회전 종류는 방위차 12° 미만 직진 · 40° 미만 약한 회전(왼쪽/오른쪽 방향) · 그 이상 좌/우회전이다.
- 도보 시간 = 거리 / 67m 분(`WALK_M_PER_MIN`).

### 6-5. 폴백

- 직선거리 + 8방위(북 · 북동 · 동 · 남동 · 남 · 남서 · 서 · 북서)만 말한다. 단계 목록은 만들지 않고 지도에는 출발-도착 직선을 점선(`straight: true`)으로 긋는다.

### 6-6. 설정 값 (`config.js`)

| 상수 | 값 | 뜻 |
|---|---|---|
| `WALK_ROUTE_ENDPOINT` | `""` | 서버 프록시 주소. 비어 있으면 예시 경로 |
| `WALK_ROUTE_QUOTA` | 1000 | 기기별 1일 호출 한도(1차 방어선). 진짜 한도 관리는 서버 몫 |
| `WALK_ROUTE_TIMEOUT` | 6000 ms | 응답 대기 한계 |
| `SAMPLE_ROUTE_DELAY` | 320 ms | 예시 경로 지연(검수용) |
| `WALK_M_PER_MIN` | 67 | 도보 속도(m/분) |

## 7. 오류신고 (S10)

### 7-1. 폼 (`#/report[/{종류}/{id}]`)

| 항목 | 규칙 |
|---|---|
| 앱바 | 제목 「정보 오류 신고」, 뒤로 |
| 대상 | 대상이 있으면 읽기 전용 카드(유형 아이콘 · 「신고 대상」 · 이름 · 주소 또는 위치). 대상이 없으면 `Notice(info)` 「대상이 지정되지 않았습니다」 + 선택 입력 「대상 이름」(「아는 만큼만 적어 주세요 (선택)」) |
| 유형 | 라디오 5개, 필수, 한 개 선택 |
| 자세한 내용 | `Textarea` 5줄, 필수, 최대 500자, 최소 10자(`trim` 기준) |
| 하단 고정 | [신고 접수] |
| 안내 | 「접수된 내용은 안내 정보를 수정하는 데 활용됩니다. 개별 답변은 어려운 점 양해 부탁드립니다.」 |

- 유형 5개(`REPORT_KINDS`): 위치가 실제와 다릅니다 · 운영시간, 휴무 정보가 다릅니다 · 폐업, 철거되어 지금은 없습니다 · 이름, 연락처 등 표기가 다릅니다 · 그 밖의 오류나 문의.
- 회신처 · 연락처 · 개인정보 동의 칸이 없다. 119 안내도 없다.
- 검증은 [신고 접수]를 누를 때 한 번 한다. 규칙: 유형 미선택 「어떤 오류인지 골라 주세요.」 / 내용 10자 미만 「무엇이 어떻게 다른지 10자 이상 적어 주세요.」 첫 오류 칸으로 초점과 스크롤이 가고 `aria-live` 로 「입력하지 않은 항목이 N개 있습니다.」 를 알린다. 첫 제출 시도 이후에는 고칠 때마다 즉시 갱신된다.
- 통과하면 단추가 「접수 중…」(비활성)이 되고 입력을 올려보낸다 — `{ kind, kindLabel, body(trim), target: { id, name, type } }` (대상 없으면 `{id: null, name: 입력값 또는 null, type: null}`).

### 7-2. 접수 (서버 없음)

- 셸의 `submitReport` 가 420ms 뒤 접수번호를 붙여 결과를 돌려준다. 입력은 어디에도 저장 · 전송되지 않는다.
- 접수번호 형식 `YG-{YYMMDD}-{0000~9999 무작위 4자리}`.
- 신고 화면을 벗어나면 접수 결과를 비운다 — 다시 열면 빈 폼이다.

### 7-3. 접수 완료 화면

「신고 접수 완료」 앱바 · `EmptyState`(조아용 thanks) 「접수되었습니다」 / 「보내주신 내용은 담당 부서 확인을 거쳐 반영됩니다.」 · 접수번호 박스 · 정보 표(대상 · 유형) · 「개별 회신은 드리지 않습니다. 확인된 내용은 안내 정보에 바로 반영됩니다.」 · 하단 [닫기](뒤로).

| 대상 없는 신고 | 이름 입력 칸이 열린다(선택) |

## 9. 미정 · 한계

- 도보 경로 제공자와 서버 프록시 주소: 미정(`WALK_ROUTE_ENDPOINT` 가 빈 값). 안내 코드 변환표 검증도 미정.
- 오류신고 서버 연동: 없음(접수번호는 화면이 만든다). 신고가 관리자에 전달되는 길이 시민용에는 없다.
- 점포 상세의 홍보 정보 구성: 미정 (`direction_v2_rules.md` 8장). 지금은 사진 자리표시 · 소속 상점가 · 축제 배너 · 코스 추천뿐이다.
- 점포 · 축제 사진 자료(`images`): 없음. 자리표시만 그린다.
- 문의처(`CONTACT`)는 자리표시 값이다(S11 이 쓴다).
