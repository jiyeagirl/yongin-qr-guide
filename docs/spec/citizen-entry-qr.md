## 1. 진입 순서

| 단계 | 동작 | 코드 |
|---|---|---|
| 1 | URL 에서 QR 코드와 검수 플래그를 읽는다 | `readQrCode`, `readReviewFlags` |
| 2 | S01 로딩(`QrEntry`)이 `lookup(code)` 로 조회한다 | `QrEntry` |
| 3 | 결과 `status` 에 따라 갈린다 (아래 표) | `App.onResolved` |
| 4 | `status=ok` 이고 `?coupon` 플래그가 있으면 셸보다 먼저 쿠폰 흐름 | `App` |
| 5 | 셸(`MainApp`)을 세운다. 이후 `App` 은 관여하지 않는다 | `App` |

| status | 의미 | 화면 |
|---|---|---|
| `ok` | 활성 지점 | 셸 (첫 탭 = 상점가) |
| `unknown` | 표에 없는 코드 | S11 |
| `inactive` | 비활성 + 설치 상태가 `훼손` 또는 `철거` | S11 |
| `pending` | 비활성 + 그 밖의 설치 상태(설치예정 · 설치완료) | S11-A |
| `error` | 조회 자체가 실패(`lookup` reject) | S11-B |

- 셸이 서기 전에 갈린다. 비정상 코드는 지도 SDK 를 받지 않는다.
- `active` 를 먼저 본다. 활성이면 설치 상태와 무관하게 `ok`.
- `[다시 시도]`(S11-B)는 `QrEntry` 를 새 `key` 로 다시 세워 조회를 처음부터 건다.
- **축제 QR(`kind: festival`, qr-004)로 들어오면 셸 위에 쿠폰 팝업이 덮인다** (`FestivalCoupon`, A안 — 2026-10-19). 가운데 직사각형 + 어두운 막, 아래 [오늘 하루 보지 않기 | 닫기]. [쿠폰 받기] → 상인에게 보이는 쿠폰(C2, 전체화면, 오른쪽 위 [X] 로 셸에 나간다, 단추 「상인 확인」, 아래 안내 「※ 상인 전용 버튼입니다. 버튼을 누르면 쿠폰 사용이 완료되어 재사용할 수 없으니, 결제 시에만 눌러 주세요.」는 붉고 굵게) → 확인 완료(C3, 하단 버튼은 상세 화면과 같은 [상점가 둘러보기] — 눌러 축제 상세를 걷어내고 상점가 탭에 선다). 이미 받았으면 [받은 쿠폰 보기](오늘 하루 보지 않기 없음), 이미 썼으면 뜨지 않는다. 저장은 `localStorage`, 검수로 지우려면 `?qr=qr-004&popup=reset` 으로 연다(열 때마다 기록을 지우고 처음부터). `?coupon` · `?pamphlet` 진입에서는 뜨지 않는다.
- **축제 상세(S09) 머리의 축제명과 같은 행 오른쪽 끝의 [쿠폰]**(쿠폰이 걸린 축제 `ft-dunjeon` 에서만, 2026-10-19)이 같은 쿠폰을 다시 연다: 받기 전 → 받기 팝업, 받은 뒤 → 쿠폰 화면, 쓴 뒤 → 확인 완료(단추 글자 「사용완료」). 팝업을 닫거나 [X] 로 나가도 되돌아올 길이다. 둘은 `openCoupon()` / `COUPON_CHANGE` 이벤트로 잇는다(`FestivalCoupon` 은 언제나 서 있고 축제 QR 이면 스스로 열린다).
- 쿠폰 흐름은 `ok` 이후에만 선다. `?coupon=1&qr=<없는코드>` 는 S11 이 먼저다.

### 1-1. 주소에서 코드 읽기

| 형태 | 규칙 |
|---|---|
| `/s/{code}` | 경로 정규식 `\/s\/([^/?#]+)` — `decodeURIComponent` |
| `?qr={code}` | 앞뒤 공백 제거 |
| 둘 다 없음 | 기본 `qr-001` (오류 화면 없음) |
| 해시 `#/…` | 상세 오버레이용. QR 읽기에 쓰지 않는다 |

### 1-2. S01 로딩 (`QrEntry`)

| 항목 | 값 |
|---|---|
| 조회 지연 | `QR_LOOKUP_MS` = 260ms (검수용 상수) |
| 단계 문구 | 0 「QR 지점을 확인하고 있습니다」 / 1(220ms 후) 「주변 공공시설을 불러오는 중」 / 2 「잠시만 기다려 주세요」 |
| 지점명 | 조회 결과에 지점이 있으면 알약으로 표시 |
| 결과 전달 | `ok` 는 420ms 후, 그 밖은 220ms 후 `onResolved` |
| 실패 | 대기 없이 `{status:"error"}` 전달. 판단은 하지 않는다 |
| 고정 문구 | 「용인시 위치안내」 / 「공공시설 · 골목형 상점가」 |

| code | active | 이름 | kind | 연결 | 설치 상태 | 결과 |
|---|---|---|---|---|---|---|
| `qr-001` | true | 우리의류 (`ANCHOR.name`) | `store` | `storeId: dj-163`, `districtId: dunjeon` | 설치완료 | ok — 상점 상세 먼저 |

| `qr-003` | false | 둔전 시장 서편 출입구 | — | `districtId: dunjeon` | 설치완료 | S11-A |
| `qr-004` | true | 둔전 골목축제 안내 팜플렛 | `festival` | `festivalId: ft-dunjeon`, `anchorName: 둔전 골목형 상점가 중심 거리`, `bannerLabel: 둔전 골목형 상점가 기준 안내`, `bannerPlace: 축제 QR`(띠 뒤쪽 굵은 글자), `basisLabel: 둔전 골목형 상점가 기준 직선거리 · 가까운 순`, `backLabel: 상점가 중심으로` | 설치완료 | ok — 축제 상세 먼저 |

- `bannerLabel`·`basisLabel`·`backLabel` 은 팜플렛 사용자가 스캔 지점을 모르므로 상단 띠 · 공공시설 시트 기준 문구 · 지도 위 복귀 버튼(아이콘은 map-pin)을 상점가 말로 적는 선택 항목이다. 없는 코드는 「QR 스캔 지점」 문구 그대로다.
- 항목: `code · active · name · lat · lng · dong · addr · kind · storeId/festivalId · districtId · installStatus · installedAt · locationDetail · memo · replacedBy · anchorName`. 시민 화면이 읽는 것은 `status` 판정에 쓰는 `active`·`installStatus`, 진입에 쓰는 `kind`·`storeId`·`festivalId`, 기준점 이름에 쓰는 `anchorName` 이다. 나머지는 관리자용 항목이다.
- `qr-004` 에는 `addr` 가 없다. 좌표는 `districtAnchor("dunjeon")` — `DISTRICTS` 의 소속 상점가 `lat/lng` 를 읽는다.
- 셸의 기준점(컨텍스트 바 이름 · 거리 기준 · 길찾기 출발지)은 지점의 `lat/lng/name` 이 아니라 `DUNJEON.anchor`(`ANCHOR`: 우리의류, 37.28874 / 127.19931)다. `qr.anchorName` 이 있으면 이름만 덮는다 (`MainApp`).
- 더미 점포 · 시설 · 거리는 모두 `ANCHOR` 한 점 기준이다. 셸을 세우는 코드는 `qr-001`, `qr-004` 둘이다.
- 종류(kind) 이름 · 칸 구성은 「미정」(`direction_v2_rules.md` 3-3).

## 3. 첫 화면 결정 (QR 종류별)

`App.onResolved` 가 `status=ok` 일 때 아래 조건이 모두 맞으면 해시를 갈아 끼운다(`history.replaceState`, 기록을 쌓지 않음, `shellDepth: 0`).

- 조건: 지점이 있고 · 주소에 이미 해시가 없고 · `?pamphlet` 플래그가 없다.

| kind | 설정되는 해시 | 첫 화면 |
|---|---|---|
| `store` + `storeId` | `#/store/{storeId}` | 점포 상세 (S06) |
| `festival` + `festivalId` | `#/festival/{festivalId}` | 축제 상세 (S09) — S14 대화상자는 거치지 않는다 |
| 그 밖 | 없음 | 셸(상점가 탭) |

- 상세를 닫으면(`back`) 쌓인 기록이 없으므로 현재 항목을 `#/` 로 교체해 셸로 나간다. 서비스 밖으로 나가지 않는다.
- 사람이 해시를 달고 들어온 딥링크는 건드리지 않는다.
- 상점 QR 로 들어오면 코스는 그 가게 둘레로 만든다 (`coursesFrom(storeId)`, 그 가게는 코스에서 제외).
- 셸의 첫 탭은 `district`(상점가) 고정이다. 탭바 순서는 공공시설 · 상점가 · 둘러보기.

### 3-1. 해시 라우트 (`router.js`)

| 해시 | 화면 |
|---|---|
| `#/` 또는 없음 | 셸 |
| `#/facility/:id` | S05 시설 상세 |
| `#/store/:id[/:출발지id]` | S06 점포 상세 |
| `#/course/:id` | S08 코스 상세 |
| `#/festival/:id` | S09 축제 상세 |
| `#/route/{facility\|store}/:id[/:출발지id]` | S07 길찾기 |
| `#/district/:id` | S13-A 다른 상점가 안내 |
| `#/report[/{facility\|store}/:id]` | S10 오류신고 (대상 없이도 열림) |
| `#/festivals` · `#/districts` · `#/stores` | S12 · S13 · S15 (대상 없이 열림) |
| 그 밖 · 대상이 없는 id | 셸로 복귀. 대상 id 를 못 찾으면 토스트 「정보를 찾을 수 없습니다」 후 `back` |

## 4. S11 / S11-A / S11-B (`EntryFallback`)

하나의 컴포넌트이고 문구 · 조아용 표정 · 단추만 갈린다. 상단은 앱바 「용인시 위치안내」(뒤로가기 없음).

| 화면 | status | 조아용 | 제목 | 본문 | 단추 | 문의처 |
|---|---|---|---|---|---|---|
| S11 | `unknown` | curious | 등록되지 않은 QR 코드입니다 | 용인시의 QR이 아니거나, / 코드가 손상되었을 수 있습니다. / 다른 QR을 찍어주세요. | 없음 | 표시 |
| S11 | `inactive` | sorry | 안내를 불러올 수 없는 QR 코드입니다 | 코드가 손상되었거나, 지금은 쓰지 않는 QR 코드일 수 있습니다. / 다른 QR을 찍어주세요. | 없음 | 표시 |
| S11-A | `pending` | shy | 아직 준비 중인 QR 코드입니다 | 준비가 끝나면 해당 QR코드로 주변 공공시설과 상점가를 안내합니다. | 없음 | 표시 |
| S11-B | `error` | sorry | 정보를 불러오지 못했습니다 | 인터넷 연결이 불안정한 것 같습니다. / 연결을 확인한 뒤 다시 시도해 주세요. | [다시 시도] | 없음 |

- 문의처 문구: 「문의 : {CONTACT.dept}, {CONTACT.tel}」. 값은 `config.js` 의 `CONTACT`(자리표시 값 — 부서 「용인시 담당부서 0000」, 전화 「031-000-0000」). `tel:` 링크가 아니다.
- 알 수 없는 status 는 `unknown` 문구로 떨어진다.
- 찍은 코드 문자열 · 지점명은 화면에 쓰지 않는다 (`App` 이 `status` 와 `onRetry` 만 넘긴다).
- 번호를 가르는 기준: 다른 QR 을 찍는다(S11) / 그 자리에서 나중에 다시 찍는다(S11-A) / 지금 다시 시도한다(S11-B).

## 5. 검수 플래그

| 플래그 | 효과 | 읽는 곳 |
|---|---|---|
| `?qr=<code>` | 코드 지정 (`qr-001`~`qr-004`, 그 밖은 S11) | `readQrCode` |
| `?net=fail` | **첫 조회만** 통신 오류로 실패 → S11-B. 모듈 변수 `netFailed` 로 기억 (새로고침하면 다시 실패) | `lookup` |
| `?district=none` | 현재 상점가 없음 → 상점가 탭이 S03-E 로, 코치마크 둘째 걸음 제외 | `MainApp` `noDistrict` |
| `?coach=1` | 코치마크를 연다 (**유일한 입구** — 첫 진입에서 자동으로 뜨지 않는다, 2026-10-19). 닫아도 기억하지 않는다 | `useCoachMarks(force)` |
| `?pamphlet=<축제 id>` | S14 대화상자를 연다 (아래 6장). 이 플래그가 있으면 3장의 해시 갈아 끼우기를 하지 않는다 | `MainApp` |
| `?coupon=1` | 쿠폰 흐름을 셸 앞에 세운다 (저장된 상태가 있으면 그 자리에서 이어감) | `App` |
| `?coupon=reset` | 쿠폰 저장 상태를 지우고 처음부터 | `CouponFlow` |
| `&plan=b` | 쿠폰 B안(간편 가입 후 발급). 그 밖은 A안 | `couponPlan` |

- `?pamphlet` 검수값: `ft-everland` = 종료, `ft-namsa` = 예정, `ft-dunjeon` = 진행중 (`TODAY` = `2026-10-17` 기준, `config.js`).
- 이 플래그들은 서버가 없는 시연용이다. 실서비스에서는 제거하고 서버 값을 쓴다.

## 6. S14 축제 팜플렛 진입 안내 (예비 화면)

- 열리는 길은 `?pamphlet=<축제 id>` 플래그뿐이다. `qr-004`(`kind: festival`)는 이 대화상자를 열지 않고 축제 상세로 간다.
- 도입 여부는 확정되지 않았다 (`screens/README.md` 의 「예비 화면」 표기).
- 조건: `pamphletOpen` 이고 대상 축제가 `FESTIVALS` 에 있고 현재 라우트가 셸(`main`)일 때. 열림 상태는 이번 진입 안에서만 산다 — 어느 단추를 눌러도 닫히고, 축제 상세를 보고 돌아와도 다시 뜨지 않는다. `localStorage` 에 기록하지 않는다.
- 구성: 조아용 · 제목 · 기간 줄(`festival.date`) · 단추 둘. [×] 없음. Esc(`onDismiss`)는 [주변 안내보기]와 같다.

| 축제 상태 | 조아용 | 제목 |
|---|---|---|
| 진행중 | excited | 「{축제명}이 열리고 있어요!」 |
| 예정 | curious | 「{축제명}이 열릴 예정이에요」 |
| 종료 | front | 「{축제명}은 지난 축제예요」 |

- 축제명은 `short` 가 아니라 `name`. 조사는 `josa`(`i`, `eun`)로 붙인다. 상태 값이 표에 없으면 진행중 문구를 쓴다.
- 단추 순서는 세 상태 모두 [축제 정보보기](닫고 `#/festival/{id}`) → [주변 안내보기](닫기만 — 셸의 현재 탭인 상점가 탭에 선다).

## 7. 축제 쿠폰 흐름 (`CouponFlow`) — A안 / B안 미정

- 셸 앞에 서는 예외 화면. 진입 플래그는 `?coupon` 뿐이며, QR 지점 표에는 쿠폰용 지점이 없다 (쿠폰 QR 위치 「미정」).
- A안(가입 없이) · B안(간편 가입 후 발급) 확정은 「미정」. 개인정보 동의 문구는 구현되어 있지 않다.
- 쿠폰 내용은 협의 중인 예시값이며 `COUPON` 한 곳에서만 받는다.

| 항목 | 값 |
|---|---|
| id | `festival-1107` |
| 머리 배지 | 11월 7일 단 하루! |
| 이름 | 골목 축제 할인 쿠폰 |
| 혜택 | 1,000원 할인 |
| 요약 | 2만 원 이상 결제 시, 11.7(토) 당일 한정 |
| 조건 | 2만 원 이상 결제 시 사용 가능 / 11월 7일(토) 축제 당일에만 사용 가능 / 참여 점포에서만 사용 가능 / 결제 1회당 1장 사용 |

| 화면 | 내용 | 단추 |
|---|---|---|
| C1 안내 | 「골목 축제에 오신 걸 환영해요」 · 혜택 · 조건 4줄 · 하단 안내(A: 「가입 없이 바로 사용할 수 있어요」 / B: 「아이디와 비밀번호만으로 간단하게 가입해요」) | [쿠폰 받기] · [다음에 받을게요](= 셸 진입) |
| 가입/로그인 (B안만) | 아이디 · 비밀번호(· 확인). 모드 전환 「이미 가입했어요 · 로그인」 / 「처음이에요 · 가입하기」 | [가입하고 쿠폰 받기] / [로그인] · [이전으로] |
| C2 쿠폰 | 「계산할 때 이 화면을 상인분께 보여주세요」 · 쿠폰 카드 | [확인하기 (상인 전용)] |
| C3 확인 완료 | 「쿠폰이 확인되었어요」 · 이름 · 혜택 | [상점가 둘러보기](= 셸 진입) |

- 상태 저장: `localStorage`. A안 키 `yongin.coupon.festival-1107`, B안 계정별 `….u.{id}`. 값 `issued`(C2) / `used`(C3). 저장이 막히면 저장하지 않고 이번 화면 안에서만 유지한다.
- 다시 찍으면 받은 자리로 돌아온다: `used` → C3, `issued` → C2, 없음 → C1. B안은 로그인된 계정이 있을 때만 그렇다 (없으면 C1).
- B안 계정: `yongin.coupon.accounts`(아이디 → 해시), `yongin.coupon.session`(로그인 아이디). 해시는 보안이 아니다(시연용). 아이디 규칙 `^[a-z0-9]{4,12}$`, 비밀번호 6자 이상, 가입 시 확인 일치. 오류 문구: 「영문 소문자와 숫자 4~12자로 입력해 주세요.」 「비밀번호는 6자 이상 입력해 주세요.」 「비밀번호가 서로 달라요.」 「이미 사용 중인 아이디예요.」 「아이디 또는 비밀번호가 맞지 않아요.」
- 가입을 마치면 로그인된 상태가 되고, 저장값이 없으면 `issued` 를 쓰고 C2(이미 `used` 면 C3)로 간다. 계정 하나당 쿠폰 1장.
- `?coupon=reset` 은 모든 계정 · 세션 · A안 상태를 지운다.
- 서버가 없는 시연용이다. 발급 · 사용 처리와 계정은 실서비스에서 서버 몫이다.
- 쿠폰 흐름이 끝나면 셸로 들어간다. 3장에서 설정된 해시가 이미 있으면 그 상세 오버레이가 셸 위에 뜬다.

## 8. 코치마크 (예외 화면 — `?coach=1` 로만 열린다)

**2026-10-19 첫 진입에서 자동으로 뜨는 것을 없앴다** (사용자 요청 — 첫 화면이 상세로 바뀌고 쿠폰 팝업이 서면서 필요가 줄었다). 화면과 문구는 그대로 두고 루트 `index.html` 의 「예외상황 화면」에서 `?coach=1` 로 연다.

| 항목 | 값 |
|---|---|
| 걸음 | 탭 하나에 한 걸음, 순서는 탭바(공공시설 → 상점가 → 둘러보기) |
| 상점가 없음(`?district=none`) | 둘째(상점가) 걸음을 제외 → 2걸음 |
| 걸음이 넘어갈 때 | 탭을 바꾸지 않는다 (처음 들어온 탭에 그대로) |
| 열림 조건 | `coachOpen` 이고 · S14 대화상자가 닫혀 있고 · 현재 라우트가 셸(`main`) |
| 상세 오버레이가 열려 있을 때 | 열지 않는다. 버리지 않고 셸로 돌아오면 뜬다 |

| 걸음 | 제목 | 본문 |
|---|---|---|
| 공공시설 | 내 주변 시설을 확인해요 | QR을 찍은 곳에서 가까운 AED, 대피소, 쉼터, 화장실을 알려드려요. |
| 상점가 | 이 동네 상점 찾기 | {상점가명}에 있는 상점들을 업종별로 보고, 온누리상품권 되는 곳만 골라 볼 수 있어요. (`{상점가명}` = `DISTRICT.name`, 현재 「둔전골목형상점가」) |
| 둘러보기 | 다른 상점가도 둘러봐요 | 다른 골목형 상점가들도 살펴볼 수 있어요. 상점가 축제 소식도 여기서 확인해요. |

- 밝히는 대상은 `TabBar` 가 넘기는 탭 칸(`itemRefs`)이다.
- 기억하지 않는다 (옛 `yongin.coach.v1` 기록은 쓰지 않는다). `?coach=1` 일 때만 열리고 닫아도 아무것도 적지 않는다.
- 쿠폰 흐름 · S14 보다 나중이다. 상점 QR · 축제 QR 은 상세를 닫고 셸에 선 뒤에 뜬다.
- 카드 내부 동작([이전] · [×] 등)은 디자인 시스템 `CoachMarks` 몫이며 이 문서의 근거 코드 범위 밖이다.
