# 시민용 — 더미 데이터 · 분류 규칙 · 판정 방식 · 공통 UI 정책 (현재 상태)

현재 코드가 기준이다. 코드에서 확인한 구조 · 규칙 · 수치 · 출처 · 예외만 적는다. 「미정」은 코드나 방향 문서가 미정으로 적은 것이다. 서버가 없는 시연 단계라 아래 데이터는 전부 브라우저 안의 상수이고, 실연동 때 데이터 파일을 서버 응답으로 바꾸면 화면은 그대로다.

## 2. 점포 (`dunjeon.js`)

### 2-1. 필드

| 필드 | 뜻 | 시민 화면에서 쓰는 곳 |
|---|---|---|
| `id` | `dj-001` ~ `dj-335` | 라우트 · 선택 |
| `name` | 생성한 상호 | 모든 곳 |
| `branch` | 지점명(약 12%만 값, 나머지 null) | 화면에 쓰지 않음 |
| `cat` | 화면의 업종 칩 id (7종) | 칩 필터 · 아이콘 · 배지 · 코스 규칙 |
| `bizL` / `bizS` / `ksic` | 원천 분류: 상권업종대분류명 / 소분류명 / 표준산업분류명 | 화면에 쓰지 않음 (관리자가 다룬다) |
| `biz` | 상권업종중분류명 | 목록 한 줄 · 카드 · 검색 |
| `onnuri` | 온누리 가맹 여부(true/false) | 배지 · 필터 · 핀 색 · 코스 규칙 |
| `dist` | 기준점에서의 직선거리(m, 40~620) | 정렬 · 거리 표기 · 코스 후보(300~500m) |
| `views` | 인기순 정렬용 조회수(3~113) | 인기 매장 · 인기순 정렬. 화면에 숫자로 직접 적는 곳은 인기 매장 note 뿐 |
| `agoMonths` | 등록 시점(개월 전) | 화면에 쓰지 않음 |
| `addr` | 「처인구 포곡읍 {도로명} {번호}」 | 점포 상세 · 카드 · 목록 |
| `lat` / `lng` | 좌표 | 핀 · 거리 일치(거리 → 방위 → 좌표 순으로 계산) |

- 목록 한 줄의 거리 문구: 「약 {dist}m, 도보 {n}분」, 도보 분 = `max(1, round(dist/67))` (67m/분).
- `STORES` 는 거리 오름차순으로 정렬해 내보낸다.
- 숨김 점포(`visible === false`)는 인기 매장 선정에서 제외한다. 더미에는 `visible` 키가 없다.
- `DISTRICT`(현재 상점가의 요약): 이름 「둔전골목형상점가」 · 소재지 「포곡읍 포곡로124번길 2 일원」 · 점포 335 · 온누리 139 · `topCategories`. 상점가 정보에는 기준일을 적지 않는다.

### 2-3. 칩 필터 규칙 (`storeRows`)

| 조건 | 규칙 |
|---|---|
| 업종 칩 | 여럿 고를 수 있다. 빈 선택 = 전체. 칩끼리는 **OR** (고른 칩 중 하나에 `cat` 이 속하면 남음) |
| 온누리 | 켜면 `onnuri` 인 점포만. 업종 · 검색과 **AND** |
| 검색어 | `trim` 한 값이 점포 `name` 또는 `biz` 에 **포함**되면 남음(부분 일치, 대소문자 처리 없음). 업종 · 온누리와 AND |
| 정렬 | 거리순(기본): `dist` 오름차순 / 인기순: `views` 내림차순, 같으면 `dist` 오름차순. 업종 · 온누리 · 검색과 독립(조합 가능) |
| 결과 | 지도 핀 · S15 목록이 같은 `storeRows` 를 본다. 쪽 나누기는 목록만 끊고 핀은 쪽을 따르지 않는다 |

- 목록 머리 문구: 고른 칩이 없으면 「전체 {n}곳」, 하나면 「{업종} {n}곳」, 둘 이상이면 「업종 {k}종 {n}곳」.
- 칩 · 온누리 · 정렬 · 검색어 · 쪽 번호의 상태는 셸이 든다. 조건이 바뀌면 쪽은 1 로 돌아간다.

### 2-4. 원천 분류 → 칩 산출 규칙 (`deriveChip`, 관리자 코드)

시민용에는 이 매핑 코드가 없다(더미가 `cat` 을 박은 채 만들어지고 화면은 비교만 한다). 규칙을 수행하는 유일한 코드는 관리자 폼의 `deriveChip` 이며, 점포의 대 · 중 · 소분류를 고치면 칩이 따라 바뀌고 담당자가 칩을 직접 고르면 자동 산출이 멈춘다.

| 순서 | 조건 (공백을 털어낸 대분류 `L`, 중분류 `M`, 소분류 `S`) | 칩 |
|---|---|---|
| 1 | `L === "음식"` 이고 `M` 에 비알코올 · 커피 · 음료 | 카페/디저트 |
| 2 | `L === "음식"` 이고 `M+S` 에 제과 · 빵 · 도넛 · 디저트 · 빙수 · 아이스크림 · 커피 | 카페/디저트 |
| 3 | `L === "음식"` 그 밖 | 음식 |
| 4 | `L` 에 소매 · 도매 · 유통 이고 `M+S` 에 서점 · 서적 | 여가/문화 |
| 5 | 같은 대분류에서 `M+S` 에 약국 · 의약 | 생활/편의 |
| 6 | 같은 대분류 그 밖 | 쇼핑 |
| 7 | `L` 에 수리 · 개인 · 생활서비스 / 보건 · 의료 | 생활/편의 |
| 8 | `L` 에 교육 · 학문 | 교육 |
| 9 | `L` 에 여가 · 스포츠 · 예술 | 여가/문화 |
| 10 | 나머지(부동산 · 시설관리 및 임대 · 과학 및 기술 · 숙박) | 기타 |

- 대분류 열 종이 빠짐없이 일곱 칩 중 하나로 떨어진다. 마지막 「기타」는 폴백이 아니라 규칙이다 — 어느 칩에도 걸리지 않으면 그 점포가 칩 필터에서 사라지기 때문이다.
- 칩과 원천 대분류는 1:1 이 아니다(서점: 칩 여가/문화, 대분류 소매. 약국: 칩 생활/편의, 대분류 소매).
- 더미 점포의 원천 분류표(`BIZ`): 업종(중분류)마다 `[대분류, 소분류, 표준산업분류명]`. 소분류 · 표준산업분류명이 null 인 업종이 있다(수선 · 세무 · 공방). 숙박은 둔전에 0곳이라 표에 없다. 대분류 표기는 현행(2022 이후) 표기다.

## 3. 상점가 · 구역 · 현재 상점가

### 3-1. 상점가 32곳 (`DISTRICTS`)

- 항목: `id · kind("district") · name · gu · addr · stores · onnuri · lat · lng · area(행정동) · dist · homepage · festival · zone`.
- 이름은 시 표기 그대로다(「둔전골목형상점가」처럼 붙기도 하고 「남사한숲 골목형상점가」처럼 띄기도 한다). 화면에서 띄워 적는 곳이 있다(`shortName`, `spaced`).
- 시 목록 36곳 중 골목형이 아닌 4곳(용인중앙시장 · 죽전로데오상점가시장 · 구갈상점가 · 용인어정가구단지상점가)을 뺀 32곳이다. 가르는 기준은 시 표기(이름에 「골목형」)이다. 화면에 적는 총수는 배열 길이(`DISTRICT_COUNT`)에서 뽑는다.
- 거리 `dist` = 기준점과의 직선거리(평면 근사)를 **100m 단위로 반올림**. **둔전만 좌표가 기준점**이라 거리 0 이다(시 자료의 둔전 좌표는 기준점에서 2.7km 떨어져 있어 쓰지 않는다). 둔전의 점포수 335 · 온누리 139 는 시 값(340 · 150)이 아니라 우리가 그리는 목록의 수다.
- 온누리 가맹 수 `onnuri` 가 **null 인 4곳**: 동백중심상가 · 새천년 · 행복풍덕 · 상현마실로(시 안내에 수가 없다). 0 으로 적지 않고 화면은 온누리 표기를 생략하거나 「시 안내에 수가 없습니다」(상점가 안내)로 적는다.
- `homepage`(시 누리집 안내 주소)는 데이터에 남아 있으나 어떤 화면도 그리로 보내지 않는다.
- 상점가 줄 거리 문구: 0 → 「현 위치」, 1000m 이상 → `x.x km`, 그 미만 `m`.
- 정렬: `byDistrictNear` = 거리, 같으면 이름(`localeCompare` ko). 구 칩 순서 `GU_ORDER` = 처인구 · 기흥구 · 수지구(행정 구 번호순).

### 3-2. 구(區) 판정 — 도로명주소에서 읽는다

- 상점가는 `gu` 를 데이터로 갖는다. 시설 · QR 지점은 도로명주소만 있어 `guOf(addr)` 가 주소를 공백으로 나눠 `GU_ORDER` 에 있는 토막을 찾는다(없으면 빈 문자열). 저장해 두지 않고 거를 때마다 읽는다. 시민 화면은 이 함수를 쓰지 않는다(관리자 목록용).

### 3-3. 소속 상점가 · 현재 상점가

- **시민 화면은 구역을 계산하지 않는다.** 점포의 소속은 데이터가 정한다(더미 점포 335곳이 전부 둔전). 구역 판정의 정의(도로명주소 목록 매칭)는 서버 · 관리자 쪽 일이다.
- 현재 상점가 = `CURRENT_DISTRICT_ID`(`"dunjeon"`) 상수로 `DISTRICTS` 에서 찾는다. 검수 플래그 `?district=none` 이면 `null` 이 되어 상점가 탭이 S03-E 로, 둘러보기가 축소 모드로 바뀌고 코치마크 둘째 걸음이 빠진다. **QR 지점 표의 `districtId` 는 셸이 읽지 않는다.**
- 현재 상점가의 진행 중 · 예정 축제 = `CURRENT_FESTIVAL`(종료면 null).
- 「가까운 상점가가 없다」의 임계 거리(명세 1km 권장)를 화면은 계산하지 않는다 — 판정은 QR 등록 때 정해진 값을 받는 자리인데 지금은 플래그가 대신한다.

### 3-4. 구역 면 (지도에 그리는 대략의 영역)

- 구역도(경계 좌표)가 없다. 둔전: 점포 335곳 좌표의 **볼록 껍질**. 나머지 31곳: 대표 좌표 중심의 **원**, 반지름 = `min(320, max(70, 12×√점포수))` m, 28각형. 점포수가 많을수록 크다(실제 면적이 아니다).
- 다른 상점가를 골라 지도가 넘어갔을 때만 그린다.

| 코스 | 「온누리 알뜰 한바퀴」는 가맹 여부(`onnuri`)로 후보를 거른다(업종 무관) |
| 상점가 가맹 수 | `DISTRICTS[].onnuri` 는 가맹점 **수**(숫자 또는 null). 점포의 불리언과 다른 값이고 지도 카드에서는 「온누리 N곳」, 이름 옆 배지로 쓰지 않는다 |
| 인기 매장 지름길 | 인기 매장 카드를 누르면 온누리 필터가 켜져 있고 그 점포가 비가맹일 때만 필터를 끈다 |

## 5. 공공시설 데이터 (`facilities.js`)

| 유형 | 건수 | 거리(m) | 비고 |
|---|---|---|---|
| AED | 7 | 120 · 340 · 520 · 690 · 1150 · 2340 · 3480 | 안전시설 · 핀 적색 |
| 대피소 | 3 | 1400 · 1760 · 2050 | 안전시설 · 핀 적색(더 짙음). 최근접이 1km 를 넘어 원거리 안내가 걸린다 |

- 분류 상수(`FacilityIcon`): `SAFETY` = AED · 대피소 · 쉼터, `EMERGENCY`(핀 적색) = AED · 대피소, `CONVENIENCE` = 화장실, 유형 순서 `FACILITY_TYPES` = aed · shelter · rest · toilet. 유형 아이콘: AED `heart-pulse`, 화장실 `toilet`, 쉼터 `parasol`, 대피소 `shield`.

- 이름: 화장실 · 쉼터는 `name`, AED · 대피소는 도로명주소에서 만든다(`facilityName`: 도로명 + 건물번호 + 유형, 건물번호 뒤 군더더기는 뗀다).
- 안내 반경: `RADIUS_STEPS` = 2000 · 3000 · 4000m, 기본 2000m, 하한이 2km. 반경 안 시설이 0건인 유형은 **반경을 무시하고 최근접 2건**을 되살린다(빈 결과를 만들지 않는다). 유형별 곳수는 2km 17(AED 5 · 대피소 2 · 쉼터 4 · 화장실 6), 3km 20, 4km 22.
- 「가깝다」의 선 `NEAR_ENOUGH` = 1000m(화면에 적지 않는다): 안전시설 유형(유형을 고르면 그 유형)의 최근접이 이 선을 넘으면 원거리 안내가 뜬다.
- 시설 유형별 기준일 `FACILITY_AS_OF`: AED 2026.05. · 화장실 2026.04. · 쉼터 2026.06. · 대피소 2026.03. 점포 정보 기준일 `STORE_AS_OF` = 2026.03.

### 9-1. 글자 · 접근성

| 항목 | 규칙 |

| 위치정보 | 사용자 GPS 를 쓰지 않는다 (코드에 위치 요청이 없다). 화면의 「내 위치」는 언제나 QR 지점(기준점)이다 |

### 9-3. 구현 규칙

- 시민용 화면은 `design-systems/index.js` 에서만 컴포넌트 · 토큰을 가져온다(관리자는 `admin.js`).
- 화면 코드가 스타일을 직접 만들지 않고 디자인 시스템 컴포넌트 · 토큰을 쓴다. 화면 사이의 겹침(z-index)은 `layers.css` 의 값으로 말한다(한 부품 안에서 제 것끼리 앞뒤를 가리는 작은 수는 예외).
- 서버가 해야 할 일(QR 조회 · 접수번호 · 쿠폰 발급 · 경로 호출)을 화면이 흉내 내는 곳은 코드 머리말에 그 사실을 적는다.
- 상태 화면을 새로 만들면 저장소 루트 `index.html` 의 예외상황 목록에 한 줄을 더한다 (방향 문서 규칙).

## 11. 미정 · 한계

- 코스: 시민용은 자동 생성 더미. 실서비스의 큐레이션 응답 형식은 서버 쪽이다.
- 점포 · 시설 · 축제의 사진 자료(`images`)는 없다. 자리표시만 그린다.
- 점포의 인기순 값(`views`)은 더미 조회수다. 실서비스에서는 서버 집계값이다.
- 칩별 점포 수 7개는 재배분한 값이다. 실데이터가 들어오면 다시 세어진다.
- QR 지점별 기준점 · 소속 상점가를 셸이 어떻게 받을지는 미정이다(지금은 `ANCHOR` 와 `CURRENT_DISTRICT_ID` 고정).
- 도심 지점의 시설 유형별 건수 상한은 실데이터 규모를 본 뒤 정한다 — 미정.
- 도보 경로 제공자 · 서버 프록시 · 문의처 실제 값은 미정(자리표시).
