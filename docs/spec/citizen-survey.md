# 사용자 만족도 조사 (시민용)

방향은 `docs/direction_v2_rules.md` 13장. 코드: 판정·저장 `screens/main/data/survey.js`, 카드 `design-systems/components/feedback/SurveyPrompt.jsx`,
띄우는 자리 `screens/main/MainApp.jsx`(상세 오버레이 뒤, 토스트 앞).

## 화면
- 화면 아래(좌우 12px 띄움)에 붙는 카드. 막을 깔지 않는다 — 뒤 화면을 그대로 쓸 수 있다. z 는 `--z-prompt`(650): 상세 오버레이(600) 위, 토스트(700) 아래.
- 문구 「오늘 확인하신 정보, 만족스러우셨나요?」, 오른쪽 위 [×](닫기).
- 이모지 5칸(라디오 그룹): 😞 매우 불만족(1) · 🙁 불만족(2) · 😐 보통(3) · 🙂 만족(4) · 😄 매우 만족(5). 누르면 고른 칸만 테두리·연녹색 바탕, 나머지는 흐려진다. 다시 누르면 바꿀 수 있다.
- 아래 줄: 왼쪽 [다시 보지 않기](글자 단추) · 오른쪽 [제출](고르기 전에는 꺼짐).
- [제출]하면 점수를 저장하고 카드가 **이유 쓰기 단계**로 바뀐다: 제목 「응답해 주셔서 감사합니다」, 입력칸 「아쉬운 점이 있다면 알려주세요. (선택)」
  (3줄에서 늘어남, 300자, 글자 수 표시), [보내기](빈 칸이면 꺼짐). 이 단계는 저절로 닫히지 않는다.
- [보내기]하면 「♥ 소중한 의견 감사합니다」 한 줄로 바뀌고 2.5초 뒤 물러난다([×]로 바로 닫을 수도 있다).
- 이유 쓰기 단계에서 [×]로 닫으면 점수만 남는다 — 응답 완료로 치며, 이번 방문 닫기 기록은 남기지 않는다.

## 노출 조건 (물어도 되는 사람인가 — 하나라도)
| 조건 | 판정 |
|---|---|
| 누적 사용 시간 | 이번 방문에서 화면이 보인 시간 합계 30초 이상. 모든 화면(메인 · 상세 · 코스 · 축제 …)을 센다. 탭이 가려진 동안은 세지 않는다. sessionStorage `yongin.survey.visibleMs` 에 1초씩 더한다 |
| 탐색량 | 서로 다른 상점·시설 상세(`#/store/:id` · `#/facility/:id`) 5곳 이상. 같은 곳 재방문은 세지 않음 |
| 길찾기 복귀 | 아래 시점과 같다 — 조건이 곧 시점 |

조건이 맞아도 그 자리에서 뜨지 않는다. 아래 시점을 기다린다.

## 노출 시점 (조건이 맞은 뒤, 먼저 오는 때)
| 시점 | 판정 |
|---|---|
| 흐름이 끝남 | 상세 · 코스 · 축제 · 길찾기 화면(`store` · `facility` · `festival` · `course` · `route`)에서 그 밖(메인 · 전체보기 목록 · 상점가 안내)으로 돌아온 순간. 상세 → 길찾기 → 상세처럼 흐름 안에서 옮기는 것은 끝이 아니다. 신고 폼으로 가는 것도 끝이 아니다 |
| 손을 놓음 | 5초 동안 스크롤 · 터치 · 휠 · 키 입력이 없다(어느 화면에서든) |
| 길찾기 복귀 | 길찾기 화면(`#/route/…`)에서 페이지가 가려졌다(`visibilitychange` hidden) 돌아오면 1.5초 뒤. 다른 조건이 없어도 뜬다. 페이지가 통째로 다시 뜨는 경우도 잡도록 떠난 표시를 sessionStorage 에 둔다 |

팜플렛 안내(S14)·코치마크가 셸에 떠 있거나 오류신고 폼(`#/report`)을 쓰는 동안은 비켜서 있다(그동안 조작이 없어도 「손을 놓음」으로 치지 않는다).

## 재노출 제어
| 행동 | 처리 | 저장 |
|---|---|---|
| 응답 완료 | 다시 묻지 않음 | localStorage `yongin.survey.stop = answered` |
| 다시 보지 않기 | 다시 묻지 않음 | localStorage `yongin.survey.stop = never` |
| [×] | 이번 방문에서만 묻지 않음 | sessionStorage `yongin.survey.closed` |

「한 방문」은 브라우저 탭의 sessionStorage 수명이다. 저장소가 막힌 브라우저에서는 막는 기록이 남지 않는다(편의 값이라 화면은 멈추지 않는다).

## 저장되는 응답 (서버 자리)
서버가 없어 localStorage `yongin.survey.responses` 배열에 쌓는다. 실연동 때 `survey.js` 의 `send()`(점수) · `attach()`(이유) 만 바꾼다.
콘솔에서 `listSurveyResponses()` 로 볼 수 있다(모듈 export).

| 키 | 값 |
|---|---|
| id | 응답 기록 id (`sv-…`). 이유를 이 기록에 덧붙인다 |
| value | 1~5 |
| pageType · pageTypeLabel | `store` 상점 · `facility` 공공시설 · `festival` 축제 · `course` 코스. 길찾기 화면에서 답하면 도착지의 유형. 메인 · 목록에서 답하면(흐름이 끝난 뒤) **방금 보던 페이지**, 아무것도 보지 않았으면 null |
| answeredOn | 카드가 떠 있던 화면(`main` · `store` …) |
| itemId | 그 항목 id |
| qr | QR 유입 위치(`?qr=` 또는 `/s/<코드>`, 없으면 기본 `m-1`) |
| entryParams | URL 파라미터 원문(`location.search`) |
| answeredAt | 응답 일시(ISO 8601, UTC) |
| comment · commentedAt | 이유(쓰지 않으면 null)와 쓴 일시. 실서버에서는 점수 저장 뒤 같은 id 로 덧붙이는 요청이 된다(`attach()`) |
| trigger | 꺼낸 시점 — `flow-end` · `idle` · `route-return` · `flag`(검수) |
| basis | 맞은 조건 — `time`(누적 30초) · `explore`(5곳) · `route-return` |

## 검수 플래그
- `?survey=reset` — 기록(응답 · 다시 보지 않기 · [×] · 본 곳 수 · 누적 시간)을 지우고 시작. 이 주소로 열고 30초 지난 뒤 메인으로 돌아오거나 5초 손을 놓으면 뜬다.
- `?survey=1` — 기록을 지우고 바로 띄운다.

## 관리자 보기 (M17 `#/survey`, `admin/pages/Survey.jsx`)
- 좌측 메뉴 「사용자 의견」 절의 [사용자 만족도 조사]. 모든 계정이 본다. **조회 전용** — 등록 · 수정 · 삭제 없음.
- 위: 응답 수 · 평균 만족도(/5) · 만족 비율(만족 · 매우 만족) · 이유 작성 수, 그 아래 5단계 점수 분포 막대. 모두 **지금 걸린 필터**를 따른다.
- 필터(왼쪽부터): 전체 응답 값 / 전체 페이지 유형 / 「항목명, 이유 검색」(2자 이상). QR 유입 위치 필터는 두지 않는다(2026-11-11) — 표의 열과 상세에는 남는다.
- 표(최신순, 20줄씩): 응답 일시 · 응답 값(이모지 + 점수 · 이름) · 페이지 유형 · 항목 (이름 + ID) · QR 유입 위치(코드 + 지점명) · 이유 · 구분(이 브라우저 / 예시).
- 첫 열(응답 일시)을 누르면 상세: 응답 값 · 페이지 유형 · 항목 · QR 유입 위치 · URL 파라미터 원문 · 응답 일시 · 이유.
- 자료(`admin/data/surveys.js`): 예시 응답 46건(11월 1~8일, 실제 가게 · 시설 · 축제 · 코스 · QR 지점 이름을 빌림) + **이 브라우저에서 시민 화면으로 제출한 응답**.
  시민 화면이 localStorage 에 쌓은 것을 같은 주소(origin)라 그대로 읽는다 — 다른 브라우저 · 기기의 응답은 오지 않는다. 화면 위 안내 상자가 그 사실을 적는다.
