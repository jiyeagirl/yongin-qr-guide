## 2. 둘러보기 탭 (S04)

### 2-1. 탭의 성격

- 탭 id `discover`. 지도가 없는 정보 화면이다. `KakaoMap` 은 언마운트하지 않고 `display:none` 으로 감춘다.
- 이 탭에는 바텀시트 · 상단 필터 바 · 미리보기 카드 · [스캔 위치로] 버튼이 없다. 상단 한 줄 띠(`ContextBar`, 「QR 스캔 지점 기준 안내 · {기준점 이름}」, QR 지점에 `bannerLabel` 이 있으면 그 문구)와 하단 탭바는 남는다.
- 탭을 옮기면 선택(`selected`)과 시트 스냅(절반)이 초기화된다. 둘러보기로 옮길 때 지도 카메라는 건드리지 않는다.
- 탭 아이콘에 알림 점은 없다.
- 스크린리더용 상태 문구: 「둘러보기 탭 · 축제 {전체 6}건, 다른 상점가 {31}곳」 (`FESTIVALS.length`, `OTHER_DISTRICTS.length`).

### 2-2. 섹션 (위에서 아래 순서)

|---|---|---|---|---|
| 1 | 상점가 축제 정보 | 상점가 전체 | `FestivalCard` 2장 + [축제 N건 더 보기] | 진행중 · 예정만 (`FESTIVALS_OPEN`). 머리말 오른쪽 [전체보기] → S12 |
| 2 | 인기 매장 (note = 현재 상점가명) | 현재 상점가 | `StoreRankList` | 현재 상점가가 있을 때만 (2026-10-19 코스보다 위로) |
| 3 | 골목 한바퀴 코스 추천 (머리말 note = 현재 상점가명) | 현재 상점가 | `CourseCard` 가로 스크롤 | 현재 상점가가 있을 때만 |
| 4 | 용인 골목형 상점가 | 현재 상점가를 뺀 31곳 | 가까운 5곳(`DISTRICT_PREVIEW`) 행 + 머리말 오른쪽 [전체보기] → S13 | `DistrictRow` |
| 끝 | 고지 | | 「상점가 지정 현황 2026.07 기준이며, 안내 정보는 참고용입니다.」 | 119 안내 없음 |

- 축제 섹션: 처음에 2건(`FESTIVAL_PREVIEW`)만 펼친다. 나머지가 있으면 [축제 N건 더 보기](누르면 전부 펼침), 다 펼친 뒤에는 [축제 접기]. 한 번 펼치면 남은 건이 없으므로 둘 중 하나만 나온다. 펼침 상태는 탭을 떠나면 사라진다(컴포넌트 상태).
- 축제 0건: `Notice(info)` 「열리고 있거나 예정된 축제가 없습니다」 / 「새 축제가 확정되면 이 자리에 표시됩니다. 지난 축제는 [전체보기]에서 볼 수 있습니다.」
- 현재 상점가 없음(`?district=none`): 2 · 3 섹션을 통째로 감추고 `Notice(info)` 「가까운 상점가가 없습니다」 / 「골목 한바퀴 코스와 인기 매장은 가까운 상점가가 있을 때 보여드립니다. 아래에서 가볼 만한 상점가를 골라보세요.」 를 둔다. 1 · 4 섹션은 그대로다.
- 축제 섹션 정렬: 상태(진행중 → 예정) 다음 「임박」 순이다 (`byFestivalSoon`). 진행중은 종료일이 빠른 순, 예정은 시작일이 빠른 순. 현재 데이터 순서: 둔전 · 구성언남 · 남사한숲 · 머내마을 · 보정중심.

### 2-3. 요소를 누르면

| 요소 | 동작 |
|---|---|
| 축제 카드 | `#/festival/:id` (history 쌓음) |
| 축제 머리말 [전체보기] | `#/festivals` |
| 코스 카드 | `#/course/:id` |
| 인기 매장 행 | `showStoreOnMap` — 상점가 탭으로 옮겨 그 점포를 지도에서 켠다 (아래) |
| 상점가 행 | `showDistrictOnMap` — 열린 오버레이를 모두 닫고(`closeAll`) 상점가 탭으로 옮겨 그 상점가 핀 + 구역 면 + 미리보기 카드를 띄운다 |
| 상점가 머리말 [전체보기] | `#/districts` (S13) |

점포 행(인기 매장)을 눌렀을 때 (`MainApp.showStoreOnMap`):

1. 원본 점포를 `id` 로 되찾는다 (카드가 들고 있는 것은 `note` 가 붙은 사본이다).
2. 탭이 상점가가 아니면 상점가 탭으로 옮긴다.
3. 업종 칩 선택이 있으면 **비운다**(추가하지 않는다). 온누리 칩은 켜져 있고 그 점포가 비가맹일 때만 끈다. 검색어는 있고 그 점포가 이름 · 업종(`biz`)에 걸리지 않을 때만 비운다. 정렬은 건드리지 않는다.
4. `pickOnMap(store)` — 시트를 접힘으로 내리고 핀을 켜며 미리보기 카드를 띄운다.
5. 토스트 「상점가 탭으로 이동했습니다」 (2.2초).

### 2-4. 인기 매장 데이터

- `POPULAR = discoverPicks(STORES).popular`: `visible !== false` 인 점포를 `views` 내림차순으로 정렬해 앞 4곳(`DISCOVER_PICK`, 2026-10-19 8→4).
- 줄 note: 없다 (2026-10-19 「이번 주 조회 1위」·「조회 n회」 삭제). 조회수는 정렬에만 쓰는 더미 생성값(3~113)이다.
- `StoreRankList`: 한 쪽 4줄(`PER_PAGE`), 가로로 밀어 다음 쪽(스냅), 다음 쪽이 오른쪽에 걸쳐 보인다. 줄 = 사진 칸(84px, 자료 `images[0]` 없으면 회색 칸 + 이미지 아이콘) · 순번 · 이름 + 온누리 배지 · `업종 · 주소` · note. 신규 매장 목록은 없다.

### 2-5. 코스 카드 데이터

- 코스는 3개(`COURSES`): 먹자골목 한바퀴(음식 · 카페) · 온누리 알뜰 한바퀴(가맹점, 업종 무관) · 동네 상점 둘러보기(조건 없음). 규칙과 만드는 방법은 5-1.
- 카드: 「도보 {분}분 · {곳수}곳」 · 코스명 · 설명 · 들르는 곳 순번 + 업종 아이콘 + 상호. 폭 244px, 높이는 내용을 따른다. 「반경 300~500m」는 화면에 적지 않는다.
- 상점 QR 로 들어온 진입이면 코스는 그 가게 둘레로 만든다 (`coursesFrom(storeId)`, 그 가게는 코스에서 제외). 그 밖 진입은 기준점(`ANCHOR`) 둘레다.

|---|---|---|---|---|---|

| ft-guseong | 구성언남 | 10.16~18 | 15:00~21:00 | 진행중 | 6.9km |

- 이름이 둘이다. `name` = 실제 축제명(관리자가 고치는 값과 같다), `short` = 화면 제목용(「OO 골목축제」). 데이터 항목은 `id · districtId · name · short · start · end · time · place · program · pose · state · date · period · programs[] · booths[] · tempFacilities[]`. 목록에 쓰는 사본에는 `districtName · dist · homepage` 가 더해진다.
- 상태 판정: `TODAY < start` → 예정, `TODAY > end` → 종료, 그 밖 진행중. `TODAY`(`config.js`)는 검수용 고정 상수 `"2026-10-17"` 이다.
- `date` 문자열 형식: 하루 「10.17 (토) 15:00~21:00」, 여러 날 「10.16 (금) ~ 10.18 (일) 15:00~21:00」. 요일은 `Date.UTC` 로 계산한다.
- 거리는 `DISTRICTS[].dist`(기준점에서의 직선거리를 100m 단위로 반올림). 둔전만 0 이다.
- 프로그램: ft-dunjeon 4 · ft-guseong 4 · ft-everland 3 · ft-namsa 3 · ft-dongcheon 3 · ft-bojeong 4건. 한 건 = 시작 일시 · 종료 일시 · 프로그램명 · 위치 · 설명.
- 부스: ft-dunjeon 만 3건(먹거리 · 체험 · 공연 무대). 나머지 축제는 부스 자료가 없다.
- `tempFacilities`(임시 화장실 · 의료소 · 안내소)는 ft-dunjeon 에만 있고 어떤 화면에도 그리지 않는다.
- 조아용 포즈: ft-everland excited · ft-guseong surprised · ft-dunjeon thumbsup · ft-namsa front · ft-dongcheon shy · ft-bojeong curious.
- 현재 상점가의 진행 중 축제가 상점가 탭 배너 · 점포 상세 배너의 원천이다 (`CURRENT_FESTIVAL`, 종료면 null). 점포 상세 배너는 상태가 「진행중」일 때만 나온다.

### FestivalCard 의 모양

- 상태 배지(글자 + 색: 진행중 · 예정 · 종료) · 날짜(`date`) · 제목(`short || name`) · 실제 축제명(`short` 가 있을 때만 한 줄 더) · 「상점가명 · 거리」(거리 ≥1000m 면 `x.x km`, 그 미만 `m`, 0 이면 「현 위치」) · 조아용(종료는 투명도 .45).
- 카드 바탕 · 배지 색은 상태가 정한다 (`festivalState.js`). 색만으로 말하지 않는다.
- 스크린리더 라벨은 실제 축제명만 읽는다: 「{상태} · {name}. {date}. {상점가} {거리}.」

## 5. 코스

### 5-1. 코스 데이터 규칙 (`dunjeon.js` · `coursePlan.js`)

- 후보: 기준점에서 300~500m 인 점포(`BAND`). 코스마다 `pick` 규칙으로 거른 뒤 **탐욕적 최근접 이웃**으로 4곳을 잇는다(시작점 = 기준점, `coursesFrom` 의 경우 그 가게). 3곳 미만이면 코스를 버린다.
- 한 코스의 구간 값: `legM`(직전 지점까지 도보 거리, 첫 곳은 점포 `dist`), `legMin = max(1, round(legM/67))`(67m/분 = `WALK_M_PER_MIN`). 총 시간 · 거리는 구간의 합이다.
- 상점 QR 둘레 코스(`coursesFrom`): 그 가게를 후보에서 빼고, 앞 코스가 쓴 가게는 뒤 코스 후보에서 먼저 뺀다(후보가 4곳 미만이면 겹침 허용).
- 현재 데이터(기준점 둘레): 먹자골목 9분 530m · 온누리 8분 484m · 동네 상점 8분 421m, 각 4곳. 상점 QR(`dj-163`) 둘레: 각 8분, 4곳.
- 시민용 더미의 코스는 위 규칙으로 자동 생성한 결과다. 데이터 출처를 서버 응답으로 바꾸는 자리는 이 블록 하나다 (`dunjeon.js` 의 `COURSES`).

### 5-2. 코스 상세 (S08, `#/course/:id`)

| 영역 | 내용 |
|---|---|
| 앱바 | 제목 = 코스명, 뒤로 |
| 코스 지도 | 화면 위에 붙는(sticky) 지도. 비율 4:3, 높이 최대 46vh, 초기 레벨 3. 셸 지도와 **별개 인스턴스**다. 순번 핀(30px 원, 번호) + 기준점에서 출발해 순서대로 잇는 점선. 열릴 때 코스 전체(기준점 포함)에 맞춘다(`fitTo`) |
| 요약 | 배지 「도보 {분}분」 · 「{n}곳」 · 「약 {거리}」(≥1000m 면 km) — 지금 깔린 순서의 구간 합. 코스 설명(굵게) |
| 진행률 | 조아용(방문 0 front · 일부 curious · 전부 thumbsup) · 「{방문}/{전체} 방문」 · 막대. 한 곳이라도 표시하면 「들른 곳에 표시해 두세요」, 전부면 「다 도셨어요」. 방문이 있을 때만 [처음부터] |
| 순서 안내 | 「순서 변경 아이콘을 드래그하면 순서가 변경됩니다」(곳이 2곳 이상일 때). 순서를 바꾼 상태에서만 아이콘 단추 ↺ 「추천 순서로 되돌리기」 |
| 순번 목록 | 행 = 순번 · 업종 아이콘 · 상호 · 온누리 배지 · `업종라벨 · 업종` · [방문 완료]/[방문함] 칩 · 순서 변경 아이콘(⠿). 첫 행 위에 「기준점 → ①」 구간 시간, 각 행 왼쪽에 다음 지점까지의 구간 시간 |
| 고지 | 「점포 정보 2026.03. 기준」 + 「안내 정보는 참고용이며, 코스는 추천 경로입니다. 영업시간과 휴무는 매장마다 다르니 방문 전에 확인해 주세요.」 119 없음 |

동작 규칙:

- 처음에는 아무 순번도 고르지 않는다. 행 · 지도 핀을 누르면 `activeId` 가 정해지고 지도가 그 핀으로 이동(카드 높이만큼 위로 올려 잡음), 지도 바닥에 `MapPreviewCard(compact)` 가 뜬다. 고른 핀 · 행은 강조색(`--pin-course-active`)으로 바뀐다.
- 카드 [길찾기] → `#/route/store/{id}[/{직전 가게 id}]`, [상세 보기] → `#/store/{id}[/{직전 가게 id}]`. 직전 가게 = 지금 순서상 바로 앞 가게(첫 곳은 없음 → 출발지가 기준점). 카드 [×] → 선택 해제 + 코스 전체로 되돌림.
- [방문 완료]는 표시만 한다. 순서 · 번호 · 총 시간 어느 것도 바꾸지 않는다. 표시를 **켤 때** 지도가 목록에서 아직 안 들른 첫 곳으로 이동한다(끌 때는 이동하지 않음). 방문한 행은 글자가 흐려지고 조아용 도장이 행 위에 겹쳐 찍힌다(자리를 차지하지 않는다).
- 순서 바꾸기: ⠿ 단추에서만 끌기가 시작된다(`touch-action:none`이 그 44px 에만 걸림). 끄는 동안 잡은 줄은 손가락을 1:1 로 따라가고 나머지 줄은 자리를 비우며 밀리고, 순번은 놓았을 때의 번호로 미리 바뀐다. 배열은 손을 뗄 때 한 번만 바뀐다. 키보드: ⠿ 에 초점이 있을 때 ↑ / ↓ 로 한 칸씩. 옮긴 결과(「{상호}, {n}곳 중 {k}번」)를 `aria-live` 로 읽어준다.
- 순서를 바꾸면 구간 값(`withLegs`)과 총합이 그 순서로 다시 계산된다. 손대지 않았으면 추천 순서를 계산 없이 그대로 쓴다. 코스 자료에 새로 생긴 곳은 사용자 순서 뒤에 붙는다.
- 기록은 **세션 단위**(`sessionStorage`)다. 방문 기록 키 `yongin.course.visits.v1`, 순서 키 `yongin.course.order.v1`, 둘 다 코스 id 별 객체. [처음부터]는 방문만, ↺ 는 순서만 지운다. 저장소를 못 쓰면 메모리에만 남는다.
- 상세로 갔다 돌아오면 이 오버레이는 언마운트되므로 고른 순번은 사라지고, 방문 기록과 순서만 남는다.

## 6. 축제 상세 (S09, `#/festival/:id`)

위에서 아래 순서:

| 순서 | 내용 | 조건 |
|---|---|---|
| 앱바 | 제목 `short || name`, 뒤로 | 축제 QR 로 막 들어온 첫 화면이면(`entry`) 뒤로 대신 `store` 아이콘 「홈」 — 누르면 셸(상점가 탭)로 나간다 |
| 하단 고정 | 주 버튼 [상점가 둘러보기](`store` 아이콘) → 열린 오버레이를 모두 닫고 상점가 탭 | 항상 |
| 머리 | 상태 배지 · `party-popper` 아이콘 · 제목 `short || name` · 실제 축제명(`short` 가 있을 때) | |
| 종료 안내 | `Notice(info, sm)` 「이미 끝난 축제입니다」 / 「아래 내용은 지난 행사 기준입니다.」 | 상태가 종료일 때 |
| 사진 | `PhotoStrip`(「축제 이미지」). `festival.images` 자료가 없어 자리표시 카드 3장 | 항상 |
| 소속 상점가 | 「소속 상점가 :」 + 링크 버튼(상점가명) | 항상. 누르면: 현재 상점가면 오버레이를 닫고 상점가 탭, 다른 상점가면 `showDistrictOnMap`(지도 핀 + 카드) |
| 정보 표 | 기간 · 시간 · 주요 프로그램 (`InfoList`, 값이 비면 「-」) | 항상 |
| 주요 프로그램 일정 | 아코디언, 전부 닫힌 채 시작. 접힌 줄 = 시각 + 프로그램명, 펼치면 위치(굵게) + 설명 | 프로그램 자료가 있을 때만 |
| 부스 위치 | 카드 안 행: 부스명 · 위치 · 시각(있을 때) | 부스 자료가 있을 때만 (현재 ft-dunjeon) |
| 골목 한바퀴 코스 추천 | 안내 「축제 위치 근처 가게들을 둘러보세요」 + `CourseCard` 가로 스크롤 | 코스가 넘어올 때만 — 축제의 상점가가 현재 상점가일 때. 누르면 `#/course/:id` |
| 고지 | 「안내 정보는 참고용이며, 일정과 프로그램은 주최 상점가 사정으로 변경될 수 있습니다.」 | 기준일 · 119 없음 |

- 시각 문구(`whenLabel`): 하루짜리 축제는 시각만(「15:00 ~ 17:00」), 여러 날 축제는 날짜를 붙인다(「10.17 15:00 ~ 21:00」, 날을 넘기면 양쪽 날짜).
- 화면에 없는 것: 오류 신고 단추 · 장소(`place`) · 당일 임시시설 · 기준일자.
- 이 화면에서 코스 목록이 가리키는 곳은 상점 QR 진입이면 그 가게 둘레, 아니면 기준점 둘레다.

## 7. S14 축제 팜플렛 진입 안내 (예비 화면)

- **도입이 확정되지 않았다.** 지금 열리는 길은 `?pamphlet=<축제 id>`(검수) 뿐이다. 팜플렛 코드 `qr-004` 는 이 대화상자를 거치지 않고 `#/festival/ft-dunjeon` 으로 간다 (`citizen-entry-qr.md` 3 · 6장).
- 조건: 대상 축제가 `FESTIVALS` 에 있고, 이번 진입에서 닫지 않았고, 현재 라우트가 셸일 때. 닫은 기억은 이번 진입 안에서만 산다 (`localStorage` 기록 없음). 코치마크는 이 대화상자가 떠 있는 동안 뜨지 않고 닫힌 뒤에 뜬다.
- 구성: 조아용 · 제목 · 기간 줄(`festival.date`) · 단추 둘. [×] 없음. 막(scrim)을 눌러도 닫히지 않는다. Esc 는 [주변 안내보기]와 같다.

| 축제 상태 | 조아용 | 제목 |
|---|---|---|
| 진행중 | excited | 「{name}이/가 열리고 있어요!」 |
| 예정 | curious | 「{name}이/가 열릴 예정이에요」 |
| 종료 | front | 「{name}은/는 지난 축제예요」 |

- 이름은 `short` 가 아니라 `name`. 조사는 `josa`(`i`, `eun`)가 받침을 보고 붙인다.
- 단추 순서는 세 상태 모두 같다: [축제 정보보기](대화상자를 닫고 `#/festival/{id}`) · [주변 안내보기](닫기만 — 셸의 현재 탭인 상점가 탭에 선다).
- 검수 값(`TODAY` 기준): `ft-dunjeon` 진행중 · `ft-namsa` 예정 · `ft-everland` 종료.
- 실서비스에서 뜨려면 QR 지점에 연계 축제가 걸려야 하는데 관리자 화면에 그 칸이 없다 — 지금 상태로는 시민에게 뜨지 않는다.

## 8. 상태 · 예외 요약

| 상황 | 화면 동작 |
|---|---|
| 존재하지 않는 축제 · 코스 id 의 딥링크 | 토스트 「정보를 찾을 수 없습니다」 후 `back()` |
