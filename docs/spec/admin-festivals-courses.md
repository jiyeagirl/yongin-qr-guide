## 3. 1:N 목록 (슬롯 ③) — 프로그램 일정 · 부스 위치

`Repeater` 로 그린다. 두 목록 모두 제목 옆에 「선택」 배지와 「{n}건」, 아래에 안내 「작성하신 순서에 따라 사용자 화면에 노출됩니다.」가 선다(코스 목록의 안내는 4장). 저장되는 것은 배열 순서 그대로이며 `sort_order` 같은 순서 값은 만들지 않는다.

### 3-1. 공통 동작

| 항목 | 내용 |
|---|---|
| 빈 목록 | 열 이름 줄 + 비활성 칸 한 줄(「예) …」)을 그려 [추가]를 누르면 생기는 모양을 미리 보인다 |
| 열 이름 줄 | 필수 열 이름 뒤에 붉은 `*`. 저장 시 필수 검사가 이 별표와 같은 규칙을 지킨다 |
| [추가] | [프로그램 추가] / [부스 추가]. 축제 기간에서 고를 날이 없으면 줄을 만들지 않고 목록 아래에 이유를 적는다: 시작일 · 종료일이 비었을 때 「시작일과 종료일을 먼저 입력해 주세요.」, 종료일이 시작일보다 빠를 때 「종료일이 시작일보다 빠릅니다. 축제 기간을 먼저 고쳐 주세요.」 (단추는 흐리지 않는다) |
| 줄 삭제 | 휴지통 → **그 줄 아래에** 「{프로그램명|부스명|n번째 줄} 을(를) 지울까요?」 [취소] [삭제] (다이얼로그를 겹치지 않는다). 폼 안의 임시 값이라 [저장] 전에는 어디에도 없다 |
| 줄 순서 | 프로그램 · 부스는 순서 변경 단추가 없다(적은 순서가 노출 순서) |
| 일시 칸 (`daytime`) | **축제 기간의 날짜 목록 중 하나**(`10.17 (토)` 형식, 앞자리 0 없음) + **시각**(`type="time"`, 폭 148px) 두 칸. 연도를 묻지 않는다. 저장 값은 `YYYY-MM-DDTHH:mm`. 날짜를 고르지 않고 시각을 넣으면 첫날(`days[0]`)로 본다. 고를 날이 없으면 날짜 칸은 칸 이름 「일자」만 달고 잠기고 시각 칸도 잠긴다. 값이 이미 들어 있는데 기간 밖이 되면 그 날짜를 「m.d (기간 밖)」로 앞에 세워 보여준다 |
| 반쪽 값 | 날짜만 있고 시각이 없는 값(`2026-10-18T`)은 필수 검사에서 「채워지지 않은 것」으로 본다 |
| 칸 폭 | 일시 칸 300px 고정 |

### 3-2. 프로그램 일정 (`PROGRAM_COLUMNS`)

| 열 | 키 | 필수 | 형식 | 범위 · 검증 | 예시 |
|---|---|---|---|---|---|
| 시작 일시 | `startAt` | 필수 | daytime | 축제 기간 내(목록으로 제한) | — |
| 종료 일시 | `endAt` | 필수 | daytime | 시작 일시 이후 (V-07, 줄 번호로 보고) | — |
| 프로그램명 | `title` | 필수 | text | 최대 40자 | 개막 풍물놀이 |
| 위치 | `where` | 선택 | text | 최대 60자 | 시장통 무대 |
| 설명 | `desc` | 선택 | text(**아랫줄**) | 최대 300자 | 포곡농악보존회 |

설명 칸은 접혀 있다 — 비어 있으면 「설명 추가」 한 줄이고 누르면 펴진다. 값이 들어 있으면 처음부터 펴진 채로 서고 접는 단추가 없다. 줄 하나가 테두리 카드다(아랫줄 칸이 있는 목록만 카드). 삭제 확인 문구의 이름은 `title`.

### 3-3. 부스 위치 (`BOOTH_COLUMNS`)

| 열 | 키 | 필수 | 형식 | 범위 · 검증 | 예시 |
|---|---|---|---|---|---|
| 시작 일시 | `startAt` | 필수 | daytime | 축제 기간 내 | — |
| 종료 일시 | `endAt` | 필수 | daytime | 시작 일시 이후(날을 넘길 수 있다) | — |
| 부스명 | `name` | 필수 | text | 최대 40자 | 먹거리 부스 |
| 위치 | `where` | 선택 | text | 최대 60자 | 시장통 입구 ~ 중앙 무대 양쪽 |

부스는 좌표 · 배치도 · 번호 · 유형 · 설명 칸이 없다. 카드 테두리도 두르지 않는다(아랫줄이 없는 목록).

## 4. 골목 한바퀴 코스 (M09 · M10) — `#/courses`

### 4-1. 목록

| 항목 | 내용 |
|---|---|
| 제목 · 개수 | 「골목 한바퀴 코스 관리」 · 「{n}건」 |
| 머리 단추 | [코스 등록] |
| 필터 | 소속 상점가(「전체 골목형 상점가」 + 32곳) → 검색창(「코스명 검색」, 코스명만 본다) |
| 열 | 코스명(정렬) · 골목형 상점가(정렬) · 코스(「n곳」 배지 + 앞 두 곳 이름 + 「외 n곳」, 정렬) · 노출 여부(토글) |
| 강조 | 점포가 4곳이 아닌 코스는 줄 경고 색 + 「n곳」 배지 위험 색 |
| 선택 · 일괄 | 체크박스 → [노출] · [숨김] |
| 삭제 | 없음 |
| 빈 목록 | 「조건에 맞는 코스가 없습니다.」 |

### 4-2. 등록 · 수정 다이얼로그

| 항목 | 내용 |
|---|---|
| 제목 | 「골목 한바퀴 코스 등록」 / 「골목 한바퀴 코스 수정」(크기 lg), 수정 창 부제 코스명 |
| 등록 기본값 | 상점가 = 목록에서 건 상점가 필터(「전체」면 둔전 `dunjeon`), 노출 = 켜짐, 점포 = 빈 줄 4개 |
| 수정 열기 | 점포 목록을 **항상 4줄로 맞춘다**(모자라면 빈 줄, 넘치면 잘라서 연다) |
| 점포 줄 | 4줄 고정. [점포 추가] · 휴지통 없음. 순번(1~4) + 검색해서 고르는 칸 + 오른쪽 손잡이(끌기 또는 ↑/↓ 키로 순서 변경). 안내 「손잡이 아이콘을 통해 차례를 조정할 수 있습니다.」 |
| 점포 선택지 | 고른 상점가의 점포만, 상호명 가나다순, 지점명이 있으면 「상호 지점」으로 적는다. 상호의 가운데 토막으로도 걸린다. 목록은 열 줄까지 보이고 「n개 더 있습니다. …」를 적는다 |
| 소속 점포 없음 | 선택한 상점가에 점포가 0이면 경고 상자 「이 골목형 상점가에 등록된 점포가 없습니다」(「코스는 소속 점포 중에서 고릅니다. 점포 정보 관리에서 이 상점가의 점포를 먼저 등록해 주세요.」) |
| 상점가를 바꿨을 때 | 이미 고른 점포 중 새 상점가에 속하지 않는 줄이 있으면 **지우지 않고** 경고 「다른 골목형 상점가의 점포가 {n}곳 남아 있습니다」 |
| 저장되는 값 | 점포의 id 와 차례(`stops: [{ storeId }]`)만. 이름 · 업종 · 좌표 · 거리 · 도보 시간은 저장하지 않는다 |

### 4-3. 입력 항목표 (`COURSE_FIELDS`, `COURSE_STOP_COLUMNS`)

| 항목 | 키 / spec | 필수 | 형식 | 범위 · 검증 | 예시 · 힌트 |
|---|---|---|---|---|---|
| 코스명 | `name` / `name` | 필수 | text(2열) | 2~40자 | 먹자골목 한바퀴 |
| 골목형 상점가 | `districtId` / `market_id` | 필수 | select(2열) | 상점가 중 하나. 힌트 「코스에 넣을 점포는 이 상점가의 것 중에서 고릅니다」 | 둔전골목형상점가 |
| 코스 설명 | `desc` / `description` | 필수 | text(2열) | 2~60자 | 맛있는 음식점과 카페를 찾아 떠나는 코스 |
| 노출 여부 | `visible` / `is_visible` | 필수 | switch | — | — |
| 점포(4줄) | `stops[].storeId` / `store_id` | 필수(4줄 모두) | 슬롯(`Repeater` `ordered` `fixedRows=4`), 칸 종류 `picker` | 소속 상점가의 점포 중에서 검색해 고른다. 장소 입력 칸 아님 | 상호명으로 찾습니다 |

### 4-4. 저장 전 추가 검사 (`extraValidate`)

| 순서 | 검사 | 문구 (코스 목록 칸에 붙음) |
|---|---|---|
| 1 | 비어 있는 점포 줄 | 「{n}번째 줄의 점포를 채워 주세요.」(`missingInRows`, 열 이름 받침에 따라 을/를) |
| 2 | 같은 점포가 앞 줄에 이미 있음 | 「{n}번째 줄의 {상호명} 이(가) 앞줄에 이미 있습니다.」 |

도보 시간 · 총 거리 · 업종 조건 · 노출 순서 칸은 없다(코스 카드의 차례는 목록 차례).

## 5. 슬롯 3종 정리

항목표에 줄로 서지 않거나 자리만 있는 항목. 모두 **저장되는 항목**이다.

| 슬롯 | 항목표에서의 상태 | 화면 구현 | 쓰이는 화면 |
|---|---|---|---|
| ① 좌표 (`lat` · `lng`) | `type: "coord"` 한 줄(`key: "coord"`, `spec: "lat · lng"`, 필수, 2열)이 자리만 갖고 있다 | `RecordForm` 의 `slots.coord` 에 화면이 `CoordField` 를 넣는다. 필수 · 오류는 `RecordForm` 이 항목표에서 얹는다. 검사는 `validate` 의 coord 갈래 | 점포 · 공공시설 · QR 지점 (본 문서 범위의 축제 · 코스에는 없다) |
| ② 조아용 이미지 (`pose` ← `character_id`) | **줄이 없다** | `RecordForm` 의 `extra` 로 폼 맨 뒤(항목표 뒤)에 `AssetPicker` 를 붙인다. 필수 검사는 `Festivals.jsx` `extraValidate` | 축제 |
| ③ 1:N 목록 | **줄이 없다** | `extra` 로 폼 맨 뒤에 `Repeater` 를 붙인다. 필수 · 순서 검사는 `extraValidate` 가 `missingInRows` 등으로 한다 | 축제(프로그램 `programs` · 부스 `booths`), 코스(`stops`) |
