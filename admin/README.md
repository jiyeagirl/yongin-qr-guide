# 관리자 웹 (`/admin/`)

기능명세서 v1.0 **2장 관리자 웹**의 8개 화면. 시민용 12개 화면이 끝난 뒤 별도 과제로 진행한
후속분이다 (확정 결정사항 1번).

## 시민용과 왜 완전히 나누는가

**시민용 앱에서 들어갈 수 있는 입구를 두지 않는다.** QR 을 찍고 들어온 시민이 관리자
화면을 볼 이유가 없고, 로그인이 붙는 순간 그 링크는 실패하는 문으로만 남는다. 그래서
주소도 폴더도 나눈다 — `/screens/main/` 과 `/admin/` 은 서로를 가리키지 않는다.
(검수 입구인 저장소 루트 `index.html` 에만 링크가 있다.)

**디자인 시스템 진입점도 나눈다.** `design-systems/index.js` 는 시민용, `admin.js` 는
관리자용이다. 관리자 컴포넌트를 `index.js` 에 합치면 재수출을 타고 시민용 모바일 번들에
데이터 표와 다이얼로그가 들어간다 — 길에서 QR 을 찍는 사람이 내려받을 이유가 없는 것들이다.
합치지 않은 결과, 관리자 화면 8개를 더한 뒤에도 시민용 번들은 **92모듈 715KB 그대로**다.

거기서 정하고 나머지 다섯이 복제한다. 시민용에서 S03 이 지도 화면의, S05 가 상세 화면의
기준이었던 것과 같은 자리다. 새 관리 화면을 만들 때 배치를 다시 정하지 않는다.

## 입력 항목은 정의서가 정한다

`data/fields.js` 가 **입력 항목 정의서의 항목표**를 그대로 들고 있고, 폼 여덟 개가 전부
거기서 나온다. 화면이 항목을 하나 더 넣고 싶어도 넣을 자리가 없다 — 그게 이 구조의 요점이다.

같은 정의서에서 나온 표가 시민 쪽에도 있다. **읽는 쪽과 쓰는 쪽이 한 표의 앞뒤다:**

| | 파일 | 정의서 |
| --- | --- | --- |
| 읽기 | `screens/detail/FacilityDetail.jsx` 의 `FIELDS` | 2-1 ~ 2-4 |
| 읽기 | `screens/detail/StoreDetail.jsx` 의 `InfoList` | 1-2 |
| 읽기 | `screens/detail/FestivalDetail.jsx` 의 `InfoList` | 1-3 |
| **쓰기** | `admin/data/fields.js` | 전부 |

지금 하나로 합치지 않은 것은 의도다 — 잘 돌고 있는 시민 화면 셋을 아직 검증되지 않은
관리자 폼을 위해 뜯을 이유가 없다. **어긋나면 정의서를 따른다** (명세서 참조 문서).

폼이 지키는 것 다섯:

1. **정의서에 있는 항목만.** 없는 칸을 만들어 두면 담당자는 채워야 하는 것으로 읽고,
   채운 값의 출처는 아무도 모른다
2. **필수/선택을 항목마다 배지로 적는다.** 색만으로 말하지 않고 배지 안에 글자로 적는다
3. **선택 항목을 비우면 시민 화면에 `-` 가 뜬다**고 폼 아래 한 줄로 적는다. 담당자에게는
   그 결과를 볼 방법이 지금 없다
4. **가부 항목은 Switch, 저장값은 불리언.** 표시(○ · ×)는 읽는 쪽이 정한다
5. **AED · 대피소의 명칭 입력칸은 없다.** 도로명주소에서 만든다 (U-FC-10). 폼에는 만들어질
   이름을 미리보기로 보여준다 — 규칙으로 생기는 값이라는 것이 입력하는 사람에게도 보여야 한다

정의서에 없지만 화면이 다루는 것도 있다. 그것들은 **항목표 밖에** 따로 둔다:
노출 토글(운영 상태), 상점가의 구역 주소 목록(상점가 xlsx 의 「구역 주소」 시트)과
노출 순서, QR 지점의 모든 항목(공공데이터 원천이 없다).

## 데이터

읽기 원본은 **시민용과 같은 파일**이다. 복사본을 만들면 둘이 갈라져, 관리자에서 고친 값이
시민 화면에 없는 상태가 곧바로 만들어진다.

```
읽기  screens/main/data/{facilities,dunjeon,districts,qr}.js   ← 손대지 않는다
쓰기  admin/data/store.js                                       ← 원본 위에 덮개(overlay)
관리자 전용  admin/data/{fields,account,stats,inquiries}.js
```

`store.js` 의 덮개가 갖는 것은 셋뿐이다 — `edits`(바뀐 필드만) · `added`(통째 행) ·
`removed`(id). 읽을 때 원본에 겹쳐 목록을 만든다. 실연동 때는 이 파일이 통째로 fetch/POST 로
바뀌고 화면 코드는 `useCollection` 의 모양만 같으면 손대지 않는다.

> **여기서 고친 것은 시민용 화면에 반영되지 않는다.** 서버가 없어 둘이 자료를 주고받을 길이
> 없고, 덮개는 `sessionStorage` 에 있는데 그 저장소는 **탭 단위**라 시민용 화면을 다른 탭에서
> 열면 애초에 닿지 않는다. 화면 상단의 노란 띠가 이 사실을 늘 적어 둔다. 실연동 때는 양쪽이
> 같은 서버를 보므로 그 띠를 지운다.

`sessionStorage` 인 이유는 `screens/main/data/courseVisits.js` 와 같다 — 새로고침에 살아남아야
검수가 되고(폼을 채우다 새로고침하면 처음부터다), 탭을 닫으면 사라져야 다음 검수가 깨끗한
상태에서 시작한다. 상단바의 **[데모 데이터 초기화]** 는 고친 것이 있을 때만 선다.

## 권한 (A-AC-01)

| 계정 | 권한 | 볼 수 있는 화면 |
| --- | --- | --- |
| `yongin` / `yongin1234` | 시청 담당자 | 7개 전부 |
| `ninelight` / `ninelight1234` | 운영사 | 5개 (대시보드 · 문의 제외) |

가르는 기준은 **책임의 종류**다. 문의 답변은 그 답이 시청의 답으로 읽히기 때문에 시청
담당자만 하고, 통계는 대외 보고에 쓰이는 수치라 같은 쪽에 둔다. 운영사는 자료를 채워 넣는다.

두 겹으로 막는다: 내비에서 감추고, 주소로 직접 들어와도 되돌린다. 하나만으로는 부족하다 —
감추기만 하면 `#/inquiries` 를 주소창에 치는 것으로 들어와지고, 되돌리기만 하면 눌러보고
튕겨나는 메뉴가 남는다. **다만 이것은 UI 수준의 분리일 뿐이다.** 실서비스의 권한은 서버가
막는다. 계정 표(`data/account.js`)와 비밀번호가 소스에 있는 것도 그래서다 — 감출 가치가 있는
비밀이 아니라 검수용 열쇠이고, 로그인 화면이 그 사실을 화면에 그대로 적는다.

## 실행

```bash
npm run serve      # 로컬 서버 — 기본 8000
npm run build      # 번들 2개 생성 (시민용 + 관리자)
```

→ http://localhost:8000/admin/

로컬 개발에는 빌드가 필요 없다 (번들이 없으면 로더로 떨어진다). 시민용과 같은 규칙이다 —
`?dev=1` 을 붙이면 번들이 있어도 원본을 읽는다.

**카카오 SDK 도메인을 새로 등록할 필요는 없다.** 등록 대상은 경로가 아니라 출처(origin)라
`/screens/main/` 과 `/admin/` 이 같은 도메인이다. QR 지점 관리의 좌표 미리보기가 지도를 쓴다.

### 검수 순서

| 확인할 것 | 방법 |
| --- | --- |
| 로그인 · 권한 분리 | 두 계정으로 각각 들어가면 좌측 메뉴가 7개 / 5개로 갈린다 |
| 유형별 폼 | `#/facilities` → [시설 등록] → 유형을 화장실로 바꾸면 항목이 3개에서 10개로 갈린다 |
| 필수 검사 | 빈 채로 [저장] → 다이얼로그가 닫히지 않고 해당 칸에 오류가 뜬다 |
| 자동 생성 명칭 | AED 의 도로명주소를 고치면 명칭 미리보기가 따라 바뀐다 |
| 세션 유지 | 무언가 고친 뒤 새로고침 → 남아 있다. 탭을 닫았다 열면 → 사라진다 |
| 좁은 화면 | 창을 1,024px 아래로 줄이면 안내 문구만 남는다 |
| 시민용 무영향 | `/screens/main/` 세 탭과 상세가 전과 같다 |

## 구조

```
admin/
├── index.html          부트스트랩 — screens/main/index.html 과 같은 규칙, 기기 틀만 없다
├── AdminApp.jsx        로그인 게이트 + 권한 되돌리기 + 셸 + 토스트
├── router.js           해시 라우터 (screens/main/router.js 축소판 — 히스토리 깊이 계산이 없다)
├── pages/
│   ├── Login.jsx  Dashboard.jsx  Facilities.jsx  Districts.jsx
│   ├── Stores.jsx  Festivals.jsx  QrPoints.jsx  Inquiries.jsx
│   ├── useRecordEditor.js   등록·수정·삭제 상태 한 벌 (여섯 화면 공용)
│   └── RecordForm.jsx       항목표 → 입력 칸
└── data/
    ├── fields.js       정의서 항목표 — 폼 여덟 개의 유일한 출처
    ├── store.js        덮개 저장소
    ├── account.js      계정 2종과 권한
    ├── stats.js        대시보드 수치 (시드 난수 — 새로고침해도 같다)
    └── inquiries.js    접수 12건
```

디자인 시스템 쪽에 추가된 것은 `design-systems/components/admin/` 8개와
`tokens/admin.css` 다 (`design-systems/CHANGELOG.md` 참조).
