# 관리자 웹 규칙 (CLAUDE.md 에서 @import)

상세는 `docs/spec/admin-*.md`(현재 상태) · `admin/README.md` · `docs/archive/admin_specifications.md`.

- 범위는 **개별 건의 조회·수정·신규 등록과 오류신고 기반 보정**이다. 일괄 적재·매칭·갱신·검수와
  서비스 운영 설정값은 개발 쪽이다. **관리자가 데이터를 무리로 다루지 않는다**(재매칭·동기화·검수 큐 금지).
- 조건부 `C` 항목(축제 프로그램·부스)은 감추지 않고 화면이 그 사실을 적는다.
- **입력 항목의 유일한 출처는 `admin/data/fields.js` 한 표다.** 화면이 항목을 더 넣고 싶어도 넣을 자리가 없다.
- **표에 줄로 서지 않는 항목 셋은 화면이 슬롯으로 그린다** — 좌표(`CoordField`, 표에는 `coord` 한 줄) ·
  조아용 이미지(`character_id` → 코드에서는 `pose`, `AssetPicker`) · 1:N 목록(프로그램·부스·코스, `Repeater`).
  저장되는 항목이므로 항목표만 보고 스키마를 짜면 이 셋이 빠진다.
- **엑셀 일괄 등록은 파일을 받는 데까지만 화면의 일이다.** 점포·공공시설 목록의 [등록]이 그 창을 열고
  (파일보다 먼저 소속 상점가·시설 유형을 고른다), 읽고 넣고 실패 행을 돌려주는 일은 서버 쪽이다.
  상점가 목록의 [등록]은 폼이다(한 건씩).
- **시민용 화면 어디에도 관리자로 가는 링크를 두지 않는다**(루트 `index.html` 검수 입구는 예외).
  서버가 없어 관리자에서 고친 내용은 시민용에 반영되지 않으며, 그 사실을 관리자 상단 띠가 늘 적는다.
