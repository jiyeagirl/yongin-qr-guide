# 시민용 모바일 웹 화면

기능명세서(v1.0) 4장의 12개 화면(S01~S11)이 여기에 들어간다.
별도 홈 화면은 없고, 지도가 상시 노출되며 하단 탭 3개가 바텀시트 콘텐츠를 교체하는 구조다.

## 폴더가 화면 번호와 1:1이 아닌 이유

**S02·S03·S04 는 별도 페이지가 아니라 같은 화면의 탭 상태다** (기능명세서 4장).
페이지를 나누면 탭을 바꿀 때마다 지도가 다시 뜨는데, 그것을 **U-CM-16(지도 상시 노출,
탭 전환 시 재로딩 금지)** 이 금지한다. 그래서 세 탭은 `main/` 한 폴더 안에 있고,
상세·길찾기처럼 실제로 페이지가 바뀌는 화면만 자기 폴더를 갖는다.

| 화면 | 상태 | 경로 |
| --- | --- | --- |
| S03 상점가 탭 | **완료 (기준 화면)** | `main/` — `DistrictSheet.jsx` |
| S02 공공시설 탭 | **완료** | `main/` — `FacilitySheet.jsx` |
| S04 둘러보기 탭 | **완료** | `main/` — `DiscoverSheet.jsx` |
| S03-E 상점가 없음 안내 | 미착수 | `main/` (상점가 탭의 한 상태) |
| S01, S05~S11 | 미착수 | 각자 폴더 예정 |

**셸은 완성됐다.** 탭 3개가 모두 실제 내용을 갖고, 지도는 한 번만 만들어져 탭 전환 때
마커 레이어만 갈아끼운다 (U-CM-16 / U-CM-17). 남은 화면은 이 셸에서 진입하는 상세·폼 화면들이다.

지도·시트·필터 규칙은 S03 에서 확정했고 S02 가 그대로 물려받았다 →
[`docs/S03_map_overlay_rules.md`](../docs/S03_map_overlay_rules.md)

> **하단 탭바(U-CM-03)까지 포함한다.** 이를 위해 5-3 의 **#5 탭바와 바텀시트의 공존**,
> **#6 탭 전환 시 지도 동작** 을 확정했다 — 탭바는 항상 보이고(시트의 형제 요소),
> 탭을 바꾸면 카메라가 QR 지점 + 탭별 기본 줌으로 돌아온다.
> 탭바가 지도 영역에서 64px 을 가져가면서 시트 스냅도 재계산했다 (절반 55% → 62%).

## 실행

`fetch` 로 디자인 시스템 원본을 읽으므로 **`file://` 이 아니라 HTTP 로 열어야 한다.**

```bash
# 저장소 루트에서 (Node 만 있으면 된다. 설치·의존성 없음)
node tools/serve.mjs          # 기본 8000
node tools/serve.mjs 8080     # 포트 지정
```

→ http://localhost:8000/screens/main/

> **Windows 에서 `python -m http.server` 를 쓰지 말 것.**
> `python` 이 Microsoft Store 앱 실행 별칭(`%LOCALAPPDATA%\Microsoft\WindowsApps\python`)이면
> 아무 것도 하지 않고 조용히 끝난다. 서버가 뜬 것처럼 보이지만 실제로는 리스닝하지 않아
> localhost 연결이 실패한다. `python -c "print(1)"` 이 `1` 을 출력하지 않으면 이 경우다.

## Vercel 배포

빌드가 없다. 정적 파일을 그대로 올린다.

```bash
# 저장소 루트에서
npx vercel          # 첫 실행 — 로그인 후 프로젝트 이름을 정하면 미리보기 주소가 나온다
npx vercel --prod   # 운영 주소(<프로젝트>.vercel.app)로 올린다
```

`package.json` 이 없으므로 Vercel 이 빌드를 시도하지 않고 정적 호스팅으로 잡는다.
루트 `index.html` 이 화면 목록 입구이고, 메인 화면은 `/screens/main/` 이다.

| 파일 | 역할 |
| --- | --- |
| `vercel.json` | 프레임워크 없음 · `trailingSlash` · 보안 헤더 2종 |
| `.vercelignore` | `.claude/` `skills/` `tools/` `docs/` `CLAUDE.md` 등 웹에서 안 쓰는 것 제외 |
| `index.html` | 배포 주소 루트로 들어온 사람을 위한 화면 목록 |

> **여기 없는 파일은 전부 공개 주소로 그대로 서빙된다.** `docs/` 와 `CLAUDE.md` 는 저장소
> 안쪽 문서라 기본 제외해 두었다. 공개해도 되면 `.vercelignore` 에서 두 줄을 지운다.

### 배포 후 반드시 할 것 — 카카오 SDK 도메인 등록

**이걸 안 하면 배포본에서 지도만 안 뜬다.** 로컬(`http://localhost:8000`)과 배포 주소는
카카오 입장에서 완전히 다른 도메인이다.

```
https://<프로젝트>.vercel.app        ← 운영 주소를 SDK 도메인에 추가
```

> **미리보기(preview) 주소는 배포할 때마다 바뀐다** (`<프로젝트>-<해시>-<팀>.vercel.app`).
> 매번 등록할 수 없으므로 **지도 확인은 `--prod` 로 올린 운영 주소에서 한다.**
> 미리보기에서 지도 자리에 안내 문구가 뜨는 것은 정상이다 (그 화면이 등록해야 할 주소를 알려준다).

`config.js` 의 JavaScript 키는 소스에 그대로 들어가고 배포본에서 누구나 볼 수 있다.
**이건 정상이다** — 카카오 JavaScript 키는 공개 전제이고, 도용을 막는 것은 키 숨김이 아니라
위의 SDK 도메인 등록이다. 등록된 도메인 밖에서는 그 키로 지도가 뜨지 않는다.
(REST API 키·Admin 키는 성격이 다르다. 그것들은 절대 소스에 넣지 않는다.)

### 첫 로딩 용량 — 아직 무겁다

빌드가 없어서 브라우저가 Babel 로 JSX 를 실시간 변환한다. 그 대가가 크다.

| 항목 | 크기 |
| --- | --- |
| `@babel/standalone` | **3,064 KB** |
| `react-dom` (development) | 1,054 KB |
| `lucide` | 608 KB |
| `react` (development) | 107 KB |
| 화면·디자인시스템 원본 (약 60개 파일을 개별 요청) | 315 KB |
| **합계** | **약 4.7 MB** |

검수용으로는 쓸 만하지만, **길에서 QR 을 찍는 실사용자에게 낼 숫자는 아니다.**
줄이려면 배포 전에 JSX 를 미리 변환하는 단계가 필요하다 (Babel 3MB 와 개별 요청 60건이
통째로 사라져 약 750KB / 요청 1건이 된다). 지금 구조는 그대로 두고 배포 시점에만
변환본을 만드는 방식이라 개발 방식은 바뀌지 않는다.

`react.development.js` 는 일부러 유지 중이다 — 남은 화면 9개를 만드는 동안 브라우저 콘솔의
경고 메시지가 필요하다. 위 변환 단계를 넣을 때 `production.min.js` 로 함께 바꾼다.

## 카카오맵 연동

지도는 목업이 아니라 카카오맵 JavaScript SDK 실연동이다. **앱키와 도메인 등록 두 가지**가 모두 필요하다.

1. [Kakao Developers](https://developers.kakao.com/console/app) > 앱 선택
2. **앱 설정 > 앱 > 플랫폼 키** → **JavaScript 키** 복사 → `main/config.js` 의 `KAKAO_APP_KEY` 에 붙여넣기
3. 같은 화면의 **SDK 도메인** 에 화면을 여는 주소를 등록. 로컬과 배포본 **둘 다** 넣는다
   ```
   http://localhost:8000
   https://<프로젝트>.vercel.app
   ```
   - `localhost` 와 `127.0.0.1` 은 **다른 도메인으로 취급**된다. 등록한 쪽 주소로 접속할 것
   - 포트까지 정확히 일치해야 한다. 서버를 8080 으로 띄웠다면 `http://localhost:8080` 을 등록
   - 입력값 앞뒤 **공백 주의** — "유효하지 않은 도메인" 오류의 흔한 원인
4. 저장 후 브라우저 강력 새로고침 (Ctrl+Shift+R)

> 등록 대상은 **경로가 아니라 출처(origin)** 다. 폴더 이름이 `S03/` 에서 `main/` 으로 바뀌었어도
> 다시 등록할 필요는 없다.

키가 없거나 도메인이 등록되지 않으면 `KakaoMap` 이 디자인 시스템의 목업(`MapCanvas`)으로 떨어지고
지도 자리에 사유가 표시된다 (등록해야 할 주소를 그대로 알려주므로 복사해 붙여넣으면 된다).
**레이어 구조, 시트 스냅, 필터, 목록은 앱키 없이도 그대로 검증할 수 있다.**

`libraries=clusterer` 를 함께 받는다 — 점포 마커 클러스터링(U-ST-13)에 필수다.

## 구조

```
main/
├── index.html            프레임 · CDN 스크립트 · DSLoader 부트스트랩
├── MainApp.jsx           셸 — 지도 1개 + 탭 3개 + 시트 + 상단 필터 바 (5-3 결정 전부)
├── FacilitySheet.jsx     S02 공공시설 탭 시트 내용
├── DistrictSheet.jsx     S03 상점가 탭 시트 내용
├── DiscoverSheet.jsx     S04 둘러보기 탭 시트 내용
├── config.js             앱키, 지도 레벨, 페이지 크기, 기준일자, 축제 기준일
└── data/
    ├── dunjeon.js        둔전 점포 335곳 (온누리 139) · 신규/인기 매장 · 골목 한바퀴 코스
    ├── facilities.js     공공시설 18곳 (AED 5 · 대피소 3 · 화장실 6 · 쉼터 4)
    └── districts.js      골목형 상점가 32개소 · 축제 6건
```

탭별로 지도가 갖는 마커 레이어 (U-CM-17 — 한 번에 하나):

| 탭 | 마커 | 카메라 |
| --- | --- | --- |
| 공공시설 | 시설 18곳, 유형 4종 색 | QR 지점 + 레벨 4 |
| 상점가 | 점포 335곳, 클러스터 | QR 지점 + 레벨 4 |
| 둘러보기 | 상점가 32개소 (축제 있는 곳은 호박색) | 32개 지점을 담는 경계로 `fitTo` |

화면 코드는 스타일을 직접 만들지 않는다. 컴포넌트와 토큰은 전부
`design-systems/index.js` 에서 가져온다. 필요한 것이 없으면 디자인 시스템을 고친 뒤 쓴다
(CLAUDE.md 디자인 시스템 사용 원칙, 변경 이력은 `design-systems/CHANGELOG.md`).

## 더미 데이터

### `data/dunjeon.js` — 상점가 (기능명세서 3장 검증 수치 재현)

- 총 점포 **335곳**, 온누리 가맹 **139곳**
- 업종 칩 7종 개수: 음식 132 / 카페·디저트 18 / 쇼핑 53 / 미용·생활 43 / 여가·문화 30 / 기타 59
- 거리 → 방위 → 좌표 순으로 생성하므로 목록의 "약 320m"와 지도 마커 위치가 일치한다
- 결정적 생성이라 새로고침해도 같은 목록이 나온다 (검수 가능)
- "기준 점포수 108개"는 지정 요건 산정용 수치이므로 화면에 쓰지 않는다 (기능명세서 3-5)

### `data/facilities.js` — 공공시설

같은 (거리 → 방위 → 좌표) 규칙을 쓴다. 수치는 **U-FC-08(내부 상한)과 U-FC-09(원거리 안내)가
실제로 걸리도록** 잡혀 있다 — 둘 다 평소에는 보이지 않는 규칙이라, 데이터가 전부 가까우면
구현했는지 확인할 방법이 없다.

| 유형 | 건수 | 최근접 | 걸리는 규칙 |
| --- | --- | --- | --- |
| AED | 5 | 120m | — |
| 화장실 | 6 | 210m | 1km 상한에 1건(1,240m)이 걸려 목록에서 조용히 빠진다 |
| 쉼터 | 4 | 90m | 1km 상한에 1건(1,080m)이 걸려 조용히 빠진다 |
| 대피소 | 3 | **1,400m** | 상한은 없지만 "가깝지 않다" → **U-FC-09 배너**가 뜬다 |

상한 수치(1km)는 **화면 어디에도 노출하지 않는다** (U-FC-08 "사용자 비노출").

`인근 편의시설`(U-ST-07, 상점가 탭 하단)도 이 파일에서 유형별 최근접 1건씩 뽑는다 —
두 탭이 같은 시설을 다른 거리로 말하면 안 된다.

### `data/districts.js` — 골목형 상점가 32개소 · 축제 6건

**실제 값**: 둔전(335/139) · BOCA(462/257) · 에버랜드마을(214/71) 의 점포·온누리 수 (명세서 3-3 검증치),
축제 6건의 상점가명과 날짜 (명세서 1-6).
**생성값**: 나머지 25개소의 이름과 수치, 그리고 **모든 좌표**.
상점가 이름은 용인시 실제 행정동에 "상점가"를 붙여 만든 것이며 실제 지정 명칭이 아니다.

거리는 명세서 0장의 예시("10월 24일 남사한숲 상점가, 12km")에 맞춰 남사한숲을 12km 에 두고,
나머지를 실제 지리(포곡읍 기준 처인 8~10km / 기흥 13~18km / 수지 19~24km)에 맞춰 잡았다.

> 축제 6건이 전부 2026.10~11 이라 실제 오늘(8월)로 계산하면 6건 모두 "예정"이 되어
